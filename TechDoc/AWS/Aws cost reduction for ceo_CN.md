# 写给 CEO 的 6 个 AWS 成本削减技巧

在如今汇率上涨的背景下,云账单往往成为初创公司的沉重负担。然而许多管理层却把这份账单当作"应由工程师自行削减的领域"而搁置一旁。现实恰恰相反。AWS 成本中有 30-50% 并非因技术而流失,而是因决策而流失。关闭闲置资源的决策、批准长期承诺的决策、决定把哪种工作负载放在哪里的决策——这些都完全属于经营层面的范畴。以下整理出 CEO 应当、也能够亲自把握执行的六个技巧。

## 1. 监控 EC2 规格,并随之降配

云端最常见的浪费,就是"以防万一"而配置过大的服务器。在本地机房(on-premises)时代,一旦买了服务器就无法缩小规格,而云的本质区别在于——它随时都可以缩小。

首先要看数据。用 CloudWatch 观察 CPU、内存、网络使用率 1-2 周,你会发现一个又一个实例的平均利用率只停留在 10-20%。AWS Compute Optimizer 会自动分析这些数据,免费给出"该实例降低一档规格即可"之类的建议。降低一档规格(例如 large → medium)可以立即带来约 50% 的单价节省。

在此基础上再加两个武器。第一,把使用量不稳定的工作负载迁移到可突增(t 系列)实例族,平时享受较低单价,瞬时高负载时则用积分调用性能。第二,基于 ARM 的 Graviton 实例在同等性能下单价更低,只要确认兼容性,就是最容易实现的省钱手段。**核心原则是: 不要靠猜测来定规格,先测量,再降配。**

## 2. 删除未使用的实例和资源

账单中最令人懊恼的项目,是"没人在用却每月扣钱"的资源。典型的"幽灵资源"包括:

| 幽灵资源 | 为何会持续流失费用 |
|---|---|
| 已分离的 EBS 卷 | 删除实例后卷仍会留存,每月持续计费 |
| 已停止实例上的 EBS | 即使停止(stop)实例,附加的存储仍会持续计费 |
| 未关联的弹性 IP(EIP) | 仅分配而未关联时反而会被计费 |
| 旧的快照/AMI | 随着代数累积,存储费用不断增加 |
| 无流量的负载均衡器 | 按小时计的固定费用会悄悄累积 |
| NAT 网关 | 按小时费用 + 数据处理费用组成的"隐藏杀手" |

清理这类资源不是一次性工作。需要建立标签(Tag)策略,要求所有资源标注所有者、项目和到期日,并形成每季度清理未使用资源的常态化流程。AWS Trusted Advisor 和 Cost Explorer 会自动筛选出候选项。从管理层的角度来看,要做的事情很简单: 将"不创建没有标签的资源,每季度进行清理"变成组织文化的一部分。

## 3. 通过 RI 和 Savings Plans 获得长期承诺折扣

对于始终运行的工作负载(数据库、核心系统等),按需(on-demand)价格全天候运行是最昂贵的方式。如果这台服务器永远不会关闭,那么通过承诺换取折扣才是正统做法。

有两种选择。预留实例(RI)以承诺 1 年或 3 年使用特定实例配置为代价,相比按需价格最多可享受 75% 的折扣。而 Savings Plans 不是承诺实例类型,而是承诺"每小时的使用金额",因此更加灵活。截至 2026 年,Savings Plans 的折扣幅度依产品和承诺条件不同,大致在 32%-72% 之间,其中 Compute Savings Plan 在 3 年全额预付的情况下折扣可达约 66%。

在实际操作中,通常会将两者混合使用: 对 EC2、Fargate、Lambda 等计算资源采用灵活的 Savings Plans,而对需要更深折扣的特定数据库工作负载采用 RI。实际上,RDS、ElastiCache、Redshift、OpenSearch 等通常由 RI 而非 Savings Plans 覆盖,2025 年 12 月还新推出了专门针对数据库的 Savings Plans。

不过,承诺是一把双刃剑。如果未能达到承诺的用量,差额部分会作为"浪费的承诺"被计费。因此更安全的策略是: 参考最近 60-90 天的使用数据,寻找"最低使用底线(floor)"而非平均值,只承诺该底线的约 70%-80%。规模扩大后还会有额外优惠——当单一区域内活跃 RI 的标价总额超过 50 万美元时,预付款和按小时费率都会自动获得额外 5% 的折扣。管理层需要把握的平衡点不是"全部承诺",而是"只承诺永远不会关闭的部分"。

## 4. 将静态网站与轻量服务迁移到免费账户

对于公司主页、落地页、文档站点、内部静态仪表盘这类"几乎没有服务器端逻辑"的服务,使用 AWS 的付费资源来运行是一种过度投入。竞争对手的云平台正好在这一领域提供了强大的免费账户。

| 服务 | 免费提供内容 |
|---|---|
| Cloudflare Pages | 静态站点托管、自动 HTTPS、全球 CDN、无限带宽 |
| Oracle Cloud Always Free | ARM 计算、对象/块存储、托管数据库、每月大量出网流量(egress) |
| Microsoft Azure 免费账户 | 初始信用额度 + 12 个月热门服务免费 + 一批常年免费服务 |

对于静态站点,Cloudflare Pages 的威力尤为突出。Cloudflare Pages 在所有套餐中都不对带宽设置硬性上限,针对静态资源的请求完全免费且无限制。这不是营销说辞,而是其商业模式的必然结果——这种结构是以带宽为核心成本的 Vercel、Netlify 难以追赶的。这意味着即便流量骤增,也无需担心额外扣费。

如果需要用到服务器的轻量服务,Oracle Cloud 的永久免费套餐(Always Free)则相当强大。Oracle 的 Always Free 永久免费提供 Ampere A1 4 OCPU + 24GB 内存、2 台 AMD 虚拟机、200GB 存储、Autonomous Database,以及每月 10TB 的出网流量。新注册用户还会额外获得为期 30 天、价值 300 美元的试用额度。但需要考虑的是,在热门区域,ARM Ampere A1 资源常因需求激增而出现"容量不足(Out of capacity)"错误,选择区域时需要一定的耐心。

## 5. 考虑迁移至国产(本土)云服务商

在同等规格下,确实存在国产云服务商单价低于全球三大巨头的区间。以同等规格比较,NHN Cloud 相比 AWS、Azure 便宜约 20%-22%,而在国内服务商之间,Naver Cloud 的单价据分析比 NHN Cloud 低约 5%-7%。

除单价之外,结构性优势也不小。国产云以本币计费,不存在汇率波动风险,并且依托自有的国内数据中心运营,具备基础设施稳定性和地理位置上的优势。再加上承诺折扣和合作伙伴折扣,差距会进一步拉大: 1 年期承诺相比按需价格最多可享 30%-40% 折扣,正式 MSP 合作伙伴合约还可享受额外的批量折扣,NHN Cloud 也针对初创公司和中小企业运营着最高约 5400 万韩元规模的信用额度支持计划。

不过,"单价便宜 20%-80%"这一较宽泛的数字,会因迁移对象的不同而有很大差异。单纯的服务器单价差距大致在 20% 左右,但如果把在全球云平台上臭名昭著的**数据传输(egress)费用和汇兑损失**也计算进去,节省的幅度会大得多。反过来,迁移成本、缺乏全球区域节点、部分托管服务功能上的差异,也是明确的局限性。因此,决策不应仅基于单价,而应从**总拥有成本(TCO)的角度**——涵盖网络费用、技术支持、迁移工作量、运维人力——按工作负载逐一拆解评估。"优先选择性迁移以国内流量为主的工作负载",比"全部迁移"更为现实可行。

## 6. 领取免费额度,并与客户经理建立深度联系

云服务商为了留住客户,会发放大量免费额度。不了解这一点而支付全价,是最令人惋惜的损失之一。AWS Activate、Microsoft for Startups、Google for Startups、Oracle 的创业计划都为初创公司提供数千至数万美元规模的额度。通过加速器、VC 投资组合公司或特定认证合作伙伴,额度上限还会进一步提高。

而最被低估的武器是**人**。达到一定规模的客户会被分配客户经理(AM)和技术客户经理(TAM)。与他们建立深入的联系,能打开公开报价单上看不到的谈判空间。当用量超过一定规模后,可以谈判企业级折扣计划(EDP,Enterprise Discount Program);在引入新服务时,还能获得额外额度、PoC(概念验证)费用支持,以及免费的架构咨询。管理层应记住: **削减账单最快的方法,有时不是技术,而是每个季度给客户经理打的一个电话。**

## 结语

这六个技巧在难度和效果上各不相同。第 1、2 项(规格调整、资源清理)是今天就能立刻开始的免费速效药;第 3 项(承诺购买)通过一次审批即可带来最大的削减效果。第 4、5 项(免费账户、迁移国产云)需要根据工作负载的特性进行选择性应用;第 6 项(额度、谈判)则来自于持续的关系维护。

云成本不是"技术债务"问题,而是"经营纪律"问题。只要 CEO 亲自审视每月账单中的前五大项目,并养成追问"这一项为何会是这个数字"的习惯,削减工作就已经完成了一半。

*本专栏基于截至 2026 年 5 月的公开信息及各云服务商的价格政策撰写,仅呈现通用的成本优化视角,并不能替代特定企业的合同、财务或法律决策。承诺、额度及价格条款会依服务商政策随时变动,建议在实际决策前核实最新价格表并咨询客户经理。*

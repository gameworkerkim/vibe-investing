## 1. 概要

**MAI-Cyber-1-Flash**は、マイクロソフトが2026年7月27日にサンフランシスコのイベントで公開した**同社初のサイバーセキュリティ専用AIモデル**である。Microsoft AI (MAI) 組織が社内開発し、複雑なコードベースから脆弱性を発見する作業に特化している。

中核構造は単一モデルではなく**システム**である。モデルは独立したエンドポイントとして提供されず、マイクロソフトのマルチエージェント脆弱性識別・修正ハーネスである**MDASH**（Multi-model agentic Discovery And Security Harness）内部でのみ動作する。MDASHは100以上の特殊化エージェントをオーケストレーションし、MAI-Cyber-1-Flashが最大90%の作業を処理、残りの難易度上位約10%はOpenAIのGPT-5.4にエスカレーションされる。

同時に発表された**Project Perception**は、レッドチーム（攻撃経路探索）・ブルーチーム（リスク識別および調査）・グリーンチーム（修正およびハードニング）エージェントを調整するエージェンティックセキュリティシステムで、**2026年8月3日にMicrosoft Defender内でパブリックプレビュー**に入る。

## 2. アーキテクチャおよびモデルスペック

### 2.1 モデルカード基準公式スペック

| 仕様 | 詳細 |
|------|------|
| アーキテクチャ | Self-attention + **Sparse Mixture-of-Experts (MoE)** Transformer |
| 総パラメータ | **1,370億 (137B)** |
| アクティブパラメータ | **50億 (5B)** — トークンあたりの活性化 |
| コンテキストウィンドウ | **256,000トークン** |
| 入出力モダリティ | テキスト専用 (text-in / text-out) |
| 直接ベースモデル | **MAI-Code-1-Flash**（GitHub Copilot・VS Code内蔵の軽量エージェンティックコーディングモデル） |
| 系統 | MAI-Base-1 → MAI-Thinking-1 (中間学習チェックポイント) → MAI-Code-1-Flash → MAI-Cyber-1-Flash |
| 学習データ規模 | **非公開** |
| 配布形態 | MDASH内部専用。スタンドアロンAPIなし |

### 2.2 MDASHハーネス構造

**5段階パイプライン**: Prepare → Scan → Validate → Dedupe → Prove

- **Auditorエージェント**: findingsフラグ付け
- **Debaterエージェント**: エクスプロイト可能性を議論。**エージェント間の不一致自体をシグナルとして使用**
- 合計100以上の特殊化エージェント、複数のフロンティア・蒸留モデルを混用

### 2.3 90/10ルーティングアーキテクチャ

MAI-Cyber-1-Flashの技術革新はモデル自体ではなく**難易度ベースのルーティング**である。

Suleymanの説明（2026年7月27日）: 「MDASH内でMAI-Cyber-1-Flashが最大90%のクエリを処理し脆弱性を検出・パッチし修正が実際に動作したかまで確認する。残りの10%はより大きなモデルであるGPT-5.4に渡す。」GPT-5.4はMAI-Cyber-1-Flashより**約10倍大きい**と述べた。

### 2.4 防御専用設計（重要）

モデルカードは軽量ターミナルハーネス基準の単独性能を次のように報告:

| ベンチマーク | MAI-Cyber-1-Flash |
|-------------|-------------------|
| ExploitGym — Kernel | **0** |
| ExploitGym — Userspace | **0** |
| ExploitGym — Browser | **0** |

ExploitGymは与えられた脆弱性とクラッシュ入力を実際のコード実行エクスプロイトに変換する能力を測定する。全カテゴリ0点は欠陥ではなく**意図された結果**である。Microsoftはモデルが防御作業（バグパッチなど）を実行するよう学習され、攻撃作業（マルウェア配布など）は学習していないと明示した。

**実務的含意**: エクスプロイトを生成できずに95.95%の発見パイプラインを駆動する5B-アクティブモデルは、攻撃能力流出リスクを構造的に低減したディフェンダー専用アーティファクトである。

## 4. 戦略的方向性

### 4.1 「最も大きなモデルではなく、最も賢くルーティングするシステム」

Microsoftの論旨はモデルサイズ競争からシステム設計競争への転換である。フロンティアモデルをエンタープライズリポジトリ全体に実行すればコストが爆発する。Microsoftは**モデル可用性ではなく計算コストが防御者のスキャン範囲を制約する**と主張する。

### 4.2 三つの軸: Model. Data. Harness.

| 軸 | Microsoftの主張 |
|-----|----------------|
| **Model** | 高品質データでゼロから学習したコンパクトなコード中心セキュリティモデル |
| **Data** | 最も深い優位性。アイデンティティ・エンドポイント・クラウド・ネットワーク全体で**毎日100兆以上のセキュリティシグナル**、MSRC脆弱性履歴、**160万社の顧客**の運用インサイト |
| **Harness** | 業界最高のセキュリティ専門家がチューニングした100+エージェントシステム |

## 5. TCO（総所有コスト）

### 5.1 コスト構造

| 項目 | 詳細 |
|------|------|
| 削減主張 | 従来MDASH最高構成（**GPT-5.4 + GPT-5.4 mini + GPT-5.3 Codex**）対比 **50%削減** |
| 削減メカニズム | 基本ルーティングを低コスト専用モデルに置き、超過難易度のみエスカレーション |
| Perception課金 | 従量制 pay-as-you-go、**Security Compute Unit (SCU)** 単位測定 |
| SCU単価 | **非公開**。エージェント種類別にSCU消費率が異なる |

### 5.2 TCOリスク

- 検証不可能な削減率: 50%の根拠となるトークン使用量、呼出量、レイテンシ、タスクミックス、計算配分がすべて非公開
- 比較基準が自社構成: 50%は「Microsoftの以前の構成対比」。競合他社対比の絶対的コスト優位を意味しない
- エスカレーション比率変動: 90/10は設計目標値（"up to 90%"）。実際のコードベースの難易度分布が悪ければGPT-5.4呼出比率が上昇し削減率が損なわれる

### 9.2 評価

この発表はモデル発表ではなく**システムアーキテクチャ発表**として読むのが正確である。Taesoo Kimの表現（「モデルは一つの入力であり、それを取り巻くシステムが製品である」）が発表全体の正直な要約である。

ベンチマーク数値はベンダー独自測定であるため導入判断の根拠としては弱い。判断根拠とすべきは二つ: 第一にMicrosoftが自社Windowsコードベースで実際にCVEを発見したという運営実績。第二にルーティングでスキャン単価を下げるという構造的論理。

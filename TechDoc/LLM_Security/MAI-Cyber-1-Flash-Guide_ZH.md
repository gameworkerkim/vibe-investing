## 1. 概述

**MAI-Cyber-1-Flash** 是微软于 2026 年 7 月 27 日在旧金山活动中发布的**公司首个网络安全专用 AI 模型**。由 Microsoft AI (MAI) 组织内部开发，专精于在复杂代码库中发现漏洞。

核心架构不是独立模型，而是**系统**。该模型不作为独立端点提供，仅在微软多智能体漏洞识别与修复框架 — **MDASH**（Multi-model agentic Discovery And Security Harness）内部运行。MDASH 编排 100 多个专用智能体，MAI-Cyber-1-Flash 处理最多 90% 的工作负载，剩余约 10% 最难的任务升级至 OpenAI 的 GPT-5.4。

同时发布的 **Project Perception** 是协调红队（攻击路径发现）、蓝队（风险识别与调查）、绿队（修复与加固）智能体的代理式安全系统，将于 **2026 年 8 月 3 日在 Microsoft Defender 内进入公开预览**。

Suleyman 的定位总结清晰明了："世界级性能，一半的成本。"核心价值主张不是原始性能，而是**性能性价比（路由）**。

## 2. 架构与模型规格

### 2.1 模型卡官方规格

| 规格 | 详情 |
|------|------|
| 架构 | Self-attention + **稀疏混合专家 (Sparse MoE)** Transformer |
| 总参数 | **1,370 亿 (137B)** |
| 激活参数 | **50 亿 (5B)** — 每 token 激活 |
| 上下文窗口 | **256,000 token** |
| 输入/输出模态 | 纯文本 (text-in / text-out) |
| 直接基础模型 | **MAI-Code-1-Flash**（GitHub Copilot / VS Code 内置轻量代理式编码模型） |
| 谱系 | MAI-Base-1 → MAI-Thinking-1（中间训练检查点）→ MAI-Code-1-Flash → MAI-Cyber-1-Flash |
| 训练数据规模 | **未公开** |
| 部署形式 | 仅 MDASH 内部。无独立 API |

### 2.2 MDASH 框架架构

**5 阶段管道**: Prepare → Scan → Validate → Dedupe → Prove

- **Auditor 智能体**: 标记 findings
- **Debater 智能体**: 争议可利用性。**智能体间的分歧本身被用作信号**
- 共 100+ 专用智能体，混合多个前沿与蒸馏模型

### 2.3 90/10 路由架构

MAI-Cyber-1-Flash 的技术创新不在于模型本身，而在于**基于难度的路由**。

Suleyman 说明（2026 年 7 月 27 日）："在 MDASH 内，MAI-Cyber-1-Flash 处理最多 90% 的查询 — 检测漏洞、打补丁并验证修复实际有效。剩余 10% 交给更大的模型 GPT-5.4。"他指出 GPT-5.4 比 MAI-Cyber-1-Flash **大约 10 倍**。

### 2.4 仅防御设计（重要）

模型卡报告轻量终端框架下的独立性能如下：

| 基准测试 | MAI-Cyber-1-Flash |
|---------|-------------------|
| ExploitGym — 内核 | **0** |
| ExploitGym — 用户空间 | **0** |
| ExploitGym — 浏览器 | **0** |

ExploitGym 衡量将已知漏洞和崩溃输入转化为实际代码执行利用的能力。全类别零分不是缺陷 — 而是**有意为之**。微软明确表示该模型被训练执行防御任务（漏洞修补等），未训练攻击任务（恶意软件分发等）。

**实际意义**: 一个 5B 激活模型，在不具备利用生成能力的情况下驱动 95.95% 的发现管道，是结构性降低攻击能力泄露风险的纯防御者制品。

## 4. 战略方向

### 4.1 "用 AI 防御 AI"

官方公告的核心论点：攻击者拥有越来越强大的能力，在庞大的代码库中扫描寻找单一弱点。**随着发现缺陷的成本崩溃，间歇性扫描、稍后打补丁的传统安全模型已经过时。**

### 4.2 "不是最大的模型 — 是最聪明的路由系统"

微软的论点是模型规模竞争向系统设计竞争的转变。在全部企业仓库上运行前沿模型成本高昂。微软主张**计算成本 — 而非模型可用性 — 制约防御者的扫描覆盖范围**。

### 4.3 三大支柱: 模型. 数据. 框架.

| 支柱 | 微软主张 |
|------|---------|
| **模型** | 以高质量数据从零训练的紧凑型代码中心安全模型 |
| **数据** | 最深优势。身份·端点·云·网络全维度**每日 100 万亿+ 安全信号**，MSRC 漏洞历史，**160 万客户**的运营洞察 |
| **框架** | 顶级行业安全专家调优的 100+ 智能体系统 |

## 5. TCO（总拥有成本）

### 5.1 成本结构

| 项目 | 详情 |
|------|------|
| 降本主张 | 对比此前 MDASH 最佳配置（**GPT-5.4 + GPT-5.4 mini + GPT-5.3 Codex**）**降低 50%** |
| 降本机制 | 基础路由走低成本专用模型，仅超阈值难度升级 |
| Perception 计费 | 基于消耗的按量付费，以 **安全计算单元 (SCU)** 计量 |
| SCU 单价 | **未公开**。不同智能体类型 SCU 消耗率不同 |

### 5.2 TCO 风险

- 不可验证的节省率：50% 依据的 token 使用量、调用量、延迟、任务组合、算力分配全部未公开
- 比较基准为自家配置：50% 是"对比微软此前配置"。不意味着对比竞品的绝对成本优势
- 升级比率波动：90/10 为设计目标（"up to 90%"）。若实际代码库难度分布不利，GPT-5.4 调用占比上升，节省率受损

## 7. 总结评价

该发布应准确解读为**系统架构发布**而非模型发布。Taesoo Kim 的表述（"模型是一个输入，围绕它的系统才是产品"）是整个发布最诚实的总结。

基准数字系供应商自行测量，因此作为采纳决策依据不足。可作判断依据的有二：第一，微软在自家 Windows 代码库中实际发现 CVE 的运营记录。第二，通过路由降低扫描单价的架构逻辑。两者均可在无需基准的情况下验证，并可在预览试点中针对自身环境直接确认。

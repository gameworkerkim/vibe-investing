## 1. Resend

### 优点 (Pros)

- **出色的开发者体验**: 直观的 API 与 TypeScript SDK，与 React Email 库完美集成，在基于 React 的环境中提供卓越的生产力。
- **与 Vercel 完美契合**: 由 Vercel 出身的工程师设计，针对 Next.js 等现代 JavaScript 技术栈进行了优化。
- **实用的免费套餐**: 提供每月 3,000 封 / 每天 100 封，是目前最实用的永久免费套餐。
- **现代化功能**: 2025 年新增收件邮件处理(inbound email)功能，实现了收发双向能力。
- **React Email 集成**: 与官方支持用 JSX 编写邮件模板并提供预览功能的 `react-email` 包实现了官方集成。

### 缺点 (Cons)

- **不支持 SMTP**: 仅支持 HTTP API，在迁移旧系统时存在困难。
- **速率限制较低**: 默认情况下每秒仅允许 2 次请求。多个请求同时发生时容易触及限制。
- **缺乏营销功能**: 邮件营销(新闻通讯)作为独立产品分离出去，基础 API 难以支持大批量营销邮件发送。
- **不提供专用 IP**: 即便是付费套餐也没有专用 IP 选项，发送 IP 动态变化导致信誉管理困难。
- **高级营销功能不足**: 缺乏 A/B 测试、复杂工作流自动化等功能。
- **付费单价相对较高**: Pro 套餐起价每月 $20，大批量发送时每千封 $0.90，与竞品相比价格竞争力较弱。

### 快速上手(以 Next.js 为例)

```bash
npm install resend
```

```typescript
// app/api/send/route.ts
import { Resend } from 'resend'

const resend = new Resend(process.env.RESEND_API_KEY)

export async function POST() {
  const { data, error } = await resend.emails.send({
    from: 'noreply@yourdomain.com',
    to: 'user@example.com',
    subject: '你好',
    html: '<p>这是通过 Resend 发送的邮件。</p>',
  })

  if (error) return Response.json({ error }, { status: 500 })
  return Response.json(data)
}
```

### 最终评价

Resend 针对基于 Vercel 与 Next.js 构建的最新技术栈的事务性邮件进行了优化。它将开发者体验放在首位，免费套餐的实用性也很出色。但如果你需要发送营销邮件、依赖 SMTP，或需要处理大规模流量，应考虑其他方案。

## 2. Brevo (原 Sendinblue)

### 优点 (Pros)

- **最慷慨的永久免费套餐**: 每天可发送 300 封 / 每月约 9,000 封,是现存免费套餐中权益最强的之一,且无需注册信用卡。
- **一体化(All-in-One)平台**: 可在同一平台上统一管理事务性邮件与营销邮件,还提供短信(SMS)功能。
- **有竞争力的付费价格**: 若拥有 5,000 个联系人,与 Mailchimp 相比可大幅节省月度成本。
- **功能丰富**: 提供拖拽式邮件构建器、CRM、A/B 测试、营销自动化等强大附加功能。
- **内置 AI 功能**: 通过 'Aura AI' 助手支持文本与图像生成。
- **支持 SMTP**: 除 API 外还支持 SMTP,便于与旧系统集成。

### 缺点 (Cons)

- **免费套餐带有品牌标识**: 使用免费套餐时,所有发出的邮件底部都会附带 Brevo 的 Logo 和广告文字。
- **联系人数量计费变更**: 由于取消了"无限量"政策,改为按联系人数量计费,发送量大时成本可能上升。
- **性能问题**: 页面加载偶尔缓慢,或在数据导入(import)过程中出现问题。
- **集成局限**: 在与大型 CRM 集成方面,可能略逊于竞品。
- **开发者体验**: 与 Resend 相比 API 略显传统,与 React 等现代框架的集成不够顺畅。

### 快速上手(以 Node.js 为例)

```bash
npm install @getbrevo/brevo
```

```typescript
import * as SibApiV3Sdk from '@getbrevo/brevo'

const apiInstance = new SibApiV3Sdk.TransactionalEmailsApi()
apiInstance.setApiKey(
  SibApiV3Sdk.TransactionalEmailsApiApiKeys.apiKey,
  process.env.BREVO_API_KEY!
)

await apiInstance.sendTransacEmail({
  sender: { name: 'My App', email: 'noreply@yourdomain.com' },
  to: [{ email: 'user@example.com' }],
  subject: '你好',
  htmlContent: '<p>这是通过 Brevo 发送的邮件。</p>',
})
```

### 最终评价

Brevo 非常适合预算有限,且需要同时处理营销邮件与事务性邮件的中小企业及创业公司。得益于丰富的免费套餐,可以无成本压力地开始使用,随着业务增长可自然过渡到付费套餐。

## 3. Mailgun

### 优点 (Pros)

- **稳定的基础设施**: 经过数十年验证的邮件基础设施,在大规模事务性邮件发送方面具有优势。
- **同时支持 SMTP 与 API**: 可同时选择兼容旧系统的集成方式与现代化 API 方式。
- **高级路由与邮件解析**: 提供解析收件邮件并转发至 Webhook 的强大路由功能。
- **提供专用 IP**: 付费套餐可使用专用 IP,便于发件信誉管理。
- **邮件有效性验证 API**: 单独提供邮件地址格式及域名有效性验证 API。

### 缺点 (Cons)

- **免费套餐有限**: 每天 100 封的永久免费额度相较其他服务偏少。
- **UI/UX 略显陈旧**: 控制面板较为老旧,直观性欠佳。
- **缺乏营销功能**: 作为纯粹的事务性邮件服务,不提供营销活动功能。
- **Flex 套餐结构**: 费用随使用量波动,预算预测可能较为困难。

### 最终评价

适合已经运行基于 SMTP 系统,或需要邮件解析与高级路由功能的团队。作为大规模事务性邮件发送基础设施,仍属于行业标准级别。

## 4. MailerSend

### 优点 (Pros)

- **直观的 UI**: 提供拖拽式模板构建器与简洁的控制面板。
- **永久免费套餐**: 每月可永久免费发送 500 封。
- **专注于事务性邮件**: 针对发送速度与稳定性进行了优化。
- **多样的 SDK**: 提供 JavaScript、PHP、Python、Ruby 等主要语言的 SDK。
- **邮件预览**: 编辑模板时支持深色/浅色模式及移动端预览。

### 缺点 (Cons)

- **免费套餐发送量较少**: 每月 500 封可能无法满足实际业务流量需求。
- **营销功能有限**: 相比 Brevo,一体化营销功能不足。
- **参考案例相对较少**: 与 Resend 或 SendGrid 相比,国内外的使用案例和社区规模较小。

### 最终评价

适合注重易用性的团队,尤其适用于需要非开发人员直接编辑模板的场景。

## 5. Amazon SES

### 优点 (Pros)

- **超低成本**: 每千封 $0.10 的成本,是业界最低水平之一。
- **AWS 生态集成**: 与 Lambda、SNS、S3 等 AWS 服务紧密集成。
- **无限扩展性**: 基于 AWS 基础设施,可稳定处理数亿封邮件的发送。
- **提供专用 IP**: 可通过额外付费使用专用 IP。

### 缺点 (Cons)

- **较高的准入门槛**: IAM 配置、域名验证、解除沙箱等初始设置较为复杂。
- **免费套餐有时间限制**: 12 个月免费额度(每月 3,000 封)结束后开始计费。
- **用户体验欠佳**: 控制面板偏技术化,完全没有邮件营销功能。
- **沙箱限制**: 默认以沙箱模式启动,转为生产环境需通过 AWS 审核。
- **Trustpilot 评分较低**: 关于支持质量的抱怨较多。

### 最终评价

最适合已经在使用 AWS、且需要大规模发送的团队。如果能接受初期设置的复杂性,从长期来看是最便宜的选择。

## 6. Mailtrap

### 优点 (Pros)

- **专注于开发/测试环境**: 提供邮件沙箱,可在不实际发送给真实收件人的情况下进行测试。
- **集成生产环境发送**: 可在同一平台管理沙箱测试与生产发送。
- **团队协作**: 多名团队成员可共享同一邮件测试环境。
- **永久免费套餐**: 每天可永久发送 150 封。

### 缺点 (Cons)

- **发送量受限**: 免费套餐每天 150 封的额度对实际业务而言不足。
- **主打测试用途**: 相比生产环境发送,更专注于开发阶段的测试。
- **知名度相对较低**: 与其他服务相比参考案例较少。

### 最终评价

尤其适合本地开发和 QA 环境中频繁进行邮件测试的团队。如果生产发送量较小,也可作为单一平台使用。

## 7. SendGrid

### 优点 (Pros)

- **业界最大规模的基础设施**: 被 Twilio 收购后,拥有众多大型企业客户。
- **丰富的参考资源**: 拥有最多的第三方集成和社区资料。
- **营销 + 事务性邮件一体化**: 同时提供这两项功能。
- **高级分析**: 提供发送统计、点击率、打开率等详细分析数据。

### 缺点 (Cons)

- **无永久免费套餐**: 60 天试用期(每天 100 封)结束后必须转为付费。
- **Trustpilot 评分较低(1.2/5)**: 关于客户支持质量和账户封禁的投诉非常多。
- **账户封禁问题**: 存在无明确事先警告即被封号的案例报告。
- **价格体系复杂**: 根据功能不同,价格体系较为复杂。

### 最终评价

参考资源丰富,但由于没有永久免费套餐且客户支持问题较多,不建议小型项目或创业公司使用。适合已经签订企业合同的场景。

---

## 8. Postmark

### 优点 (Pros)

- **发送速度快**: 事务性邮件的发送速度被认为处于业界最高水平。
- **到达率高**: 专注于事务性邮件,垃圾邮件处理率较低。
- **日志清晰**: 邮件活动日志详尽,便于搜索。
- **永久免费套餐**: 每月可永久免费发送 100 封。

### 缺点 (Cons)

- **免费发送量非常少**: 每月 100 封实际上仅够个人项目级别使用。
- **无营销功能**: 专注于纯事务性邮件,不提供营销活动功能。
- **付费单价相对较高**: 小规模套餐的成本效益较低。

### 最终评价

适合发送速度与到达率是业务核心指标的服务(如电商订单通知、金融交易通知等)。

## 10. 选型指南与最终结论

### 场景推荐

**个人项目 / 副业项目 / 以开发者体验为先**
→ **Resend**: 初始设置最简单,编码体验流畅。免费套餐(每月 3,000 封)足以支撑大多数个人项目。

**需要同时处理营销邮件与事务性邮件的创业公司**
→ **Brevo**: 免费套餐(每天 300 封)最为充裕,营销自动化等附加功能出色。未来业务增长后转为付费,成本负担也较小。

**需要与现有 SMTP 系统集成**
→ **Mailgun**: 支持 SMTP,便于与现有系统集成。稳定性也已经过充分验证。

**已投入 AWS 生态,或需要极致成本效益**
→ **Amazon SES**: 与其他服务相比成本显著更低是其优势。但需考虑 12 个月后开始计费以及初期设置的复杂性。

**注重本地开发与 QA 测试环境的团队**
→ **Mailtrap**: 可在沙箱环境中测试邮件而无需实际发送,大幅提升开发效率。

**以发送速度与到达率为核心指标的服务(电商、金融等)**
→ **Postmark**: 专注于事务性邮件的高速发送与高到达率是其优势。

### 针对 Vercel + Next.js 环境的综合推荐

以 Vercel 环境为基准,总体而言 **Resend** 是最优选择,因为它在与 Vercel 的契合度、与 React/Next.js 的集成以及免费套餐的实用性方面都表现优异。

但如果符合以下条件,请考虑替代方案:

- 如果营销邮件是业务核心 → **Brevo**
- 如果必须使用 SMTP → **Mailgun** 或 **Brevo**
- 如果必须极致降低成本 → **Amazon SES**
- 如果发送到达率会影响 SLA → **Postmark**

### 域名认证的通用注意事项

无论选择哪种服务,以下 DNS 记录设置都是必需的。若未设置,垃圾邮件处理比例会急剧上升。

| 记录 | 作用 | 设置位置 |
|--------|------|----------|
| **SPF** | 发件服务器认证 | DNS TXT 记录 |
| **DKIM** | 防止邮件签名被篡改 | DNS TXT 记录 |
| **DMARC** | SPF/DKIM 策略声明 | DNS TXT 记录 |
| **自定义域名** | 发件人地址品牌化 | 各服务的控制面板 |

> 只有同时设置 SPF、DKIM、DMARC 这三项,才能避免在 Gmail、Outlook 等主要邮件客户端中被归类为垃圾邮件。特别是自 2024 年起,Google 和 Yahoo 已要求大批量发件人(每天 5,000 封以上)必须配置 DMARC。

## 附录. 韩国服务环境的考虑事项

- **Naver 邮箱**: 从外部邮件服务发送时,垃圾邮件处理率较高。必须完整配置三项域名认证(SPF/DKIM/DMARC)。
- **Kakao 账户**: 向 `@kakao.com` 收件人大批量发送邮件可能需要单独申请白名单。
- **韩国 ISMS/个人信息保护法**: 有义务保存邮件接收同意记录。选择发送服务时,需同时建立单独管理接收同意日志的体系。
- **数据驻留**: 发送包含个人信息的邮件时,需确认各服务的数据处理服务器所在地(欧盟、美国等),并在隐私政策中明确说明。

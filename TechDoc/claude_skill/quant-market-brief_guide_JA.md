# quant-market-brief インストールおよび使用ガイド

> 今日の株式市況をクオンツ視点(ファクター・ボラティリティ・需給・レジーム)で要約するClaude Skill
> 概念・設計背景は[Claude_skill_guide.md](./Claude_skill_guide.md)第5章を参照

---

## 1. このスキルが行うこと

「今日の市況を要約して」の一言で、ニュースの列挙ではなく**構造化されたレジームブリーフィング**を生成します。

- **トリガー文言**: 「市況」「今日の相場」「マーケットブリーフィング」「相場要約」「今日のコスピ/ナスダックどう?」など
- **出力構成**(固定):
  1. 1行のレジーム判定 — `レジーム: Risk-On|Risk-Off|Rotation|Chop (確信度: 高|中|低) — 根拠`
  2. 数値テーブル(指数/ボラティリティ/金利/為替/需給、出典・基準時刻を明記)
  3. ファクタースコアカード(モメンタム・成長/バリュー・大型/小型・クオリティの4軸)
  4. 「昨日との違い」— デルタのみを記述
  5. 反証条件 — 判定が誤っていた場合、明日観測される指標
- **設計原則**: Web検索必須(記憶で答えない)、予測禁止(条件付きシナリオのみ)、売買指示禁止

レジーム判定の行は固定形式であるため、`portfolio-daily-review`など他のスキルがパースして再利用できます。

---

## 2. インストール方法

3つの方法のうち1つを選択してください。

### 方法A: Claude.ai(ウェブ/アプリ)— 推奨

1. 本リポジトリのスキルフォルダ全体をzip圧縮するか、配布された`.skill`ファイルを準備します。
   ```bash
   # フォルダから直接作る場合(zip = .skillと同じフォーマット)
   zip -r quant-market-brief.skill quant-market-brief/
   ```
2. Claude.ai → **Settings → Capabilities → Skills**でアップロードします。(有料プラン)
3. アップロード後、新しい会話でトリガー文言を言えば自動的に発動します。

### 方法B: Claude Code

個人スキルディレクトリにフォルダごとコピーします:

```bash
cp -r quant-market-brief/ ~/.claude/skills/quant-market-brief/
```

Claude Code再起動後、自然言語で言及するだけで使えます。

### 方法C: Claude API

[Skills API Quickstart](https://docs.claude.com/en/api/skills-guide#creating-a-skill)を参考に
`.skill`パッケージをアップロードすれば、API呼び出しでも同様に動作します。

> **検証のヒント**: インストール後「今使えるスキルを教えて」と聞くとロード状況を確認できます。

```markdown
# Quant Market Brief

## 目的

個別ニュースではなく市場構造(レジーム)を読む。「何があったか」ではなく
「ファクター・ボラティリティ・需給の観点で市場がどのレジームにあり、
昨日と何が変わったか」に答える。

原則: **観測された事実→ファクター解釈→条件付きシナリオ**。予測しない。

## ワークフロー

### ステップ1: データ収集(Web検索必須)

以下を必ずWeb検索で確認する。学習データの記憶で答えない。
すべての数値に出典と基準時刻を明記する。

- **主要指数**: KOSPI、KOSDAQ、S&P 500、NASDAQ、フィラデルフィア半導体指数(SOX)
  — 終値/変動率
- **ボラティリティ**: VIXレベルと前日比変化率、VKOSPI
- **金利/為替**: 米10年債利回り、ウォン/ドル為替、ドルインデックス(DXY)
- **需給**: KRX外国人/機関投資家の純買越、主要セクターETFの資金フロー
- **暗号資産(任意)**: BTC価格、キムチプレミアム — リスク選好度のプロキシとしてのみ使用し、
  方向信号として直接使わない

ユーザーが特定市場(韓国のみ、米国のみ)を指定した場合、その市場に集中するが、
グローバルリスク指標(VIX、金利、ドル)は常に含める。

### ステップ2: ファクターレンズの適用

`references/factor-checklist.md`を読み、以下の4軸を判定する:

1. **モメンタム vs リバーサル**: 最近の主導株は続伸するか、失速するか
2. **成長 vs バリュー**: 金利方向とスタイルローテーションの整合性
3. **大型 vs 小型**: リスク選好が小型株まで広がっているか
4. **クオリティ/ローボラ**: 防御的ファクターへの資金移動の有無

各軸は強気/中立/弱気+根拠1行で判定する。

### ステップ3: レジーム判定

以下の4つのいずれかに明示的に分類し、根拠を1行で付ける:

- **Risk-On**: リスク資産の広範な上昇、ボラティリティ下落、小型株/暗号資産の同伴強気
- **Risk-Off**: 防御資産への選好、ボラティリティ急騰、安全通貨の強含み
- **Rotation**: 指数は停滞するがセクター/スタイル間の資金移動が明確
- **Chop**: 方向性の欠如、低い出来高、ファクター信号の食い違い

判定の確信度を高/中/低で表記する。データが食い違う場合は「食い違い」と
そのまま書く。無理に1つのナラティブを作らない。

### ステップ4: 出力

`references/output-template.md`のテンプレートに従う。必須構成要素:

1. **1行のレジーム判定**(最上部、確信度含む)
2. **数値テーブル**(指数/ボラティリティ/金利/為替/需給)
3. **ファクタースコアカード**(4軸、それぞれ判定+根拠1行)
4. **「昨日との違い」**— デルタに集中する。昨日と同じ話は繰り返さない
5. **反証条件**— 今日の判定が誤っていた場合、明日観測されるもの

## ガイドライン

- 予測しない。条件付きシナリオ(「Xが維持されればYレジームが継続」)のみで記述する。
- すべての数値に出典と基準時刻を明記する。
- 投資勧誘表現(「買え/売れ/比重を増やせ」)を使わない。判断材料のみを提供する。
- ニュースの見出しはファクター解釈に必要なものだけを引用する。見出しの列挙は禁止。
- 取引時間終了前の要求であれば「取引時間中データ、終了後に変動する可能性あり」を明示する。
- 他のスキル(例: portfolio-daily-review)がこのブリーフィングのレジーム判定を再利用する
  可能性があるため、レジーム判定の行は常に同一の形式を維持する:
  `レジーム: {Risk-On|Risk-Off|Rotation|Chop} (確信度: {高|中|低}) — {根拠1行}`
```

### 4.2 references/factor-checklist.md

```markdown
# ファクター点検チェックリスト

各ファクターは**強気/中立/弱気**で判定し、根拠を1行で残す。
信号が食い違う場合は「食い違い」と表記し、どの指標同士が矛盾しているかを書く。

## 1. モメンタム vs リバーサル

- **点検指標**: 直近1か月の上位リターンセクターの当日相対収益率、主導株の出来高
- **モメンタム強気**: 主導セクター相対収益率>市場 && 出来高が維持以上
- **モメンタム崩壊信号**: 主導株の急落+出来高急増(分散売りパターン)
- **リバーサル信号**: 直近の売られ過ぎ銘柄群の広範な反発+ショート残高の減少

## 2. 成長 vs バリュー

- **点検指標**: 米10年債金利の方向、成長株指数(NASDAQ) vs バリュー株の相対パフォーマンス
- **整合性チェック**: 金利上昇+成長株強気のような「非整合」な組み合わせが現れた場合は
  必ず別途表記する — 非整合はレジーム転換の早期信号である可能性がある
- **注意**: 1日のデータでスタイルローテーションを断定しない。3〜5取引日の
  累積方向も併記する

## 3. 大型 vs 小型

- **点検指標**: KOSPI vs KOSDAQの相対パフォーマンス、Russell 2000 vs S&P 500
- **リスク選好の拡散**: 小型株指数が大型株をアウトパフォーム+出来高増加
- **リスク選好の縮小**: 大型株への偏重が深刻化(指数上昇が少数銘柄に集中)
  — 上昇相場であってもbreadth(広がり)の悪化は弱気信号として別途表記する

## 4. クオリティ/ローボラ(防御ファクター)

- **点検指標**: 生活必需品/ユーティリティ/ヘルスケアの相対パフォーマンス、配当株ETFの資金流入
- **防御シフト信号**: 指数が横ばい〜上昇なのに防御セクターがアウトパフォームする場合、
  スマートマネーの先制的な防御ポジション取りの可能性を表記する

## ボラティリティレジーム(すべてのファクター判定の背景)

| VIXレベル | レジーム | 意味 |
|---|---|---|
| < 15 | 低ボラティリティ | キャリー/モメンタム戦略が有利、ただし急反転に脆弱 |
| 15〜25 | 中立 | ファクター信号をそのまま解釈 |
| > 25 | 高ボラティリティ | ローボラ/クオリティが優位、ポジション縮小の検討区間 |

**注意**: VIXの「レベル」よりも「変化率」の方が短期信号として有効である。
前日比+20%以上のジャンプは、レベルとは無関係に別途警告として表記する。

## 需給解釈の原則

- 外国人純買越は円/ドル・ウォン/ドルの方向と共に読む(為替ヘッジフローの区別)
- 機関純買越はプログラム/非プログラムを可能な限り区別する
- 1日の需給でトレンドを語らない。5取引日の累積と共に表記する
```

## 5. 使用例

```
> 今日の相場どうだった?

[quant-market-brief発動]
1. Web検索: KOSPI/NASDAQ/VIX/10Y/為替/KRX需給
2. factor-checklist.mdで4軸判定
3. レジーム分類+確信度
4. output-template.md形式でブリーフィング出力
```

特定市場のみ希望する場合: 「米国市場だけ市況を整理して」— グローバルリスク指標(VIX・金利・ドル)は常に含まれます。

## 6. カスタマイズポイント

| 項目 | 位置 | 方法 |
|---|---|---|
| 追跡指数の追加/削除 | SKILL.md ステップ1 | 指数リストを修正(例: 日経、ハンセンを追加) |
| VIXレジーム閾値 | factor-checklist.md | 15/25の境界値を調整 |
| ファクター軸の追加 | factor-checklist.md + SKILL.md ステップ2 | 例: 配当・サイズファクターを追加 |
| 出力言語/形式 | output-template.md | テンプレートを直接修正 |

## 7. 注意事項

- 本スキルの出力は**判断材料であり投資助言ではありません。**
- データはWeb検索時点基準であり、取引時間中の照会時は終了後に変動する可能性があります。
- 本スキルはデモ/教育目的であり、実際の使用前に自身の環境で十分にテストしてください。

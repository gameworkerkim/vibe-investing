# Team Big Five Harness——非开发者入门指南

> 即使你不懂一行代码，也能跟着这份指南操作。
> 原始项目：https://github.com/tobyilee/team-bigfive

---

## 0. 一句话总结

**一套让多个 AI 像"一个团队"那样分工协作的配置组合，用同样的 AI 也能产出更好的结果。**

团队科学(Team Science)的一个发现是：即便是普通人组成的团队，只要团队合作良好，结果就会更好——这一发现被直接移植到了 AI 智能体上。核心不是使用更聪明的 AI，而是**让多个 AI 之间更好地协作**。

---

## 1. 需要先了解的 3 个概念

先从非开发者最容易困惑的部分说起。

### (1) 这是一套"配置组合"，不是"程序"

它不是一个双击就能运行的应用，而是**叠加在名为 Claude Code 的工具之上使用的一组规则和角色文件**。可以把它比作交给厨师(AI)的"菜谱+厨房分工表"。

### (2) 必须要有"Claude Code"才能运行

Claude Code 是 Anthropic 开发的工具，可以在终端(黑色命令窗口)中让 Claude 执行任务。Team Big Five Harness 是一个附加配置，把 Claude Code 的运行方式切换为"团队模式"。

### (3) "Harness"这个词的含义

Harness 原意是"套在马身上的挽具(缰绳、鞍具等)"。在这里，它的含义是**约束 AI 不随意行动，而是遵循既定的协作流程的框架**。

---

## 2. 为什么要用它——能带来什么好处

如果一次性把一个大任务交给单个 AI，通常会出现以下问题：

- 前面确定的内容，到后面就被遗忘了。
- 两个本应互相契合的产出(例如应用的界面和后端逻辑)彼此对不上。
- 由于是单独作业，自己无法发现自己的失误。

Team Big Five Harness 用**人类团队的工作方式**来解决这些问题。

| 在人类团队中 | 在这个 harness 中 |
|---|---|
| 团队负责人确定目标并分配任务 | `team-lead`(团队负责人 AI) |
| 团队成员各自完成分配的工作 | `contributor`(多个执行者 AI) |
| 有人交叉检查同事的工作成果 | `performance-monitor`(检查 AI) |
| 在白板上写下共同的目标 | `SMM.md`(共享笔记文件) |
| 接到指示后复述一次:"好的，是要……对吗?" | 消息确认与复述环节 |

核心效果：**任务越是需要多个产出相互契合的复杂工作，效果就越显著。**

---

## 3. 什么时候用、什么时候不用

这是最重要的判断标准。并不是用了就一定好。

### 适合使用的情况(相互契合的任务)

- "把这个 API 设计好并同时完成前端联调"
- "收集这个主题的多份资料，综合并交叉验证成一份"
- "把奇幻小说的世界观设定和情节梳理得前后一致，一起构建"

### 更适合不用的情况(简单或彼此独立的任务)

- 像"这个单词用英语怎么说?"这样的简单问题
- 一次性就能完成的短任务
- 多个彼此互不影响的独立任务(这种情况分别单独指派反而更快)

> **类比：** 卷一根紫菜包饭如果找 5 个人同时上手，反而会更慢。当多个环节像一套多道菜的大餐那样需要相互配合时，团队才能真正发挥价值。

## 4. 安装(Getting Started)

这是非开发者最容易卡住的环节，因此会逐步详细说明。
顺序：**① 准备 Claude Code → ② 获取 harness 文件 → ③ 放入工作文件夹 → ④ 验证运行**

### 步骤 ① 准备 Claude Code

Team Big Five Harness 运行在 Claude Code 之上。如果你还没有安装，需要先安装 Claude Code。
- Claude Code 是在终端中使用的工具，需要 Anthropic 账户(Claude 订阅)。
- 最准确的安装方法是遵循 Anthropic 官方文档(搜索"安装 Claude Code")。
- 安装完成后，在工作文件夹中输入 `claude` 即可启动 Claude Code。

> 如果你是第一次使用终端：Mac 上叫"终端(Terminal)"，Windows 上是"PowerShell"或"命令提示符"，都是那个黑色窗口。

### 步骤 ② 获取 harness 文件

从 GitHub 页面(https://github.com/tobyilee/team-bigfive)获取文件。以下两种方法任选其一。

**方法 A——通过按钮下载(最简单，推荐)**
1. 进入上面的 GitHub 地址。
2. 点击绿色的 **`Code`** 按钮。
3. 点击 **`Download ZIP`**。
4. 解压下载的压缩包。

**方法 B——通过命令下载**
将下面这行原样粘贴到终端中：
```
git clone https://github.com/tobyilee/team-bigfive.git
```

### 步骤 ③ 放入你的工作文件夹

这是最关键的一步。相当于 harness"大脑"的是 **`.claude`** 文件夹和 **`CLAUDE.md`** 文件。

1. 在下载的文件中找到 **`.claude`** 文件夹和 **`CLAUDE.md`** 文件。
   - (以 `.` 开头的文件夹默认是隐藏的，可能看不到。请在文件管理器中开启"显示隐藏文件"。)
2. 将这两者原样复制到 **你实际要工作的项目文件夹** 中。

复制后你的工作文件夹结构如下：
```
my-project-folder/
├── .claude/          ← harness 的角色·流程定义(已复制)
├── CLAUDE.md         ← harness 的说明文件(已复制)
└── (你的工作文件……)
```

### 步骤 ④ 验证运行

1. 在该文件夹中打开终端，输入 `claude` 启动 Claude Code。
2. 尝试输入下面第 5 节"使用示例"中的触发短语。
3. 如果 AI 不是独自作答，而是表现出"组建团队/分配角色"这样的行为，就说明运行正常。

> **要点重申：** 安装 = 把 `.claude` 文件夹和 `CLAUDE.md` 文件放进你的工作文件夹。仅此而已。

## 5. 使用方法——"触发短语"就是一切

安装完成后，不需要复杂的命令。
**像平常一样正常提出请求，只需加入下面这一个"魔法词"**，团队模式就会启动。

### 触发词(只要包含其中一个即可)

- "以团队方式"
- "智能体团队"
- "团队 big five"
- "高绩效团队"
- "用多个智能体"
- "以协作方式处理"

### 造句公式

> **[想要完成的事]** + **[触发词]** + **帮我处理**

就是这样。

> 提示：由于 Claude 理解的是自然语言，你可以用自己实际使用的语言来表达——以上只是这个概念的中文示例。

## 6. 4 个实际使用示例

非开发者也可以直接照着输入的示例。

### 示例 1——制作网站(开发任务)

```
帮我做一个公司介绍页面和联系表单，让两者顺利衔接，以团队方式处理
```

一个 AI 负责界面，另一个 AI 负责表单逻辑，检查 AI 负责确认"两者是否契合得当"。

### 示例 2——资料调研与报告(非开发任务)

```
用多份资料调研 2025 年电动车市场趋势，并综合成一份报告，用智能体团队来整理
```

多个执行者 AI 分工调研 → 检查 AI 找出资料之间的矛盾 → 负责人 AI 汇总成一份报告。

### 示例 3——写作与策划(创作任务)

```
把奇幻小说的世界观设定和第 1~3 集的剧情梳理成前后一致、没有矛盾的版本，用团队 big five 来完成
```

负责世界观和负责剧情的角色一起查看"共享笔记(SMM)"，避免出现冲突。

### 示例 4——分析+验证(业务任务)

```
分析这份 Excel 销售数据，并对分析结果进行交叉验证，用高绩效团队来处理
```

分析和验证由不同角色分别负责，能够发现单人作业时容易忽略的错误。

## 7. 运行过程中会发生什么(安心说明)

为了让你在屏幕上看到陌生术语时不至于慌张，这里提前说明整体流程。

1. **准备** —— 负责人 AI 把目标和"完成标准"写入共享笔记文件(SMM.md)。
2. **组建团队** —— 创建多个执行者 AI 加 1 个检查 AI。
3. **协作执行** —— 执行者们参考共享笔记进行工作，在互相交接成果时会确认"这样理解对吗?"。
4. **检查** —— 检查 AI 交叉核对各项产出是否彼此契合。
5. **汇总** —— 负责人 AI 将所有结果合并成最终版本。

产出结果通常会整理在名为 `_workspace/final/` 的文件夹中。

## 8. 常见问题(FAQ)

**问：在普通的 Claude 应用(网页版/移动端)中也能用吗?**
不能。这个 harness **仅适用于 Claude Code(终端工具)**。在网页版或移动端 Claude 应用中不会生效。

**问：看不到 `.claude` 文件夹。**
以 `.` 开头的文件夹默认是隐藏的。请在文件管理器设置中开启"显示隐藏项目"。(Mac Finder 中：`Cmd + Shift + .`)

**问：加了触发词，但 AI 还是像平常一样正常回答。**
请检查三点：① `.claude` 和 `CLAUDE.md` 是否确实在**当前的工作文件夹**内，② 是否在该文件夹中启动了 Claude Code，③ 触发词的拼写是否正确。

**问：每次都用团队模式不是更好吗?**
不是。在简单任务上使用团队模式反而会更慢、更低效。请只在"产出需要相互契合的复杂任务"中使用它(参见第 3 节)。

**问：如果不满意结果怎么办?**
直接用自然语言继续提出修改请求即可。这个 harness 的设计就是在每次任务后根据反馈不断改进的。

## 理论背景(想深入了解可参考)

这个 harness 的理论基础来自团队科学的经典论文 **Salas, Sims & Burke (2005), "Is there a 'Big Five' in Teamwork?"**。其核心观点是：优秀的团队表现来自五种行为(团队领导力、相互绩效监督、后备行为、适应性、团队导向)，而这五种行为又建立在三大基石之上(共享心智模型、闭环沟通、相互信任)。详细解读可参见原始仓库中的 `docs/TEAM-SCIENCE.md`。

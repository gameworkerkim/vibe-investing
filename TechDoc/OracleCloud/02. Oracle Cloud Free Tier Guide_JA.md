# Oracle Cloud 無料ティア(OCI Free Tier)利用ガイド

*2026年5月基準・韓国ユーザー視点・Always Free中心*

---

## 1. なぜOCI Free Tierなのか

業界の無料ティアの中で資源規模が最も大きく、期間制限がない。同カテゴリーのAWS・GCP無料ティアと比較すると差は明確である。

| 項目 | OCI Always Free | AWS Free Tier(12ヶ月) | GCP Always Free |
|---|---|---|---|
| コアVM | ARM Ampere A1 4 OCPU / 24 GB RAM | t2.micro / t3.micro 1 vCPU / 1 GB RAM | e2-micro 1 vCPU / 1 GB RAM |
| インスタンス分割 | 最大4台に分割可能 | 1台 | 1台 |
| 追加x86インスタンス | E2.1.Micro 2台(1 OCPU / 1 GB) | — | — |
| ブロックストレージ | 200 GB | 30 GB EBS | 30 GB |
| アウトバウンドトラフィック | 10 TB/月 | 100 GB/月 | 1 GB/月 |
| 期間 | 無制限(Always Free) | 12ヶ月 | 無制限 |

核心はARM 4コア24GBという物理的資源自体よりも、**これが永久に無料で使える**という点である。個人VPN、セルフホスティングAIエージェント、K3sクラスター、軽量LLM推論サーバーまで、実際のワークロードを回せる事実上唯一の無料クラウドである。

---

## 2. 無料ティアの二つのトラック

登録すると二種類の無料資源を同時に受け取る。この二つを混同すると課金が発生する。

| 区分 | Always Free | Free Trial |
|---|---|---|
| 期間 | 無制限 | 登録後30日 |
| 限度 | 決まった資源リスト(下記§3参照) | $300 USDクレジット |
| 期限後 | そのまま使用可能 | 未使用クレジット消滅、Always Free資源のみ残る |
| リスク | ほぼなし | 30日以内にpaid資源を作るとクレジット消耗後自動課金の可能性 |

**原則**: 課金を望まないなら30日間はコンソールで「Always Free Eligible」ラベルが付いた資源のみ作成する。30日経過するとpaid資源は作成自体がブロックされる(Always Freeアカウント維持時)。

---

## 3. Always Free資源詳細

全体の限度は以下の通りである。すべて登録したホームリージョン(Home Region)でのみ提供される。

### 3.1 コンピュート

| Shape | 数量 | 仕様 | 備考 |
|---|---|---|---|
| VM.Standard.A1.Flex(ARM Ampere) | 最大4台 | 合計4 OCPU / 24 GB RAM | 月3,000 OCPU時間+18,000 GB時間。4 OCPU×24h×31日=2,976時間なのでフル稼働でも限度内に収まる |
| VM.Standard.E2.1.Micro(AMD x86) | 2台 | 各1 OCPU / 1 GB RAM | ARM非互換ソフトウェア用 |

ARMとx86を混ぜて最大6台まで同時運用可能。ただし、ブートボリューム合計が200 GBを超えられない。

### 3.2 ストレージ

| 種類 | 限度 |
|---|---|
| Block Volume(ブート+追加) | 200 GB合計、最大5個 |
| Block Volume Backup | 5個(オブジェクトストレージに保存、別途限度) |
| Object Storage | 標準10 GB+Infrequent Access 10 GB+Archive 10 GB、月50,000 APIリクエスト(S3互換) |

### 3.3 データベース

| 種類 | 限度 |
|---|---|
| Autonomous Database(ATP/ADW/JSON) | 2個、各1 OCPU / 20 GB |
| NoSQL Database | Phoenixリージョン限定 |

### 3.4 ネットワークおよびその他

- Flexible Load Balancer: 1個(10 Mbps)
- Network Load Balancer: 1個
- VCN、Site-to-Site VPN: 無制限
- アウトバウンドトラフィック: 10 TB/月
- Vault、Bastions、Monitoring、Logging: 基本使用量無料
- Email Delivery: 1日200件

## 4. 登録手続き(韓国ユーザー)

### 4.1 事前準備物

| 項目 | 推奨 |
|---|---|
| カード | 新規発行のVISA/Master **クレジットカードまたはデビットカード** |
| 使用不可 | PIN直払、**プリペイドカード、バーチャルカード、使い捨てカード**(Oracle明示的拒否) |
| メール | OCI Free Tierまたは旧Free Trialに使用したことのないアドレス |
| 携帯電話 | OCIに使用したことのない番号(SMS認証必要) |
| 英文アドレス | 正確な道路名英文表記(マスキング・任意変更時拒絶) |

OCIはメール+電話番号+カード番号の組み合わせで重複登録を識別する。カードは一定回数の重複使用を許容するが、可能なら新しいカードを使う方が安全である。
最も重要なのはカード会社に登録した住所地を確認することである。正確に入力しないと次の段階に進めない。

### 4.2 手順

1. https://www.oracle.com/kr/cloud/free/ にアクセス → 「無料で始める」
2. メール認証 → パスワード設定
3. **アカウント情報**: 名前はカード名義と一致、住所は英文正字表記
4. **Home Regionの選択**: 一度選択すると変更不可。韓国ユーザーは通常次のうちから選択
   - **Seoul(ap-seoul-1)**: 遅延最も低い、ただしARM容量不足が頻発
   - **Chuncheon(ap-chuncheon-1)**: 韓国内2番目のリージョン、相対的に余裕
   - **Tokyo / Osaka**: 遅延30〜50ms、ARM容量確保が容易
   - 可用性優先ならChuncheonまたはOsaka、遅延優先ならSeoul
5. **携帯電話認証**: 010-1234-5678 → `1012345678`(先頭0を除いて入力)
6. **カード登録**: $1承認保留発生後即座にキャンセル。実際の課金なし
7. 約款同意 → 「Complete Sign-up」

### 4.3 登録失敗時

「トランザクション処理中エラー」メッセージが最もよくある。原因は大抵次のいずれかである。

- カード拒絶(韓国発行の一部カードの拒絶事例多数)
- IP/位置不一致(VPNが有効なら無効化)
- メール・電話・カードすべて同一で反復試行時ブロック
- 住所表記がカード登録住所と不一致

**解決順序**:
1. 別のカードで即座に再試行(同じ情報での反復禁止)
2. だめなら[Oracle Cloud Customer Service](https://www.oracle.com/cloud/contact.html)チャットまたは問い合わせフォームでケース登録
3. それでもだめなら新しいメール+新しい電話番号+新しいカードの組み合わせで再登録
4. Facebook「オラクルクラウドユーザーグループ(Oracle Cloud KR User Group)」に韓国オラクル社員が活動中。拒絶ケースの助けを得られる場合がある

## 5. ARMインスタンス作成: 「Out of host capacity」の迂回

OCI無料ティアの最大の実戦的な落とし穴。韓国・東京リージョンはARM A1の新規割り当てがほぼ常にいっぱいである。

### 5.1 推奨設定

| 項目 | 推奨 |
|---|---|
| Image | Canonical Ubuntu 24.04 Minimal **aarch64** |
| Shape | VM.Standard.A1.Flex |
| OCPU/RAM | **2 OCPU / 12 GB**(4 OCPUより確保しやすい) |
| Boot Volume | 47〜50 GB(デフォルト値) |
| SSH Key | ローカル`~/.ssh/id_ed25519.pub`またはコンソールでキーペア生成後private keyを即座にダウンロード |
| Public IP | 「Assign a public IPv4 address」をチェック |

### 5.2 容量確保戦略(効果順)

1. **OCPUを4→2に減らす**: 一度に4 OCPUをリクエストするとほぼ失敗する。2 OCPUインスタンス2個に分割すると総資源は同一でありながら成功率が大きく上がる。
2. **深夜試行(韓国時間02:00〜06:00)**: 他ユーザーの活動が少ない時間帯に資源回収が発生する。
3. **Availability Domainの変更**: AD-1、AD-2、AD-3をそれぞれ試す。同じリージョン内でもADごとに容量が異なる。
4. **自動再試行スクリプト**: GitHubの`hitrov/oci-arm-host-capacity`のようなOSSがOCI APIをポーリングして空きを発見すると即座にインスタンスを作成する。本人のOCI APIキー登録が必要。
5. **PAYGへの転換**: カード決済情報で従量制アカウントに転換するとARM容量の優先順位が上がるという報告多数。Always Free限度内では依然として0円だが、**paid資源を誤って作ると課金が発生する** — 使わないpaidサービスはコンソールの通知設定を必ず行う。

### 5.3 それでもだめな場合

- VM.Standard.E2.1.Micro(AMD)で先にインスタンスを作成する。即座に作成される。ARMは後でゆっくり確保する。
- ホームリージョンを変更するには新しいアカウントを作るしかない。既に登録したアカウントのホームリージョン変更は不可。

## 6. セキュリティ・運用の基本設定

### 6.1 ネットワーク

OCIは基本的に**すべてのインバウンドをブロック**する。AWS Security Groupとは異なり二段階で解除する必要がある。

1. **VCNのSecurity List**: コンソール → ネットワーキング → Virtual Cloud Networks → 該当VCN → Security Lists → Default Security List → Ingress Rulesで80/443/必要なポートを追加
2. **インスタンスOSのiptables**: Ubuntuイメージにはiptablesが有効化されており追加ブロックしている。以下のコマンドで確認・開放

```bash
sudo iptables -L INPUT -n --line-numbers
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
```

この二段階を両方通過しないと外部からの接続ができない。

### 6.2 SSH接続

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@<public-ip>
# Oracle Linuxイメージはubuntuの代わりにopc
```

### 6.3 Idle Reclamationの回避

Always Freeインスタンスは以下の条件で回収される:
- 7日間CPU 95パーセンタイル**20%未満** *かつ*
- 7日間ネットワーク使用95パーセンタイル**20%未満** *かつ*
- 7日間メモリ使用95パーセンタイル**20%未満**

すべて同時に満たす必要があるため、一般的なセルフホスティングワークロード(ブログ、VPN、ボット)は安全である。本当にidleな学習用VMであれば以下のcronで意図的に負荷を発生させる:

```bash
# /etc/cron.d/keepalive — 毎時1分間CPU占有
0 * * * * root timeout 60 yes > /dev/null
```

### 6.4 課金通知の必須設定

コンソール → Billing → Budgetsで$1限度の予算を作成。閾値50%、80%、100%でメール通知。PAYG転換時特に重要。

## 7. 韓国ユーザーがよく陥る落とし穴

| 落とし穴 | 結果 | 回避 |
|---|---|---|
| 登録時VPN有効 | 位置不一致→拒絶 | VPNを無効化して登録、登録後再度有効化 |
| プリペイドカード/バーチャルカード使用 | 拒絶 | VISA/Masterクレジット・デビットを使用 |
| 同一情報で反復試行 | 永久ブロックの可能性 | 1〜2回試行後別の情報で |
| 4 OCPU一度にリクエスト | Out of capacity無限反復 | 2 OCPU×2台に分割 |
| Security Listだけ開放してiptablesを開放しない | 外部接続不可 | 両方とも設定 |
| Dockerコンテナに外部マイナーを含む | アカウント即座・永久ブロック | 信頼できるイメージのみ使用、公式ハブでも検証 |
| 30日トライアル期間にpaid資源を作成 | $300クレジット消耗後自動課金 | 「Always Free Eligible」ラベルのみ使用 |
| ホームリージョンの選択ミス | 変更不可、新しいアカウントが必要 | Chuncheon/Osaka推奨 |

## 8. 推奨活用事例

ARM 4 OCPU / 24 GBで実際運用可能なワークロード:

| 用途 | 構成 | 備考 |
|---|---|---|
| 個人VPN | WireGuard単独 | 1 OCPUで十分、10 TBトラフィック |
| ブログ/ホームページ | Nginx + WordPress + MariaDB | 1 OCPU / 6 GB |
| K3sクラスター | 1 control plane + 3 worker(各1 OCPU / 6 GB) | 学習用Kubernetes実習 |
| Self-hosted AI | Ollama + 7B/8B量子化モデル | 8〜20 tokens/s、4 OCPUフル使用 |
| 自動化ワークフロー | n8n + Postgres(Docker Compose) | ARM互換イメージの確認必須 |
| ゲームサーバー | Minecraft Java + GeyserMC | 2 OCPU / 12 GB推奨 |
| 個人DNS/広告ブロック | AdGuard Home / Pi-hole | ほぼ資源を使わない |

ARM互換性: 大部分のOSSはマルチアーキイメージを提供する。ただし**一部のクローズド型または古いDockerイメージがamd64のみ提供**する場合があり、`docker pull`時にplatformオプションの確認が必要。最終的にはE2.1.Micro x86インスタンスで動かす。

## 9. PAYG(Pay-As-You-Go)転換の検討

転換の利点:
- ARM A1容量確保が容易になる
- AI/ML、高性能ネットワークなどpaidサービスへのアクセス
- 顧客サポート正式ケース登録可能
- Always Free資源はそのまま無料維持

転換のリスク:
- 「Always Free Eligible」ラベルがない資源を誤って作ると即座に課金
- ブートボリュームが200 GBを超えると超過分課金
- トラフィックが10 TBを超えると超過分課金

**PAYG転換の決定基準**: ARMインスタンスを必ず韓国/東京リージョンに置く必要があり、自動化スクリプトでも確保できない場合のみ。それ以外はAlways Free維持を推奨。

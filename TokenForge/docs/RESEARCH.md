# TokenForge 시장 리서치 — 아이디어 검증

> 검증 질문: **"DeepSeek/무료 LLM으로 한국어·외국어 코딩 프롬프트를 영어로 바꾸고 토큰 절약을 예측하는 웹 변환기 + 프로젝트 이해(WIKI/RAG) 기반 프롬프트 개선"** — 유사 프로젝트가 있는가?

## 1. 결론 요약

| 차원 | 판정 | 근거 |
|------|------|------|
| 기술 실현성 | ✅ 높음 | 토크나이저/LLM API/정적 호스팅 모두 성숙. Cloudflare free tier로 무료 운영 가능 |
| 시장 수요 | ✅ 큼 | 프롬프트의 과잉 토큰이 비용·품질 문제로 널리 인식됨. 한글→영어 "토큰 절약 번역" 개념이 독립 프로젝트로 등장 중 |
| 경쟁 | 🟡 중간(움직임 빠름) | "토큰 최적화" 도구는 다수. **"번역 + 최적화 + 토큰 절약 예측 + 프로젝트 WIKI/RAG" 통합**은 아직 없음 → 차별화 여지 |

### Chrome 확장 등 (사용자 제공 표 참조)
Terse(15–40% 절감)·LitePruner(~60%)·PromptPilot(~63%)·POTR(Groq/Llama)·Prompt Master(중→영 번역) 등은
**"토큰 최적화" 또는 "번역" 한 축만** 담당하며, 대부분 유료/BYOK. 한/영 통합 + 절감 예측 + 스킬화는 미흡.

## 3. 차별화 포인트

1. **번역+최적화 결합 워크플로(UI 6단계)** — 대부분 단일 기능
2. **DeepSeek free tier 활용** → 무료 운영 + BYOK(mock 폴백)
3. **토큰 절약 예상도(Claude/ChatGPT, 비용 포함)** — 절감을 *수치로* 검증
4. **"전체 계획 프롬프트 → 기억 → 세부 프롬프트 → 스킬화"** 파이프라인
5. **Phase 2 WIKI+RAG** — 프로젝트 전반을 이해하고 프롬프트를 개선/추천 (현 시장 미점유)

## 4. 리스크

- 경쟁 확장(최적화 도구들이 번역 추가 가능성)
- 한→영 번역 품질이 절감 효과를 좌우 → 최적화 LLM(DeepSeek) 품질에 의존
- 토큰 절감 vs 의미 보존 트레이드오프 → "의미 보존" 프롬프트 설계로 대응
- Phase 2(WIKI/RAG)는 콘텐츠 구축·유지비용 필요 → 오픈소스 커뮤니티 WIKI 전략

## 5. 판정

실행 가치가 높은 아이디어. **Phase 1(번역+최적화+토큰 예측)은 빠르게 MVP(현재 구현)로 검증**하고,
**Phase 2(WIKI+RAG)를 장기 차별점**으로 삼는 것이 타당.

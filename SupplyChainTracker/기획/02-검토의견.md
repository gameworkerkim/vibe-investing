## 1. 총평

사업 구조와 컴플라이언스 인식 수준이 평균 이상으로 높은 계획서다. 특히 다음 세 가지가 잘 설계되어 있다.

1. **Contingent Fee 제한, Set-Aside, TAA 등 규제 리스크를 사전에 인지** — 대부분의 유사 계획서가 놓치는 부분
2. **Human-in-the-loop 원칙** — AI 자동 판단으로 입찰/계약을 실행하지 않고 담당자 승인을 요구
3. **데이터 서비스가 아닌 '공급망 실행'에 차별점을 둔 점** — GovTribe, HigherGov, Deltek GovWin 등 기존 경쟁사와 정면 경쟁하지 않는 방향

다만 실행 단계에서 다음 검토 의견을 반영해야 한다.

## 2. 핵심 검토 의견

### 2.1 SAM.gov API 현실 점검

| 항목 | 계획서 내용 | 실제 |
|---|---|---|
| API 키 | 언급 없음 | api.data.gov에서 키 신청 필수. 무료 티어 일 10콜, 키 등록 시 일 1,000콜 |
| 계약금액 필터 | 100K~5M USD 필터 | **대부분의 공고에 Estimated Value가 미공개(또는 0)**. API 필드로 필터링 불가 |
| NAICS/PSC | 자동 분류 | 발주기관이 잘못 기재하는 사례 빈번. 낙찰 데이터로 교차검증 필요 |
| 낙찰 데이터 | procurement_awards 테이블만 | 별도 소스(FPDS/USAspending)에서 과거 낙찰가·낙찰업체를 수집해야 금액 추정 가능 |

**권고:**
- 계약 규모 추정은 "API의 estimated value → 미공개 시 과거 낙찰 데이터(FPDS) → 미보유 시 미확정"의 3단계로 설계
- `placeOfPerformance` 필드로 한국(주한미군 기지) 필터 우선 적용
- 공고 수집 시 응답일(deadline)을 기준으로 일 2회 이상 증분 수집 (Sources Sought/Pre-Solicitation은 응답일이 짧은 경우가 많음)

### 2.2 데이터 소스 확장 (SAM.gov 단독 의존 지양)

| 소스 | 용도 | 우선순위 |
|---|---|---|
| SAM.gov Opportunities API | 공고 수집 | P0 |
| FPDS / USAspending API | 과거 낙찰·계약금액 데이터 | P0 (금액 추정의 핵심) |
| DLA DIBBS | 국방부 물자/부품 조달 — 한국 제조사 강점 분야 | P1 |
| GSA eBuy / Advantage | 조달 스케줄 기반 구매 | P2 |
| 411th CSB (주한미군 계약) | Phase 1 핵심 채널 — 일부 공고는 현지 공지로만 배포 | P0 (Phase 1) |

특히 **주한미군 조달은 SOFA상 로컬 조달 규정으로 한국 업체가 참여 가능한 구조**가 이미 존재하므로, SAM.gov 공개 공고 외에 411th Contracting Support Brigade의 현지 공고 채널을 별도로 확보하는 것이 Phase 1 성패를 좌우한다.

### 2.3 CUI / 보안 컴플라이언스는 '플랫폼 자체'에도 적용된다

계획서는 CUI를 '계약별 검토 항목'으로 다루지만, **시스템이 DoD 계약의 CUI 문서를 저장·처리하는 순간 플랫폼 자체가 CMMC 요건을 요구받는다.**

**권고:**
- 초기 버전은 공개 정보(Public)만 처리하는 설계로 시작
- CUI 취급이 필요한 경우 별도 격리 환경(AWS GovCloud 등) + 비용 산정
- 초기 시스템에 CUI 문서가 업로드되지 않도록 업로드 단계에서 차단 규칙 적용

### 2.4 LLM 활용 설계

- AI의 역할을 **추출(Extraction) + 인용(Citation)**에 한정하는 현재 방향은 옳다.
- Compliance Engine의 판정은 FAR/DFARS 원문 검색(RAG)으로 근거 조항을 첨부하도록 설계. 단순 프롬프트 판단 금지
- 모델 비용보다 **첨부 문서 파싱(PDF/Word/OCR) 비용과 품질이 실제 병목**. PyMuPDF만으로는 스캔 문서 대응 불가 → OCR 파이프라인을 Phase 1부터 포함
- AI 비용 예산(3개월 $500~1,500)은 문서 파싱 포함 시 과소. 월 $500~1,000 수준으로 재산정 권장

### 2.5 기술 스택 간소화

- **n8n + Celery + Redis**: 초기에는 불필요. FastAPI + APScheduler + PostgreSQL + pgvector로 충분. 배치 규모가 커지면 Celery 도입
- Redis는 알림 큐가 병목이 될 때 도입
- OpenAI API는 구조화 출력(JSON Schema)으로 고정하고, 모델 교체 가능한 추상화 계층 권장

### 2.6 일정 및 예산

- **90일 내 첫 입찰 제출은 낙관적.** 실제 크리티컬 패스는 시스템이 아니라 **미국 파트너 5개 확보**(Model B). 파트너 실사·계약에만 60~90일 소요 예상
- 현실적 마일스톤: 0~30일 데이터 수집 + 30~90일 공급사/파트너 확보 + 90~180일 첫 입찰 준비
- 법률 자문 $5,000~10,000은 초기 FAR/계약구조 검토에 부족할 수 있음. 계약 템플릿(공급계약, NDA, Teaming Agreement) 확보는 별도 항목으로 분리 권장

### 2.7 누락된 운영 항목

1. **계약 템플릿**: NDA, Teaming Agreement, Supplier Agreement, US Partner Agreement
2. **원산지 증명 프로세스**: TAA/BAA 대응용 Certificate of Origin 발급 절차와 책임 주체
3. **번역 품질 절차**: RFP 응답 문서의 한국어→영어 번역은 기술 사양 오류 리스크가 크므로 전문가 검수 단계 필수
4. **환율/운전자금 시뮬레이션**: 입찰 전 Cash Flow 시뮬레이션을 Deal Room 필수 단계로 규정
5. **감사 추적(Audit Log) 대상 정의**: 누가 언제 어떤 판단을 승인했는지 — 구체 테이블 설계 필요

## 3. 결론

계획의 방향성(데이터 → 공급망 → 실행의 3자산)과 규제 인식은 타당하다. 실행 전 다음 4가지를 확정할 것을 권장한다.

1. 금액 추정을 위한 FPDS 낙찰 데이터 연동 (P0로 승격)
2. 주한미군 조달 채널(411th CSB) 전담 확보 방안
3. CUI 미취급 설계 + 파트너 계약 템플릿 확보
4. 일정을 180일 기준으로 재조정하되, 30일 단위 검증 게이트 유지

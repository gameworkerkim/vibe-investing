- Version: 1.0
- Date: 2026년 11월 22일
- 배포: 최종 `supplychain.vibequant.cc` (서브도메인) / 우선 `vibequant.cc/SupplyChainTracker` (경로)

## 0. 확정 사항

| 항목 | 결정 |
|---|---|
| 공문 원본·첨부 | **Cloudflare R2 보관** (DB에는 메타데이터·분석 텍스트·임베딩만) |
| 런타임 | Cloudflare Workers (Node.js + TypeScript) + Hono |
| DB | Cloudflare D1 (SQLite) — 검색·벡터 기능 활성화 시 Neon(PostgreSQL+pgvector) 무료 티어로 전환 |
| 인증 | 이메일+비밀번호 (PBKDF2) — 가입 후 관리자 승인, 최초 로그인 시 비밀번호 강제 변경 |
| 프론트 | Next.js (Cloudflare Pages, vinext) + Recharts |
| 최종 배포 | `supplychain.vibequant.cc` 서브도메인 |
| 당장 배포 | `vibequant.cc/SupplyChainTracker` 경로 (정적 랜딩) |

## 1. 코드 배치 (모노레포)

```
SupplyChainTracker/
├── readme.md
├── 기획/  법률/  개발계획/     # 문서
├── worker/                    # Hono Workers — 수집 크론, API, 매칭·스코어링
├── web/                       # Next.js(vinext) 대시보드
├── db/                        # D1 DDL 마이그레이션
```

기존 규칙 준수: 각 프로젝트는 자기 폴더에서 실행 (`worker/`는 `npx wrangler dev`, `web/`은 `npm run dev`).

## 2. 개발 순서 (마일스톤)

### M0. 환경 구성

- `worker/`·`web/` 스캐폴드 (wrangler, vinext)
- D1 데이터베이스 생성 (`wrangler d1 create sct-db`), `db/` DDL 초안 (procurement_notices, audit_logs 등)
- R2 버킷 생성: `sct-documents`
- 인증 기반: users/sessions/audit_logs 마이그레이션 + 관리자 시드 (최초 로그인 시 비밀번호 강제 변경)

### M1. 정적 랜딩 — 지금 목표: vibequant.cc/SupplyChainTracker

- `SupplyChainTracker/pages/` 에 랜딩 작성: 프로젝트 소개, 3단계 목표, 진행 체크 사항, 문서 링크
- 배포: `VibeQuant/pages/SupplyChainTracker/` 로 복사 후
  `cd VibeQuant/pages && npx wrangler pages deploy . --project-name=vibequant-web`
- `_routes.json` 수정 불필요 — include 목록(`/`, `/api/*` 등)에 없으므로 정적 서빙됨. `functions/_middleware.js` 수정도 불필요
- **검증**: `https://vibequant.cc/SupplyChainTracker/` 200 + 문서 링크 동작

### M2. 수집기 (Stage 1 탐색)

- SAM.gov API 키 발급 (api.data.gov)
- Cron Trigger (KST 08:00 / 20:00, 일 2회):
  SAM.gov 신규 공고 → 원본 JSON·첨부를 **R2 저장** → 메타데이터 D1 upsert
- FPDS/USAspending 낙찰 데이터 수집 → 3단계 금액 추정
- **Gate 1**: 7일 연속 무중단 수집, 공고 1,000건 이상 적재

### M3. AI 분석 파이프라인 (Stage 1)

- OpenAI 구조화 추출 (JSON Schema 고정) + 근거 문장·페이지 보관
- 문서 파싱: unpdf (Workers), 스캔 문서는 OCR 외부 파서
- Compliance 1차 필터(GREEN/YELLOW/RED) + Opportunity Scoring
- **Gate**: 표본 50건 수동 대조, 추출 오류율 10% 미만

### M4. 대시보드 MVP (Stage 2 진입)

- `web/` Next.js(vinext) — 이메일 로그인 → 기회 목록·상세·원문 뷰어
- 별도 Pages 프로젝트로 배포 (preview URL) 후 최종 서브도메인 연결
- **검증**: 로그인 후 조회·필터 동작

### M5. 매칭·원가·마진 (Stage 2)

- 공급사 CRUD (A/B/C 등급), 견적 요청·유효기간 관리
- Cost & Margin Calculator (추정값/실견적 구분)
- 알림: Telegram/Email (High Margin, Deadline Warning 등)

### M6. 승인 워크플로 (Stage 3 계약·서류)

- Deal Room, RFP 요구사항 ↔ 제출 문서 매핑
- 입찰 제출 승인 워크플로 + Audit Log (자동 제출 금지)
- **Gate 3**: 요구사항 커버리지 100% + 승인 이력 기록

### M7. 서브도메인 전환

- `supplychain.vibequant.cc` 커스텀 도메인을 대시보드 Pages 프로젝트에 연결
- Workers API는 대시보드와 동일 도메인 경로(`/api/*`) 또는 `api.supplychain.vibequant.cc` 선택
- `vibequant.cc/SupplyChainTracker`는 랜딩·안내 페이지로 유지 (대시보드 링크 추가)

## 3. R2 버킷 규칙 (`sct-documents`)

```
sct-documents/notices/{notice_id}/original.json      # API 응답 원본
sct-documents/notices/{notice_id}/attachments/{파일} # 첨부 PDF 등
sct-documents/awards/{award_id}/original.json        # FPDS 낙찰 원본
sct-documents/ai/{notice_id}/{run_id}.json           # AI 분석 결과 (버전 보존)
```

- 공개 데이터만 저장. CUI로 판단되는 문서는 업로드 차단 (`법률/01-조달규정-컴플라이언스.md` §6)

## 4. D1 무료 티어 대응 및 Neon 전환 트리거

- DB(D1)에는 메타데이터·분석 결과만 저장 (원문은 R2)
- D1 무료 티어(저장 5GB, 일 행 읽기/쓰기 한도) 모니터링
- `supplier_quotes`·`cost_estimates`는 이력 포함 저장 (견적 유효기간)

**Neon 전환 트리거 (다음 중 하나 충족 시):**

1. 벡터 검색(유사 공고·매칭 임베딩) 도입
2. 고급 SQL(윈도우 함수·복합 조인) 분석 요구
3. D1 용량·행 한도 도달

전환 시: Neon 무료 티어(스토리지 0.5GB) + pgvector, 임베딩 차원 축소 검토(예: 1536→384)

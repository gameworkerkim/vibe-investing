# 3단계 기술 로드맵

- 목표: 탐색 → 매칭 → 계약·서류 인증의 3단계로 자동화 시스템 구축
- 원칙: 각 단계는 다음 단계 진입 전 검증 게이트(Gate)를 통과해야 한다

---

## Stage 1. 탐색 (Discovery)

**목표: 검증 가능한 공고 데이터베이스 + 기회 선별 리포트**

| # | 작업 | 비고 |
|---|---|---|
| 1 | api.data.gov에서 SAM.gov Opportunities API 키 발급 | 무료 키 일 10콜 → 등록 후 일 1,000콜 |
| 2 | SAM.gov 수집기 구축 (증분 수집, placeOfPerformance 필터) | FastAPI + APScheduler |
| 3 | FPDS/USAspending 낙찰 데이터 연동 | 계약금액 3단계 추정의 근거 |
| 4 | 3단계 금액 추정 로직: API 값 → 과거 낙찰값 → 미확정 | 임의 추정 금지 |
| 5 | 문서 파싱 파이프라인 (PDF/Word + OCR) | PyMuPDF + OCR |
| 6 | AI 공고 분석 (구조화 추출 + 원문 인용) | JSON Schema 고정 출력 |
| 7 | Compliance 1차 필터 (GREEN/YELLOW/RED) | FAR/DFARS 근거 조항 인용 |
| 8 | Opportunity Scoring (100점 체계) | |
| 9 | 일일 리포트 (오전 9시 KST, Telegram/Email) | |

**Gate 1 통과 조건:**
- 일 7일 연속 무중단 수집
- 공고 1,000건 이상 DB 적재, 분석 완료율 80% 이상
- 무작위 표본 50건에 대해 AI 추출 결과와 원문 수동 대조, 오류율 10% 미만
- 한국 내 수행 장소(주한미군 기지) 공고가 필터에 정확히 걸리는지 확인

## Stage 2. 매칭 (Matching)

**목표: 20% 이상 마진의 Bid Pipeline 구축**

| # | 작업 | 비고 |
|---|---|---|
| 1 | 한국 공급사 DB + A/B/C 등급 체계 | 초기 30개 목표 |
| 2 | Supplier Matching Engine (product/delivery/compliance/price fit) | 검증 자료 기반 점수만 계산 |
| 3 | 견적 요청·유효기간 관리 (supplier_quotes) | 이력 저장 |
| 4 | Cost & Margin Calculator | 추정값과 실견적 구분 표시 |
| 5 | 미국 파트너 DB + Teaming 후보 추천 | NAICS·과거 낙찰 이력 교차 |
| 6 | 매칭 알림 (Supplier Match / Quote Required) | |

**Gate 2 통과 조건:**
- 공급사 30개, 미국 파트너 5개 DB 등록
- 실제 견적 20건 확보 (Stage 1 기회 기준)
- 20% 이상 마진 후보 20건 파이프라인 등록
- Compliance Advisor가 YELLOW 이상 10건 직접 검토

## Stage 3. 계약·서류 (Contract & Document Certification)

**목표: 제출 가능한 입찰 패키지와 계약 이행 기록**

| # | 작업 | 비고 |
|---|---|---|
| 1 | Deal Room (공고-공급사-파트너-견적-원가-마진-규제 통합 뷰) | |
| 2 | RFP 요구사항 체크리스트 ↔ 제출 문서 매핑 | 누락 항목 자동 감지 |
| 3 | 서류 인증 추적: SAM/UEI/NCAGE 등록 상태, 인증서 유효기간, 원산지 증명 | 만료 사전 알림 |
| 4 | 입찰 제출 승인 워크플로 (담당자 승인 + Audit Log) | 자동 제출 금지 |
| 5 | 번역 품질 검수 단계 (기술 사양 한→영) | |
| 6 | 계약 후 납품·검수·인보이스 추적 | |
| 7 | Cash Flow 시뮬레이션 (입찰 전 필수) | 지급 조건·시차 반영 |

**Gate 3 통과 조건:**
- 첫 입찰 1건 제출 (Model B 중심)
- 제출 패키지의 요구사항 커버리지 100% 확인
- 모든 승인 이력 Audit Log 기록

---

## 기술 스택 메모 (검토 반영)

- 초기: FastAPI + APScheduler + PostgreSQL + pgvector + Next.js + Auth.js
- Redis/Celery/n8n은 배치 규모 증가 후 도입
- AI 출력은 JSON Schema 고정, 모델 교체 가능한 추상화 계층
- Compliance 판정은 FAR/DFARS 원문 RAG로 근거 조항 첨부
- OCR 파이프라인은 Stage 1부터 포함 (스캔 문서 대응)

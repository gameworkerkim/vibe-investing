CEOのためのAWSコスト削減テクニック6選

발행 2026.05.15 · 주제 AWS · クラウドコスト · FinOps · コスト最適化 · 수정 2026.07.25

🇰🇷 한국어 English 日本語 中文

エンジニアリングだけでなく経営判断が必要な、実践的なAWSコスト削減の6手法——ライトサイジング、放置リソースの整理、コミットメント割引、無料ティアの活用、国産クラウドへの移行、クレジット交渉について。

為替が高くなった今、クラウドの請求書はスタートアップにとって負担になることが多い。しかし多くの経営者はこの請求書を「エンジニアが勝手に減らしてくれる領域」として先送りする。現実は正反対だ。AWSコストの30〜50%は技術ではなく意思決定から漏れ出ている。使っていないリソースを止める判断、長期コミットメントを承認する判断、どのワークロードをどこに置くかを決める判断——すべて経営の領域である。CEOが自ら手掛けるべき、そして手掛けられる6つのテクニックをまとめる。

1. EC2のサイズをモニタリングし、小さいものに変更する

クラウドで最もよくある無駄は「念のため」大きく確保したサーバーである。オンプレミス時代は一度買ったサーバーを縮小できなかったが、クラウドはいつでも縮小できる点が本質的な違いだ。

まずデータを見るべきだ。CloudWatchでCPU・メモリ・ネットワーク使用率を1〜2週間観察すると、平均使用率が10〜20%台にとどまるインスタンスが次々と見つかる。AWS Compute Optimizerはこのデータを自動分析し、「このインスタンスは1段階小さい仕様で十分」という推奨を無料で提示する。1段階(例:large→medium)のダウンサイズは、そのまま約50%の単価削減につながる。

これに2つの武器を加える。第一に、使用量が一定しないワークロードはバーステイブル系(tシリーズ)に移すことで、通常時は低い単価を維持し、瞬間的な負荷にはクレジットで性能を引き出せる。第二に、ARMベースのGravitonインスタンスは同等性能に対して単価が低く、互換性が確認できれば最も手軽な削減カードとなる。核心は「推測でサイジングせず、測定してから縮小する」という原則だ。

2. 使っていないインスタンス・リソースを削除する

請求書で最も悔しい項目は「誰も使っていないのに毎月お金が出ていく」リソースだ。代表的なゴーストリソースは次の通り。

ゴーストリソース なぜ漏れるのか
分離されたEBSボリューム インスタンスを削除してもボリュームは残り毎月課金される
停止インスタンスのEBS インスタンスをstopしても接続されたストレージは課金され続ける
未接続のElastic IP(EIP) 割り当てただけで接続していないと逆に課金対象になる
古いスナップショット・AMI 世代が積み重なりストレージコストが累積する
トラフィックのないロードバランサー 時間単位の固定料金が静かに積み重なる
NATゲートウェイ 時間単位料金+データ処理料金という「隠れた伏兵」

こうしたリソースは一度の掃除で終わらない。タグ(Tag)ポリシーを定めて全リソースに所有者・プロジェクト・失効日を明記させ、四半期ごとに未使用リソースを整理するルーティンを作るべきだ。AWS Trusted AdvisorとCost Explorerが候補を自動的に絞り込んでくれる。経営側がやるべきことは単純だ。「タグのないリソースは作らない、四半期ごとに整理する」というルールを組織文化にすること。

3. RIとSavings Plansで長期コミットメント割引を得る

常時稼働するワークロード(データベース、基幹システムなど)をオンデマンド料金で24時間動かすのは最も高くつく方式だ。止めないサーバーであれば、コミットメントで縛って割引を受けるのが定石だ。

選択肢は2つある。Reserved Instances(RI)は特定のインスタンス構成を1年または3年コミットする対価として、オンデマンド比最大75%までの割引を提供する。一方Savings Plansはインスタンス種類ではなく「時間当たりの使用金額」をコミットする方式のため、より柔軟だ。2026年時点でSavings Plansの割引幅は商品とコミット条件によって約32〜72%の範囲であり、Compute Savings Planは3年全額前払いで約66%に達する。

実務では両者を組み合わせる。EC2・Fargate・Lambdaのようなコンピュートには柔軟なSavings Plansを適用し、より深い割引が必要な特定のデータベースワークロードにはRIを使う組み合わせが一般的だ。実際にRDS・ElastiCache・Redshift・OpenSearchなどはSavings PlansではなくRIでカバーされ、2025年12月にはデータベース専用のSavings Plansも新たに登場した。

ただしコミットメントは両刃の剣だ。コミット量を満たせない場合、その差額が「無駄になったコミットメント」として課金される。そのため直近60〜90日の使用データから平均ではなく「最低使用の底(floor)」を見つけ、その底の約70〜80%程度のみをコミットするのが安全な戦略だ。規模が大きくなると追加のメリットもある。単一リージョンでアクティブなRIの定価合計が50万ドルを超えると、前払い・時間単位料金の両方に5%の追加割引が自動適用される。経営陣は「全部コミット」ではなく「止めない分だけコミット」というバランスを取るべきだ。

4. 静的サイト・軽量サービスは無料アカウントへ移行する

会社のホームページ、ランディングページ、ドキュメントサイト、社内用静的ダッシュボードのような「サーバーロジックがほとんどない」サービスをAWSの有料リソースで動かすのは過剰投資だ。競合クラウドはこの領域に強力な無料アカウントを提供している。

サービス 無料提供内容
Cloudflare Pages 静的サイトホスティング、自動HTTPS、グローバルCDN、帯域幅無制限
Oracle Cloud Always Free ARMコンピュート、オブジェクト・ブロックストレージ、マネージドDB、月間大量egress
Microsoft Azure無料アカウント 初期クレジット+12か月無料の人気サービス+常時無料サービス群

静的サイトにはCloudflare Pagesが特に威力を発揮する。Cloudflare Pagesはすべての料金プランで帯域幅にハードキャップを設けておらず、静的アセットへのリクエストは無料・無制限だ。これはマーケティング文句ではなくビジネスモデルの結果であり、帯域幅がコストの中核であるVercel・Netlifyが追随しにくい構造だ。トラフィックが急増しても追加課金の心配がないということだ。

サーバーが必要な軽量サービスであればOracle Cloudの常時無料ティアが強力だ。OracleのAlways FreeはAmpere A1 4 OCPU + 24GB RAM、AMD VM 2台、200GBストレージ、Autonomous Database、月10TB egressを永久無料で提供する。新規登録時には30日・300ドル相当のトライアルクレジットも別途付与される。ただし人気リージョンではARM Ampere A1リソースが需要急増で「容量不足(Out of capacity)」エラーになる場合があり、リージョン選択には多少の忍耐が必要な点は考慮すべきだ。

5. 国産クラウドへの移行を検討する

同等スペックを基準に見ると、国産クラウドの単価がグローバル3社より低い区間が明確に存在する。同等スペック比較でNHN CloudはAWS・Azureに対して約20〜22%安く、国内事業者間ではNaver CloudがNHN Cloudより約5〜7%低い単価を示すと分析されている。

単価以外の構造的な利点も大きい。国産クラウドはウォンで課金されるため為替変動リスクがなく、国内自社データセンター運営による インフラ安定性と地理的な利点がある。これにコミット割引とパートナー割引を加えると差はさらに広がる。1年コミット時にオンデマンド比最大30〜40%の割引、正式MSPパートナー契約時には別途ボリューム割引が適用され、NHN Cloudはスタートアップ・中小企業向けに最大約5,400万ウォン規模のクレジット支援プログラムも運営している。

ただし「単価20〜80%安い」という広い数値は何を移行するかによって大きく変わる。単純なサーバー単価の差は20%前後だが、グローバルクラウドで悪名高いデータ転送(egress)コストと為替差損まで含めると削減幅はさらに大きくなる。逆に、移行コスト、グローバルリージョンの不在、一部マネージドサービスの機能差は明確な限界だ。したがって意思決定は単価ではなくTCO(総所有コスト)の観点から——ネットワークコスト、技術サポート、移行工数、運用人件費をすべて含めて——ワークロードごとに分けて下すべきだ。「全部移行」ではなく「国内トラフィック中心のワークロードから選別移行」が現実的だ。

6. 無料クレジットを活用し、アカウント担当者と深く対話する

クラウド事業者は顧客を引き留めるため、莫大な無料クレジットを提供している。これを知らずに定価を支払うのは最も惜しい損失だ。AWS Activate、Microsoft for Startups、Google for Startups、Oracleのスタートアッププログラムは、スタートアップに数千〜数万ドル規模のクレジットを提供する。アクセラレーター・VCポートフォリオ企業または特定の認定パートナーを通じると、上限はさらに大きくなる。

そして最も過小評価されている武器は人だ。一定規模以上の顧客にはアカウントマネージャー(AM)と技術担当者(TAM)が割り当てられる。彼らと深く対話することで、公開価格表にはない交渉カードが開かれる。使用量が一定規模を超えれば全社レベルのコミット割引契約(EDP、Enterprise Discount Program)を交渉でき、新規サービス導入時には追加クレジット、PoC(概念実証)費用支援、アーキテクチャの無料コンサルティングも受けられる。請求書を減らす最も速い道は、時に技術ではなく四半期ごとに担当者へかける一本の電話であることを経営陣は忘れてはならない。

まとめ

6つのテクニックは難易度と効果が異なる。1・2番(サイジング・整理)は今日すぐに始められる無料の即効薬であり、3番(コミットメント)は一度の決裁で最大の削減を生む。4・5番(無料アカウント・国産移行)はワークロードの性質を見極めて選別適用すべきであり、6番(クレジット・交渉)は継続的な関係管理から生まれる。

クラウドコストは「技術的負債」ではなく「経営規律」の問題だ。CEOが毎月請求書の上位5項目だけでも自ら目を通し、「これはなぜこうなっているのか」と問う習慣をつけるだけで、削減の半分はすでに始まっている。

本コラムは2026年5月時点の公開情報および各クラウド事業者の料金政策に基づいて作成されており、一般的なコスト最適化の観点を提示するものであって、特定企業の契約・財務・法的意思決定に代わるものではない。コミットメント・クレジット・料金条件は事業者の政策により随時変動するため、実際の意思決定前に最新の料金表と担当者への確認を推奨する。

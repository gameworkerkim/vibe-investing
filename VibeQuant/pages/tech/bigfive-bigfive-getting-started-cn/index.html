Team Big Five Harness——非开发者入门指南

주제 Claude Code · AI 代理 · 多代理 · 入门指南

🇰🇷 한국어 English 日本語 中文

一份即使不懂任何一行代码也能跟着操作的说明书

这是一份即使不懂任何一行代码也能跟着操作的说明书。 原始来源: https://github.com/tobyilee/team-bigfive

0. 一句话总结

一套让多个 AI 像"一个团队"一样分工协作的配置组合,即便使用同样的 AI,也能产出更好的结果。即使聚集的是一群普通人,只要团队协作良好,结果就会变好——这是团队科学(Team Science)的发现,而这套方案正是将这一发现直接移植到了 AI 代理上。核心不在于使用更聪明的 AI,而在于让多个 AI 之间更好地协作。

1. 首先要了解的 3 个概念

先从非开发者最容易混淆的部分讲起。

(1) 这不是"程序",而是"配置组合"

它不是一个双击就能运行的应用,而是叠加在名为 Claude Code 的工具之上使用的一组规则与角色文件。可以类比为交给厨师(AI)的"菜谱 + 厨房分工表"。

(2) 必须依赖"Claude Code"才能运行

Claude Code 是 Anthropic 开发的工具,可以在终端(黑色命令窗口)中向 Claude 分配任务。Big Five Harness 是一套附加配置,能将 Claude Code 的运行方式切换为"团队模式"。

(3) "Harness(挽具)"一词的含义

Harness 原本指"套在马身上的挽具(缰绳、马鞍等的组合)"。在这里的含义是约束 AI 不要随意行动,而是遵循既定的协作流程的框架。

2. 为什么要用它——能带来什么改善

如果一次性让单个 AI 处理一项大任务,会出现以下问题:

  • 前面确定的内容,到后面会被遗忘。
  • 两个本应互相配合的成果(例如应用的界面和后端)对不上。
  • 因为是单独作业,自己犯的错误自己发现不了。

Big Five Harness 用人类团队的工作方式来解决这些问题。

在人类团队中 在这套 Harness 中
团队负责人确定目标并分配任务 team-lead(团队负责人 AI)
团队成员各自完成分配的任务 contributor(执行者 AI,多个)
一个人交叉检查同事的工作 performance-monitor(审核 AI)
在白板上写下共同目标 SMM.md(共享备忘文件)
收到指示后复述确认:"好的,您是说要这样做对吗?" 消息确认与复述流程

核心效果: 任务越复杂、成果之间需要相互契合的程度越高,效果就越显著。

3. 何时使用,何时不用

这是最重要的判断标准。并不是无条件使用就好。

适合使用的情况(相互配合的工作)

  • "把这个 API 设计好并同步完成界面对接"
  • "针对这个主题收集多份资料,综合并交叉验证成一份"
  • "把小说的世界观设定和剧情大纲一起编写,不要出现前后矛盾"

不建议使用的情况(简单或彼此独立的工作)

  • 类似"这个单词用英语怎么说?"这样的简单提问
  • 一次就能完成的简短任务
  • 多个互不影响的独立任务(这种情况分别单独下达指令反而更快)

类比: 卷一根紫菜包饭如果找 5 个人一起动手,反而会更慢。而在多个环节相互衔接的套餐料理中,团队协作才能发挥优势。

4. 安装(Getting Started)

对非开发者来说这是最容易卡壳的部分,因此逐步拆解说明。 顺序: ① 准备 Claude Code → ② 获取 Harness 文件 → ③ 放入自己的工作文件夹 → ④ 确认运行

步骤① 准备 Claude Code

Big Five Harness 运行在 Claude Code 之上。如果还没有安装,需要先安装 Claude Code。

  • Claude Code 是在终端中使用的工具,需要 Anthropic 账户(Claude 订阅)。
  • 安装方法以 Anthropic 官方文档为准最为准确。(可搜索"安装 Claude Code")
  • 安装完成后,在要工作的文件夹中输入 claude,即可启动 Claude Code。

如果是第一次使用终端: Mac 上是"终端(Terminal)",Windows 上是"PowerShell"或"命令提示符",指的就是那个黑色窗口。

步骤② 获取 Harness 文件

从 GitHub 页面(https://github.com/tobyilee/team-bigfive)获取文件。以下两种方法任选其一即可。

方法 A —— 通过按钮获取(最简单,推荐)

  1. 进入上述 GitHub 地址。
  2. 点击绿色的 Code 按钮。
  3. 点击 Download ZIP。
  4. 解压下载的压缩文件。

方法 B —— 通过命令获取 在终端中直接粘贴以下内容。

git clone https://github.com/tobyilee/team-bigfive.git

步骤③ 放入自己的工作文件夹

这是关键所在。相当于 Harness"大脑"的是 .claude文件夹和CLAUDE.md 文件。

  1. 在下载的文件中找到名为 .claude的文件夹和CLAUDE.md 文件。
    • (以 . 开头的文件夹默认会被隐藏,可能看不到。请在文件管理器中开启"显示隐藏文件"。)
  2. 将这两项原样复制到你实际要工作的项目文件夹中。

复制后自己工作文件夹的样子:

我的-项目-文件夹/
├── .claude/          ← Harness 的角色与流程定义(已复制进来)
├── CLAUDE.md         ← Harness 说明文件(已复制进来)
└── (我的工作文件…)

步骤④ 确认运行

  1. 在该文件夹中打开终端,输入 claude 启动 Claude Code。
  2. 尝试输入下面第 4 章"使用示例"中的触发语句。
  3. 如果 AI 不是自己一个人回答,而是表现出"组建团队/分配角色"的方式运作,就说明运行正常。

重点回顾: 安装 = 把 .claude 文件夹和 CLAUDE.md 放入自己的工作文件夹。仅此而已。

5. 使用方法——"触发语句"就是全部

安装完成后,不需要任何复杂的命令。 像平时一样用中文提出请求,只需加入下面某一个"魔法词",团队模式就会启动。

触发词(只要包含其中一个即可)

  • "以团队方式"
  • "代理团队"
  • "team big five 团队"
  • "高绩效团队"
  • "用多个代理"
  • "协作处理"

组句公式

[想做的事]+[触发词]+请帮我完成

就是这样,结束了。

6. 4 个实际使用示例

非开发者也可以直接照搬输入的示例。

示例 1 —— 制作网站(开发任务)

制作公司介绍页面和联系表单，并让两者良好衔接，以团队方式帮我完成

一个 AI 负责界面,另一个 AI 负责表单逻辑,审核 AI 负责检查"两者是否良好契合"。

示例 2 —— 资料调研与报告(非开发任务)

通过多份资料调研 2025 年电动车市场趋势，并综合整理成一份，用代理团队帮我完成

多个执行者 AI 分工调研 → 审核 AI 找出资料之间的矛盾 → 团队负责人 AI 整合成一份报告。

示例 3 —— 写作与策划(创作任务)

用 team big five 团队帮我编写奇幻小说的世界观设定和第 1-3 章的剧情大纲，不要有前后矛盾

世界观负责人和剧情负责人共同查看"共享备忘录(SMM)"以避免冲突。

示例 4 —— 分析 + 验证(实务任务)

分析这份 Excel 销售数据，并用高绩效团队处理，包括对分析结果进行交叉验证

分析角色与验证角色相互分离,能够捕捉到单人作业时容易遗漏的错误。

7. 运行过程中发生了什么(帮你安心)

为了不让屏幕上滚动的陌生文字让你感到慌乱,提前告知整体流程。

  1. 准备 —— 团队负责人 AI 将目标和"完成标准"写入共享备忘文件(SMM.md)。
  2. 组建团队 —— 创建多个执行者 AI 和 1 个审核 AI。
  3. 协作执行 —— 执行者们参照共享备忘录进行工作,在相互交接结果时会确认"这样理解对吗?"。
  4. 审核 —— 审核 AI 交叉检查各项成果是否良好契合。
  5. 汇总 —— 团队负责人 AI 将所有结果合并为最终版本。

结果通常会整理到名为 _workspace/final/ 的文件夹中。

8. 常见问题(FAQ)

问: 在普通的 Claude 应用(网页版/移动端)中也能用吗?不能。这套 Harness专为 Claude Code(终端工具)设计,在网页版/移动端 Claude 应用中无法运行。

问: 看不到 .claude 文件夹。以 . 开头的文件夹默认是隐藏的。请在文件管理器设置中开启"显示隐藏项目"。(Mac Finder 中: Cmd + Shift + .)问: 输入了触发词,但 AI 还是正常回答了。请检查以下三点: ① .claude 和 CLAUDE.md 是否位于当前工作文件夹内,② 是否是在该文件夹中启动了 Claude Code,③ 触发词的拼写是否准确。

问: 每次都用团队模式不是更好吗?并非如此。对简单任务使用团队模式反而会更慢、更低效。请仅在"成果需要相互契合的复杂任务"中使用。(参见第 3 章)问: 如果不满意结果怎么办? 直接用中文继续提出修改要求即可。这套 Harness 在设计上会在每次任务后根据反馈持续改进。

理论背景(想进一步了解的话)

这套 Harness 基于团队科学的经典论文 Salas, Sims & Burke (2005), "Is there a 'Big Five' in Teamwork?"。其核心观点是: 优秀的团队表现来自 5 种行为(团队领导力、相互绩效监控、后备支援、适应性、团队导向),并由 3 个基础要素(共享心智模型、闭环沟通、相互信任)支撑。详细解读见原始仓库中的 docs/TEAM-SCIENCE.md。

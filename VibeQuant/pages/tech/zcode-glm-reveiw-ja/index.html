Zcodeで体験するGLM-5.2

발행 2026.07.25 · 주제 GLM-5.2 · Zcode · Zhipu AI · Z.ai · オープンウェイト コーディングモデル · DeepSeek V4-Pro

🇰🇷 한국어 English 日本語 中文

中国Zhipu AIのフラッグシップオープンウェイトコーディングモデルGLM-5.2をZcode経由で実際に使ってみる。セットアップ、API・コーディングツール連携、実践ワークフロー、長所短所、DeepSeek V4-Pro・Claude Opus 4.8との3社比較。

中国のAI企業Zhipu AI(智譜AI)が最近公開したフラッグシップモデルGLM-5.2が、米国の開発者コミュニティで注目を集めている。オープンウェイト(open-weight)方式で提供されながらも、コーディング性能で閉鎖型モデルに匹敵する結果を出しているためである。この記事ではZcodeを中心にGLM-5.2を直接体験する方法と、モデルの長所短所を見ていく。

GLM-5.2とは?

GLM-5.2はZ.ai(Zhipu AI)の最新フラッグシップモデルであり、長期間(long-horizon)のソフトウェアエンジニアリング課題を念頭に設計された。2026年2月のGLM-5、4月のGLM-5.1に続き、6月13日にGLM Coding Plan購読者に先行公開され、6月17日にHugging Faceで全重みがMITライセンスで公開された。核心スペックは以下の通りである。

項目 仕様
コンテキスト長 1Mトークン(1,048,576トークン)
最大出力トークン 128K
パラメータ 約753B(MoE構造、トークン当たり約40B活性化)
ライセンス MITオープンソース
対応言語 英語、中国語

GLM-5.2はIndexShareという新しい疎(sparse)アテンション技法を導入し、1Mコンテキスト長でもトークン当たりの演算量を従来方式の約1/3レベルに削減した。またMTPレイヤーを改善しspeculative decodingの受容長を最大20%伸ばした。

ベンチマーク性能も印象的である。Terminal-Bench 2.1で81.0点を記録し、GLM-5.1(63.5)比で大幅に向上した。SWE-bench Proでは62.1点を達成した。Code Arenaでは1595点で全体2位、グローバル利用可能モデルの中では1位を記録した。ただし、これらの数値の多くはベンダー(Z.ai)自身の測定値であり、まだ独立検証が完了していない点は留意すべきである。

Getting Started: GLM-5.2を始める

GLM-5.2を使用する方法は大きくZcode(公式デスクトップアプリ)、API直接呼び出し、サードパーティコーディングツール連携の3つがある。

1. Zcodeのインストールと実行

Zcodeは Z.aiが提供する公式デスクトップアプリケーションであり、GLM-5.2を最も簡単に体験できる方法である。

① Zcodeのダウンロード公式サイト(zcode.z.ai)からmacOS、Windows、Linux用インストーラーをダウンロードする。② 会員登録とAPIキー発行z.aiに登録した後、ダッシュボードでAPIキーを生成する。コーディング専用の使用を望むならGLM Coding Planに購読するのが良い。Lite(約$18/月)、Pro、Max、Teamなど様々な料金プランがある。③ Zcodeの実行とモデル選択

Zcodeにログイン後、モデル選択画面でGLM-5.2を選択すればすぐに使用できる。

2. APIで直接呼び出す

プログラミング方式でGLM-5.2を活用するには、OpenAI互換APIを使用できる。

エンドポイント情報:

設定 値
Chat completionsエンドポイント https://api.z.ai/api/paas/v4/chat/completions
SDK用Base URL https://api.z.ai/api/paas/v4/
モデルID glm-5.2
認証 Authorization: Bearer $ZAI_API_KEY

cURL例:

curl https://api.z.ai/api/paas/v4/chat/completions \
  -H "Authorization: Bearer $ZAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.2",
    "messages": [{"role": "user", "content": "Hello, GLM-5.2!"}]
  }'

Python例:

import openai

client = openai.OpenAI(
    base_url="https://api.z.ai/api/paas/v4/",
    api_key="YOUR_API_KEY"
)

response = client.chat.completions.create(
    model="glm-5.2",
    messages=[{"role": "user", "content": "Write a Python function to reverse a linked list"}]
)
print(response.choices[0].message.content)

3. Claude Code、Cline、Cursorなどとの連携

GLM-5.2は開発者が既に使用しているコーディングツールとも簡単に連携できる。

Claude Code設定:

export ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"
export ANTHROPIC_API_KEY="your-glm-coding-plan-key"
# settings.jsonでモデルIDをglm-5.2[1m]に設定

OpenAI互換ツール(Cline、OpenCodeなど)設定:

Base URL: https://api.z.ai/api/paas/v4/
Model ID: glm-5.2
API Key: your-api-key

GLM-5.2の使用法: 実践ワークフロー

ZcodeやAPIを通じてGLM-5.2に接続したら、実際の開発ワークフローでどのように活用できるだろうか?公式文書は3つの代表的な使用シナリオを提案している。

シナリオ1: プロジェクトレベルのコードベース把握

GLM-5.2の1Mコンテキストは、プロジェクト全体を一度に理解するのに最適化されている。複雑なバックエンドとフロントエンドが混在する実業務のコードベースを選択した後、モデルに次のように要求してみよう。

「現在のプロジェクトを読み、システムアーキテクチャマップ、核心モジュールの責任、主要API契約、データフロー、核心コールチェーン、潜在的な技術的負債、そして今後のリファクタリングで従うべきエンジニアリング制約条件を出力してください。」

シナリオ2: 長期間のリファクタリング

GLM-5.2は複数ファイル横断、多段階、長いチェーンの作業でより安定している。モジュール分離、APIマイグレーション、ディレクトリ再構成など、継続的な進行が必要な作業に適している。/goalモードを有効化して次のように指示しよう。

「ビジネスロジック、APIシグネチャ、ランタイム動作を変更せず、現在のモジュールの分離とリファクタリングを完了してください。実行計画、影響範囲、リスク境界、検証方法を先に提示し、完了後に必要なテストを実行して検証結果を出力してください。」

シナリオ3: エンジニアリング標準の遵守

GLM-5.2はエンジニアリング標準を一貫して守る能力に優れている。チームの実際のlintルール、ビルドコマンド、テスト要件、コミット規則などをCLAUDE.mdやAgent.mdに定義した後、次のように指示しよう。

「現在のリポジトリのエンジニアリング標準を厳格に守ってください。新しい依存性を導入せず、API契約を修正せず、変更事項を事前にコミットしないでください。修正完了後にビルド、lint、テストを実行し、検証結果と発見されたリスク要因を報告してください。」

長所(Pros)

1. オープンウェイト+低コスト

GLM-5.2はモデルの重みを公開するオープンウェイト方式で提供される。開発者と企業が自社環境でモデルをダウンロードして運用または修正できるため、閉鎖型モデルに比べてコスト負担を減らしながら活用の自律性を高められる。API使用時も入力トークン100万個当たり$1.40、出力トークン100万個当たり$4.40と、競合他社に比べて非常に低価格である。

2. 優れたコーディング性能

GLM-5.2は単純なチャットボットよりもコーディング作業とソフトウェア開発ワークフローに強みを持つモデルとして評価されている。MetaやGoogle DeepMind出身の開発者を含む多数の独立テスターが「日常業務用の基準を通過した最初のオープンモデル」と評価した。

3. 1Mトークンコンテキスト

安定した1Mコンテキストは GLM-5.2の最大の強みである。プロジェクト規模のエンジニアリングコンテキストを安定的に処理し、長時間実行される作業の後半でもコンテキストの断片化現象が大きく減少する。

4. 多様な連携オプション

Claude Code、Cline、Cursor、OpenCodeなど既に広く使用されているコーディングツールとの連携が簡単である(リリース時点で20以上のサードパーティ環境をサポート)。開発者は使い慣れた環境を維持しながらGLM-5.2の性能を活用できる。

5. Thinking Effortの調整可能性

GLM-5.2はHighとMaxの2つの推論努力レベルを提供し、作業の複雑度に応じて性能と応答速度の間のバランスを調整できる。

短所(Cons)

1. 中国産モデルへの懸念

DeepSeekに続き、GLM-5.2も中国産オープンウェイトモデルである。一部の企業や開発者はデータセキュリティ、国家安全保障、技術依存性などの理由で中国産AIモデルの使用を避ける可能性がある。実際、米商務省産業安全保障局(BIS)は2025年1月にZhipu AIを輸出管理対象リスト(Entity List)に追加し、2026年5月には米下院がPRC発AIモデルの重要インフラサイバーセキュリティリスクに関する調査を開始し、Zhipu AIをDeepSeek・MiniMax・ByteDanceと共に言及した。GLM-5.2は米国の技術業界で「新たなDeepSeekモーメント」と呼ばれ、敏感に受け止められている。

2. 閉鎖型モデルとの性能差

ベンチマークで優れた性能を示すが、Claude Opus 4.8やGPT-5.5のような最上位の閉鎖型モデルには依然としてわずかに劣る領域がある。特に超長期間・高難度の課題でその差が目立つが、これは「世代差」ではなく「特定ベンチマークでの点数差」レベルに縮小したという評価が一般的である。

3. API課金構造

APIはトークンベースの課金構造であり、大規模自動化作業ではコストが急増する可能性がある。Coding Planを購読すれば一定程度コストを削減できるが、使用量の多いチームには依然として負担になる可能性がある。

4. 韓国語サポートの不足

公式文書上、GLM-5.2は英語と中国語をサポートする。韓国語プロンプトやコードコメント、文書化作業では性能がやや劣る可能性がある。

5. エコシステムの成熟度

OpenAI、Anthropicなどの閉鎖型モデルに比べ、コミュニティとサードパーティツールのエコシステムがまだ成熟していない。チュートリアルや問題解決資料も相対的に不足している。

3社比較: DeepSeek V4-Pro vs Claude Opus 4.8 vs GLM-5.2

GLM-5.2の座標を正確に把握するには、同時期にリリースされた競合モデルと並べて見る必要がある。2026年上半期のコーディングモデル市場は事実上3陣営の三派戦である。閉鎖型フロンティアを代表するClaude Opus 4.8、コストパフォーマンスを武器にしたオープンウェイトのDeepSeek V4-Pro、そしてオープンウェイトのコーディング特化で急伸したGLM-5.2である。

価格こそがこの三派戦の核心変数である。DeepSeek V4-Proの出力トークンコストを1と置くと、GLM-5.2は約5倍、Opus 4.8は約29倍である。つまりOpus 4.8がGLM-5.2に比べSWE-bench Proで約7点多く得るために支払うべきトークンコストは5〜6倍に達する。

一言まとめ

  • DeepSeek V4-Pro — コストパフォーマンスのチャンピオン。フロンティア級に近いスコアを圧倒的な最低価格で提供。大規模自動化・RAG・大量ボリュームパイプラインに最適。ただし最も難易度の高いエージェントループではスコアが一段落ちる。
  • Claude Opus 4.8 — 閉鎖型フロンティア。SWE-bench Pro 1位、エージェント信頼性と「誠実性」(欠陥を隠さず報告する)の面で優位。3つの中で最も高価だが、失敗コストがトークンコストより大きい高難度・長期間作業に対して価値がある。
  • GLM-5.2 — オープンウェイトコーディング最強候補。1Mコンテキストの安定性とコーディングスコアで閉鎖型に最も近いオープンモデル。価格はDeepSeekとOpusの中間。自己ホスティング(MIT)が可能な点が企業にとって大きな意味を持つ。

選択基準を凝縮すればこうなる。コストが最優先ならDeepSeek V4-Pro、最も難易度の高い長期間課題の信頼性が最優先ならClaude Opus 4.8、オープンウェイトの自己ホスティングとコーディング性能のバランスが最優先ならGLM-5.2である。ただし中国産の2モデル(DeepSeek・GLM)は、Z.ai/DeepSeekクラウドAPIに機密データをルーティングする場合の規制・セキュリティリスクを自己ホスティングで回避できるかをまず検討することが順序である。

おわりに: GLM-5.2がもたらす変化

Zhipu AIのGLM-5.2は、DeepSeek以降中国のAI企業が選択した「低コスト・高性能オープンウェイト」戦略をコーディングと開発自動化領域に拡張した事例である。コーディングモデルは開発者の生産性だけでなく、企業向けAIエージェント、業務自動化、ソフトウェア保守市場と直結している。企業の立場から見て、十分な性能を持つオープンウェイトモデルを自社インフラで運用できれば、高価なAPIベースの閉鎖型モデルへの依存度を大きく下げられる。

ただし、ベンチマークスコアはあくまで参考値である。ベンダー自体の測定値とハーネスの違いを取り除くと、3つのモデルの本当の違いは「自分のワークロードにおいて、1回の失敗がトークン価格差より高いか」という問いに収束する。その答えによって、同じ作業でも最適なモデルは変わってくる。

業界関係者の言葉通り、開発者が実際の業務で使えると判断した瞬間、オープンウェイトモデルの影響力はさらに大きくなり得る。GLM-5.2がその転換点になるかは見守るべきことである。

参考: 数値の出所と留意点

  • ベンチマーク・価格の数値は各ベンダー(Anthropic、DeepSeek、Z.ai)の発表および2026年6月基準の公開トラッカー(llm-stats、Artificial Analysisなど)を参考にしており、かなりの部分がベンダー自体の測定値であり独立検証が進行中である。
  • Terminal-Benchはバージョン(2.0/2.1)とハーネス(Terminus-2、Codex CLIなど)によってスコアが異なるため、同じ表にあっても直接比較は推奨されない。
  • DeepSeek V4-Proの価格は2026年5月22日付で常時適用される$0.435/$0.87基準であり、以前の定価($1.74/$3.48)は歴史的数値である。
  • Claude Opus 4.8の価格は標準モード$5/$25、Fastモード$10/$50基準である。
  • GLM-5.2の価格はZ.ai API $1.40/$4.40、GLM Coding Plan約$18/月(プロモーション時はより低い)基準である。

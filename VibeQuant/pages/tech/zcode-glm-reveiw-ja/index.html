Zcodeで体験するGLM-5.2

발행 2026.06.17 · 주제 LLM · 에이전트 · Zcode

🇰🇷 한국어 English 日本語 中文

智譜AI(Zhipu AI)のフラッグシップ・オープンウェイト・コーディングモデルGLM-5.2をZcode・API・サードパーティツールで使う実践ガイド。長所・短所、DeepSeek V4-ProおよびClaude Opus 4.8との三者比較付き。

中国AI企業の智譜AI(Zhipu AI)が最近公開したフラッグシップモデル GLM-5.2 が、米国の開発者コミュニティで注目を集めています。オープンウェイト(open-weight)方式で提供されながらも、コーディング性能で閉鎖型モデルに匹敵する結果を出しているためです。本記事では、Zcodeを中心にGLM-5.2を直接体験する方法と、モデルの長所・短所を見ていきます。

GLM-5.2とは?

GLM-5.2はZ.ai(智譜AI)の最新フラッグシップモデルで、長期間(long-horizon)のソフトウェアエンジニアリング課題を念頭に設計されました。2026年2月のGLM-5、4月のGLM-5.1に続き、6月13日にGLM Coding Plan加入者向けに先行公開され、6月17日にHugging Faceで全重みがMITライセンスで公開されました。主要スペックは以下のとおりです。

項目 仕様
コンテキスト長 1Mトークン(1,048,576トークン)
最大出力トークン 128K
パラメータ 約753B(MoE構造、トークンあたり約40B活性)
ライセンス MITオープンソース
対応言語 英語、中国語

GLM-5.2は IndexShare という新しいスパース(sparse)アテンション手法を導入し、1Mコンテキスト長でもトークンあたりの計算量を従来方式の約1/3に削減しました。MTPレイヤーを改善し、speculative decodingの受容長を最大20%延長しています。

ベンチマーク性能も印象的です。Terminal-Bench 2.1で81.0点を記録し、GLM-5.1(63.5)比で大幅に向上しました。SWE-bench Proでは62.1点を達成しています。Code Arenaでは1595点で全体2位、グローバル利用可能モデル中1位を記録しました。ただし、これらの数値の相当数はベンダー(Z.ai)自身の測定値であり、独立検証はまだ完了していない点に留意が必要です。

Getting Started: GLM-5.2の始め方

GLM-5.2の利用方法は大きく Zcode(公式デスクトップアプリ)、API直接呼び出し、サードパーティコーディングツール連携 の3つに分かれます。

1. Zcodeのインストールと実行

ZcodeはZ.aiが提供する公式デスクトップアプリケーションで、GLM-5.2を最も簡単に体験できる方法です。

① Zcodeのダウンロード公式サイト(zcode.z.ai)からmacOS、Windows、Linux用のインストーラーをダウンロードします。② 会員登録とAPIキー発行z.aiに登録後、ダッシュボードでAPIキーを作成します。コーディング専用利用を希望する場合はGLM Coding Planの加入がおすすめです。Lite(月額約$18)、Pro、Max、Teamなど複数の料金プランがあります。③ Zcodeの起動とモデル選択

Zcodeにログイン後、モデル選択画面でGLM-5.2を選べばすぐに利用できます。

2. APIで直接呼び出す

プログラムからGLM-5.2を活用するには、OpenAI互換APIを使用できます。

エンドポイント情報:

設定 値
Chat completionsエンドポイント https://api.z.ai/api/paas/v4/chat/completions
SDK用Base URL https://api.z.ai/api/paas/v4/
モデルID glm-5.2
認証 Authorization: Bearer $ZAI_API_KEY

cURL例:

curl https://api.z.ai/api/paas/v4/chat/completions \
  -H "Authorization: Bearer $ZAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.2",
    "messages": [{"role": "user", "content": "Hello, GLM-5.2!"}]
  }'

Python例:

import openai

client = openai.OpenAI(
    base_url="https://api.z.ai/api/paas/v4/",
    api_key="YOUR_API_KEY"
)

response = client.chat.completions.create(
    model="glm-5.2",
    messages=[{"role": "user", "content": "Write a Python function to reverse a linked list"}]
)
print(response.choices[0].message.content)

3. Claude Code、Cline、Cursorなどとの連携

GLM-5.2は開発者が既に使っているコーディングツールとも簡単に連携できます。

Claude Code設定:

export ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"
export ANTHROPIC_API_KEY="your-glm-coding-plan-key"
# settings.jsonでモデルIDをglm-5.2[1m]に設定

OpenAI互換ツール(Cline、OpenCodeなど)設定:

Base URL: https://api.z.ai/api/paas/v4/
Model ID: glm-5.2
API Key: your-api-key

GLM-5.2の使い方: 実践ワークフロー

ZcodeやAPI経由でGLM-5.2に接続したら、実際の開発ワークフローでどう活用できるでしょうか。公式ドキュメントは3つの代表的な利用シナリオを提案しています。

シナリオ1: プロジェクト規模のコードベース把握

GLM-5.2の1Mコンテキストは、プロジェクト全体を一度に理解するのに最適化されています。複雑なバックエンドとフロントエンドが混在する実務コードベースを選び、モデルに次のように依頼してみてください。

"現在のプロジェクトを読み、システムアーキテクチャマップ、コアモジュールの責務、主要API契約、データフロー、主要コールチェーン、潜在的な技術的負債、および今後のリファクタリングで従うべきエンジニアリング制約条件を出力してください。"

シナリオ2: 長期間リファクタリング

GLM-5.2はファイル横断、多段階、長いチェーンの作業でより安定しています。モジュール分離、API移行、ディレクトリ再構成など、連続的な進行が必要な作業に適しています。/goalモードを有効にし、次のように指示してください。

"ビジネスロジック、APIシグネチャ、ランタイム動作を変更せず、現在のモジュールの分離とリファクタリングを完了してください。実行計画、影響範囲、リスク境界、検証方法を先に提示し、完了後に必要なテストを実行して検証結果を出力してください。"

シナリオ3: エンジニアリング標準の遵守

GLM-5.2はエンジニアリング標準を一貫して守る能力に優れています。チームの実際のlintルール、ビルドコマンド、テスト要件、コミット規則などをCLAUDE.mdやAgent.mdに定義した後、次のように指示してください。

"現在のリポジトリのエンジニアリング標準を厳密に守ってください。新しい依存関係を導入せず、API契約を変更せず、変更を事前にコミットしないでください。修正完了後、ビルド、lint、テストを実行し、検証結果と発見されたリスク要素を報告してください。"

長所(Pros)

1. オープンウェイト + 低コスト

GLM-5.2はモデル重みを公開するオープンウェイト方式で提供されます。開発者と企業は自社環境でモデルをダウンロードして運用・改変でき、閉鎖型モデル比でコスト負担を抑えつつ利用の自由度を高められます。API利用時も、入力100万トークンあたり $1.40、出力100万トークンあたり $4.40 と、競合比で非常に安価です。

2. 優れたコーディング性能

GLM-5.2は単純なチャットボットより、コーディング作業とソフトウェア開発ワークフローに強みを持つモデルと評価されています。MetaやGoogle DeepMind出身の開発者を含む多数の独立テスターが「日常業務基準をクリアした初のオープンモデル」と評価しています。

3. 1Mトークンコンテキスト

安定した1MコンテキストはGLM-5.2最大の強みです。プロジェクト規模のエンジニアリングコンテキストを安定して処理し、長時間実行タスクの後半でもコンテキスト断片化が大幅に減ります。

4. 多様な連携オプション

Claude Code、Cline、Cursor、OpenCodeなど、広く使われているコーディングツールとの連携が簡単です(リリース時点で20以上のサードパーティ環境をサポート)。開発者は慣れた環境を維持したままGLM-5.2の性能を活用できます。

5. Thinking Effortの調整可能

GLM-5.2はHighとMaxの2段階の推論努力レベルを提供し、タスクの複雑度に応じて性能と応答速度のバランスを調整できます。

短所(Cons)

1. 中国製モデルへの懸念

DeepSeekに続き、GLM-5.2も中国製オープンウェイトモデルです。一部の企業や開発者は、データセキュリティ、国家安全保障、技術依存などの理由で中国製AIモデルの利用を躊躇する可能性があります。実際、米国商務省産業安全保障局(BIS)は2025年1月に智譜AIを輸出管理対象(Entity List)に追加し、2026年5月には米下院がPRC発AIモデルの中核インフラに関するサイバーセキュリティリスク調査を開始し、智譜AIをDeepSeek・MiniMax・ByteDanceとともに言及しました。GLM-5.2は米国テック業界で「新たなDeepSeekモーメント」として敏感に受け止められています。

2. 閉鎖型モデルとの性能差

ベンチマークでは優れた性能を示しますが、Claude Opus 4.8やGPT-5.5のような最上位閉鎖型モデルには依然としてわずかに劣る領域があります。特に超長期・高難度課題で差が目立ちますが、一般的な評価では「世代差」ではなく「特定ベンチマークでのスコア差」レベルまで縮まったとされています。

3. API課金構造

APIはトークンベースの課金構造で、大規模自動化作業ではコストが急増する可能性があります。Coding Planに加入すればある程度コストを抑えられますが、使用量の多いチームには依然として負担となり得ます。

4. 韓国語サポートの不足

公式ドキュメント上、GLM-5.2は英語と中国語をサポートします。韓国語プロンプトやコードコメント、ドキュメント作成では性能がやや低下する可能性があります。

5. エコシステムの成熟度

OpenAI、Anthropicなどの閉鎖型モデルと比べ、コミュニティとサードパーティツールのエコシステムはまだ未成熟です。チュートリアルやトラブルシューティング資料も相対的に不足しています。

三者比較: DeepSeek V4-Pro vs Claude Opus 4.8 vs GLM-5.2

GLM-5.2の位置づけを正確に把握するには、同時期にリリースされた競合モデルと並べて見る必要があります。2026年上半期のコーディングモデル市場は、事実上3陣営の三つ巴です。閉鎖型フロンティアを代表する Claude Opus 4.8、コスパを武器にしたオープンウェイト DeepSeek V4-Pro、オープンウェイト・コーディング特化で押し上がってきた GLM-5.2 です。

コーディングベンチマーク

異なるベンダーの数値を1表にまとめましたが、3モデルすべて自社測定値(self-reported)が混在し、ハーネス(harness)・ベンチバージョンが異なるため、直接比較には限界があります。 最も同条件に近い指標はSWE-bench Proです。

Terminal-Bench 67.9 (v2.0) 74.6 (v2.1, Terminus-2) 81.0 (v2.1, ベンダー測定)

LiveCodeBench 93.5 — —

注意:Terminal-Benchはモデルごとにバージョン(2.0/2.1)とハーネスが異なり、1行に並べてもりんご対オレンジの比較です。GLM-5.2の81.0はZ.ai自身のハーネス数値、Opus 4.8の74.6は公開Terminus-2ハーネス基準です。条件が異なるため「GLMがOpusを上回った」と断定できません。一方SWE-bench Proは比較的標準化されたセットで、Opus 4.8(69.2) > GLM-5.2(62.1) > DeepSeek V4-Pro(55.4) の順になります。

価格

項目 DeepSeek V4-Pro Claude Opus 4.8 GLM-5.2
入力(per 1M) $0.435 $5.00 $1.40
出力(per 1M) $0.87 $25.00 $4.40
サブスクリプションプラン — Claude Pro/Max GLM Coding Plan 約$18/月

価格こそがこの三つ巴の核心変数です。DeepSeek V4-Proの出力トークンコストを1とすると、GLM-5.2は約5倍、Opus 4.8は約29倍です。つまりOpus 4.8がGLM-5.2比でSWE-bench Pro約7点多く得るために支払うトークンコストは5~6倍に達します。

一行まとめ

  • DeepSeek V4-Pro — コスパチャンピオン。フロンティア級に近いスコアを圧倒的最安値で提供。大規模自動化・RAG・高ボリュームパイプラインに最適。ただし最も難しいagenticループではスコアが一段下がる。
  • Claude Opus 4.8 — 閉鎖型フロンティア。SWE-bench Pro 1位、agentic信頼性と「正直さ」(欠陥を隠さず報告)で優位。一方で3モデル中最も高価。失敗コストがトークンコストを上回る高難度・長期作業に価値あり。
  • GLM-5.2 — オープンウェイト・コーディング最強候補。1Mコンテキスト安定性とコーディングスコアで閉鎖型に最も近いオープンモデル。価格はDeepSeekとOpusの中間。MITでの自己ホスティングが企業にとって大きな意味を持つ。

選択基準を圧縮するとこうなります。コスト最優先ならDeepSeek V4-Pro、最も難しい長期課題の信頼性最優先ならClaude Opus 4.8、オープンウェイト自己ホスティングとコーディング性能のバランス最優先ならGLM-5.2 です。ただし2つの中国製モデル(DeepSeek・GLM)については、Z.ai/DeepSeekクラウドAPIで機密データをルーティングする場合の規制・セキュリティリスクを、自己ホスティングで回避できるかから検討するのが順序です。

おわりに: GLM-5.2がもたらす変化

智譜AIのGLM-5.2は、DeepSeek以降中国AI企業が選んだ「低コスト・高性能オープンウェイト」戦略を、コーディングと開発自動化の領域へ拡張した事例です。コーディングモデルは開発者生産性だけでなく、企業向けAIエージェント、業務自動化、ソフトウェア保守市場とも直接結びつきます。企業にとって性能が十分なオープンウェイトモデルを社内インフラで運用できれば、高価なAPIベース閉鎖型モデルへの依存度を大きく下げられます。

ただしベンチマークスコアはあくまで参考値です。ベンダー自己測定値とハーネス差を除くと、3モデルの真の差は「自分のワークロードで失敗1回がトークン価格差より高いか」という問いに収束します。その答えによって、同じ作業でも最適モデルは変わります。

業界関係者の言うとおり、開発者が実務で使えると判断した瞬間、オープンウェイトモデルの影響力はさらに大きくなり得ます。GLM-5.2がその転換点になるかは見守るところです。

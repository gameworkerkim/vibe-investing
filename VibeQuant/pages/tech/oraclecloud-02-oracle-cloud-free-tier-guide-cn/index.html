1. 为什么选择 OCI Free Tier

在行业免费套餐中，OCI 的资源规模最大，且没有时间限制。与同类 AWS、GCP 免费套餐相比，差异非常明显。

项目 OCI Always Free AWS Free Tier (12 个月) GCP Always Free
核心 VM ARM Ampere A1 4 OCPU / 24 GB RAM t2.micro / t3.micro 1 vCPU / 1 GB RAM e2-micro 1 vCPU / 1 GB RAM
实例拆分 最多拆成 4 台 1 台 1 台
额外 x86 实例 E2.1.Micro 2 台 (1 OCPU / 1 GB) — —
块存储 200 GB 30 GB EBS 30 GB
出站流量 10 TB/月 100 GB/月 1 GB/月
期限 无限制 (Always Free) 12 个月 无限制

关键不只是 ARM 4 核 24GB 的物理资源本身，而是 可以永久免费使用。个人 VPN、自托管 AI 代理、K3s 集群、轻量 LLM 推理服务器等实际工作负载，基本上只有这一家免费云能跑。

2. 免费套餐的两条轨道

注册后会同时获得两类免费资源。混淆两者可能产生账单。

区分 Always Free Free Trial
期限 无限制 注册后 30 天
上限 固定资源清单 (见下文 §3) $300 USD 额度
到期后 继续可用 未用额度作废，仅保留 Always Free 资源
风险 几乎无 30 天内创建付费资源，额度耗尽后可能自动扣费

原则：若不想被扣费，前 30 天在控制台只创建带 "Always Free Eligible" 标签的资源。30 天后，付费资源创建会被阻止（在维持 Always Free 账户的前提下）。

3. Always Free 资源详情

整体上限如下。所有资源仅在注册时选择的 Home Region 提供。

3.1 计算

Shape 数量 规格 备注
VM.Standard.A1.Flex (ARM Ampere) 最多 4 台 合计 4 OCPU / 24 GB RAM 每月 3,000 OCPU 小时 + 18,000 GB 小时。4 OCPU × 24h × 31 天 = 2,976 小时，满负荷也在限额内
VM.Standard.E2.1.Micro (AMD x86) 2 台 各 1 OCPU / 1 GB RAM 用于不兼容 ARM 的软件

ARM 与 x86 可混用，最多同时运行 6 台。但启动卷合计不得超过 200 GB。

4. 注册流程 (韩国用户)

4.1 事前准备

项目 建议
银行卡 新办的 VISA/Master 信用卡或借记卡
不可用 PIN 借记卡、预付卡、虚拟卡、一次性卡 (Oracle 明确拒绝)
邮箱 从未用于 OCI Free Tier 或旧 Free Trial 的地址
手机 从未用于 OCI 的号码 (需 SMS 验证)
英文地址 准确的道路英文拼写 (掩码或随意修改会被拒)

OCI 通过邮箱 + 手机号 + 卡号组合识别重复注册。同一张卡可重复使用有限次数，但尽量用新卡更安全。 最重要的是核对发卡行登记的地址，必须准确填写才能进入下一步。

4.2 步骤

  1. 访问 https://www.oracle.com/kr/cloud/free/ → 「무료로 시작하기」(免费开始)
  2. 邮箱验证 → 设置密码
  3. 账户信息：姓名与持卡人一致，地址用准确英文
  4. 选择 Home Region：选定后不可更改。韩国用户通常从以下选择
    • Seoul (ap-seoul-1)：延迟最低，但 ARM 容量经常不足
    • Chuncheon (ap-chuncheon-1)：韩国第二个区域，相对较空
    • Tokyo / Osaka：延迟 30~50ms，ARM 容量较易获得
    • 可用性优先选 Chuncheon 或 Osaka，延迟优先选 Seoul
  5. 手机验证：010-1234-5678 → 输入 1012345678 (去掉前导 0)
  6. 绑卡：产生 $1 授权冻结后立即取消，无实际扣款
  7. 同意条款 → 「Complete Sign-up」

4.3 注册失败时

最常见提示是「交易处理错误」。原因多半是以下之一：

  • 卡被拒绝 (韩国发行的部分卡被拒案例较多)
  • IP/位置不一致 (若开着 VPN 请关闭)
  • 邮箱、手机、卡全部相同信息反复重试 → 被封锁
  • 地址与卡登记地址不一致

解决顺序：

  1. 立即换另一张卡重试 (禁止用相同信息重复)
  2. 仍失败则通过 Oracle Cloud Customer Service 聊天或表单提交工单
  3. 还不行则用新邮箱 + 新手机号 + 新卡组合重新注册
  4. Facebook「Oracle Cloud KR User Group」有韩国甲骨文员工活跃，拒批案例可求助

5. 创建 ARM 实例：规避「Out of host capacity」

OCI 免费套餐最大的实战坑。韩国、东京区域的 ARM A1 新分配几乎总是满的。 当前情况是在仁川区域用 AMD 1 vCore 先应付。

5.1 推荐配置

项目 建议
Image Canonical Ubuntu 24.04 Minimal aarch64
Shape VM.Standard.A1.Flex
OCPU/RAM 2 OCPU / 12 GB (比 4 OCPU 更容易抢到)
Boot Volume 47~50 GB (默认)
SSH Key 本地 ~/.ssh/id_ed25519.pub 或在控制台生成密钥对后立即下载私钥
Public IP 勾选「Assign a public IPv4 address」

5.2 容量获取策略 (按效果排序)

  1. OCPU 从 4 降到 2：一次要 4 OCPU 几乎必失败。拆成 2 台各 2 OCPU，总资源相同但成功率高很多。
  2. 凌晨重试 (韩国时间 02:00~06:00)：其他用户活动少时会有资源回收。
  3. 切换 Availability Domain：分别试 AD-1、AD-2、AD-3。同一区域内各 AD 容量不同。
  4. 自动重试脚本：GitHub 上的 hitrov/oci-arm-host-capacity 等 OSS 轮询 OCI API，有空位立即创建实例。需注册自己的 OCI API 密钥。
  5. 转 PAYG：绑定卡信息转为按量付费账户后，据称 ARM 容量优先级会提高。Always Free 限额内仍为 0 元，但 误建付费资源会扣费 — 不用的付费服务务必设控制台告警。

5.3 仍然抢不到时

  • 先用 VM.Standard.E2.1.Micro (AMD) 创建实例，可立即成功。ARM 之后再慢慢抢。
  • 要改 Home Region 只能开新账户，已注册账户无法更改 Home Region。

6. 安全与运维基础配置

6.1 网络

OCI 默认 阻断所有入站。与 AWS Security Group 不同，需开两层：

  1. VCN Security List：控制台 → Networking → Virtual Cloud Networks → 对应 VCN → Security Lists → Default Security List → Ingress Rules 添加 80/443/所需端口
  2. 实例 OS 的 iptables：Ubuntu 镜像启用 iptables 会额外阻断。用以下命令检查并放行
sudo iptables -L INPUT -n --line-numbers
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save

两步都做完才能从外网访问。

6.2 SSH 连接

ssh -i ~/.ssh/id_ed25519 ubuntu@<public-ip>
# Oracle Linux 镜像用 opc 而非 ubuntu

6.3 避免 Idle Reclamation

Always Free 实例在以下条件下会被回收：

  • 7 天 CPU 95 分位 低于 20% 且
  • 7 天网络使用 95 分位 低于 20% 且
  • 7 天内存使用 95 分位 低于 20%

须三者同时满足，因此常见自托管负载（博客、VPN、机器人）是安全的。若真是闲置的学习 VM，可用以下 cron 故意制造负载：

# /etc/cron.d/keepalive — 每小时占用 CPU 1 分钟
0 * * * * root timeout 60 yes > /dev/null

6.4 必设计费告警

控制台 → Billing → Budgets 创建 $1 上限预算，在 50%、80%、100% 阈值发邮件。转 PAYG 时尤其重要。

7. 韩国用户常见陷阱

陷阱 后果 规避
注册时开 VPN 位置不一致 → 被拒 注册时关 VPN，注册后再开
使用预付/虚拟卡 被拒 用 VISA/Master 信用/借记卡
相同信息反复尝试 可能永久封锁 试 1~2 次后换信息
一次申请 4 OCPU Out of capacity 无限循环 拆成 2 OCPU × 2 台
只开 Security List 未开 iptables 外网无法访问 两边都要配置
Docker 容器含外部矿机 账户立即永久封禁 只用可信镜像，官方 Hub 也要验证
30 天试用期内创建付费资源 $300 额度耗尽后自动扣费 只用带「Always Free Eligible」标签的资源
Home Region 选错 无法更改，需新账户 推荐 Chuncheon/Osaka

8. 推荐用例

ARM 4 OCPU / 24 GB 可实际运行的负载：

用途 配置 备注
个人 VPN 单独 WireGuard 1 OCPU 足够，10 TB 流量
博客/主页 Nginx + WordPress + MariaDB 1 OCPU / 6 GB
K3s 集群 1 控制面 + 3 worker (各 1 OCPU / 6 GB) Kubernetes 学习
自托管 AI Ollama + 7B/8B 量化模型 8~20 tokens/s，占满 4 OCPU
自动化工作流 n8n + Postgres (Docker Compose) 必须确认 ARM 兼容镜像
游戏服务器 Minecraft Java + GeyserMC 建议 2 OCPU / 12 GB
个人 DNS/广告拦截 AdGuard Home / Pi-hole 几乎不占资源

ARM 兼容性：多数开源软件提供多架构镜像。但 部分闭源或老旧 Docker 镜像仅 amd64，docker pull 时需检查 platform 选项。最后手段是在 E2.1.Micro x86 实例上运行。

9. PAYG (Pay-As-You-Go) 迁移考量

迁移优点：

  • 更容易获得 ARM A1 容量
  • 可使用 AI/ML、高性能网络等付费服务
  • 可正式提交客户支持工单
  • Always Free 资源仍免费

迁移风险：

  • 误建无「Always Free Eligible」标签的资源会立即计费
  • 启动卷超过 200 GB 按超出部分计费
  • 流量超过 10 TB 按超出部分计费

PAYG 迁移决策标准：仅当必须将 ARM 实例放在韩国/东京区域，且自动化脚本仍抢不到时才考虑。否则建议维持 Always Free。

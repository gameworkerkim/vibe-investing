Qwenローカルインストールガイド&注意事項(改訂版)

발행 2026.06.30 · 주제 LLM · 에이전트 · Local_LLM

🇰🇷 한국어 English 日本語 中文

Ollama・LM Studio・Hugging Face Transformersを使ったQwenのローカルインストールを解説するファクトチェック済みガイド。Qwen3/Qwen3.5/Qwen3.6ラインアップのハードウェア別表を収録。

Qwen概要

Qwen(中国語: 千問、「チュエン」と発音)はアリババグループが開発した大規模言語モデル(LLM)および大規模マルチモーダルモデルの製品群である。初版は2023年4月にベータ形式で公開され、現在では世界最大級のオープンソースAIエコシステムの一つに成長した。2026年3月、アリババはAIブランドを「Qwen大規模モデル」に統一し、以前の混乱を解消した。

主要機能

Qwenは様々なマルチモーダル・言語タスクを実行できる。

自然言語理解およびテキスト生成

視覚理解(画像、動画)

音声理解および処理

ツール呼び出しおよびAIエージェント機能

ロールプレイおよび複数ターンの対話

モデルは大規模な多言語・マルチモーダルデータで事前訓練され、高品質データで微調整することで人間の選好に合致するよう設計されている。

技術構造と特徴

デュアルモードアーキテクチャ(思考モード/非思考モード) Qwen3の核心的な革新は、一つのモデルに「思考モード」と「非思考モード」を同時に搭載して効率を高めたことである。

モード 適用状況
思考モード 複雑な論理推論、数学、プログラミングなど深い思考が必要な作業
非思考モード 高速な応答が必要な一般対話

モデルは「思考予算(thinking budget)」メカニズムを通じて問題の複雑さを動的に評価し、計算資源を自動配分する。

モデル構造 DenseモデルとMoE(Mixture of Experts)モデルが並存し、0.6Bから235Bまで様々な規模を提供する。

Qwen3-Nextは高疎度MoEアーキテクチャを採用: 総パラメータ800億、推論時には約30億パラメータ(約3.75%)のみを活性化して効率性を大幅に向上させている。

Qwen3-Maxは総パラメータ1兆(1T)以上、事前訓練に36Tトークンを使用。

訓練戦略 3段階の事前訓練: 言語基盤の構築 → 推論能力の強化 → 長文テキスト能力の拡張

4段階の事後訓練: 長い思考連鎖のコールドスタート、推論強化学習、モード融合などを含む

「大モデルが小モデルを育成する」蒸留方式: 大モデルのデータで小モデルを訓練

主要バージョンとモデル

Qwen 3.5 2026年2月 - フラッグシップモデル 総397B(アクティブ17B) 262Kネイティブコンテキスト(1Mまで拡張可能) 201言語対応、Apache 2.0オープンソース

Qwen3.7-Max 2026年5月 - エージェント特化 35時間以上の超長期複雑タスクを完全自律で実行可能

Qwen3-Max 2025年9月 - 総パラメータ1T以上、LMArenaランキング世界3位

オープンソースモデルはQwen、Qwen1.5、Qwen2、Qwen2.5シリーズなどがあり、0.5B~110Bまで様々。また専用のビジョン言語モデル(Qwen-VL)、音声モデル(Qwen-Audio)、コードモデル(Qwen-Coder)、推論モデル(QwQ)などが存在する。

適用分野

Qwenは様々な分野で活用可能である。

ソフトウェア開発: コード生成、デバッグ、レビュー、50以上のプログラミング言語をサポート

コンテンツ制作: 長文作成、SEO、ソーシャルメディア、翻訳(201言語)

研究およびデータ分析: 文献レビュー、チャート解釈、科学的推論、医療分析

企業業務: カスタマーサービスチャットボット、文書処理、ナレッジベース質疑応答

ベンチマークテストでQwen 3.5はSWE-Bench Verifiedで76.4点を記録し、GPT-5.2およびClaude Opus 4.5と同等の水準である。

使用方法

オープンソースモデル: Apache 2.0ライセンスで無料使用可能、Ollama、llama.cpp、LM Studioなどでのローカル実行をサポート

APIサービス: アリババクラウドのDashScope APIを通じて呼び出し

無料体験: Qwen Chat公式ウェブサイト(chat.qwen.ai)で対話可能

企業サービス: 全世界29万社以上の企業顧客に提供

0. まず知っておくべきバージョン整理(文書アップデート)

原文はqwen2.5/qwen3/散発的なqwen3.5:4bのみを扱っていたが、2026年6月時点のラインアップは以下のように拡張されている。

世代 リリース 構成 マルチモーダル 対応言語 ライセンス ローカル可否
Qwen3 2025-04 dense 0.6B~32B + MoE 30B-A3B、235B-A22B テキスト 119 Apache-2.0 可 [R2][R7]
Qwen3.5 2026-02 Small 0.8B/2B/4B/9B + 27B / 35B-A3B / 122B-A10B / 397B-A17B ビジョン(ネイティブ) 201 Apache-2.0 可 [R1][R9]
Qwen3.6 2026-04~05 27B(dense) / 35B-A3B(MoE)、コーディング・エージェント強化 ビジョン - Apache-2.0 可 [R11][R12]

注意:

  • 本ガイドはオープンウェイトモデルのみを対象とする。*-Max、*-PlusなどAPI専用モデルはローカルインストールの対象外である。[R7][R12]
  • 2025年7~8月の「2507」リフレッシュで、Qwen3はハイブリッド(トグル)方式からthinking/instruct分離チェックポイントに分かれた。ダウンロード時にどの変種かを確認すること。[R7]

1. インストール方法の選択

方法 特徴 推奨対象
Ollama コマンド一行でインストール/実行、最も簡単 LLM初心者、迅速なテスト
LM Studio GUIベース、数クリックで完了。MLX・GGUF対応 コーディングなしで使いたい方
Hugging Face Transformers Pythonコードで細部まで制御 開発者、カスタマイズ

2. Ollamaのインストール(最も簡単)

2.1 Ollamaのインストール [R8]

Windows

irm https://ollama.com/install.ps1 | iex

または公式サイト(ollama.com)からインストーラーをダウンロード。

macOS

brew install ollama

Linux

curl -fsSL https://ollama.com/install.sh | sh

2.2 実行

ollama serve   # 手動起動(通常はインストール後に自動実行)

2.3 モデルのダウンロードと実行 [R8][R16]

# 現行推奨 - Qwen3系列
ollama run qwen3:8b            # 基本/入門、約5GB
ollama run qwen3:4b            # 軽量
ollama run qwen3:14b           # 約9GB
ollama run qwen3:32b           # dense上位
ollama run qwen3:30b-a3b       # MoE: 30B品質・8B級速度(VRAMは全体分必要)

# Qwen3.5系列(マルチモーダル)
ollama run qwen3.5:9b          # 8GBカード推奨のデフォルト、約6.6GB
ollama run qwen3.5:4b          # 軽量、約3.4GB(ファイル)

# 旧バージョン
ollama run qwen2.5:7b

利用可能なサイズ(例): qwen2.5 0.5/1.5/3/7/14/32/72B、qwen3 0.6~32B + 30B-A3B/235B-A22B、qwen3.5 0.8/2/4/9/27/35/122/397B系列。[R1][R2][R10]

注意:

  • Ollamaのタグにinstructがなくてもchat用モデルである場合が多いが、Qwen3 2507以降はthinking/instruct変種が別々に配布されるため、タグを直接確認すること。(原文の「全てInstruct」という断定は現行基準では不正確) [R7]
  • qwen3.5:4bの「3.4GB」はGGUFファイルサイズであり、実行時のRAMではない。実際にはKVキャッシュとcontextオーバーヘッドを加算する必要がある。[R7][R14]

2.4 独自のGGUFファイルを使用(Modelfile) [R8]

FROM qwen2.5-7b-instruct-q5_0.gguf
PARAMETER temperature 0.7
PARAMETER top_p 0.8
PARAMETER repeat_penalty 1.05
PARAMETER top_k 20

ollama create my-qwen -f Modelfile
ollama run my-qwen

注意: Qwen3.5のようなマルチモーダルGGUFはビジョン(mmproj)ファイル分離の問題でOllamaへの直接インポートが制限される場合がある。この場合はllama.cpp系バックエンドまたはLM Studioを推奨する。(Ollamaライブラリタグで取得する場合は正常に動作する。) [R9]

3. LM Studioのインストール(GUI)

  1. 公式サイトからmacOS/Windows/Linux用インストーラーをダウンロードしてインストール。
  2. アプリを起動 → Cmd+Shift+M(Mac)/Ctrl+Shift+M(PC)でモデルを検索。
  3. 「Qwen」を検索 → ハードウェアに合ったモデルをダウンロード。
  4. Hugging Faceのモデルカードの「Use this model → LM Studio」から直接連携可能。
  5. マルチモーダル/Thinkingトグルはモデルごとのyaml設定が必要な場合があり、CLIでlms import <パス>による手動インポートもサポートされている。[R9]

Apple SiliconではMLXフォーマットに対応したLM Studioを使用すると性能面で大きな利点がある。[R9][R11]

4. Hugging Face Transformers(開発者向け)

4.1 事前準備

pip install transformers torch accelerate
pip install modelscope   # 中国地域からのダウンロードが高速

4.2 ロードと実行

from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "Qwen/Qwen3-30B-A3B"   # またはQwen/Qwen3-8Bなど

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",
    device_map="auto",   # GPU/CPU自動割り当て、不足時はCPUオフロード
)

messages = [{"role": "user", "content": "Qwen、日本語で自己紹介してください。"}]
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
    enable_thinking=True,   # 思考モード(Qwen3以上)
)

outputs = model.generate(
    **tokenizer([text], return_tensors="pt").to(model.device),
    max_new_tokens=200,
)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

enable_thinking=Trueは複雑な推論に有利だが応答が遅くなる。日常会話にはFalseを推奨する。[R2][R8]

インストール前のVRAM適合性チェックのヒント - ダウンロードせずヘッダーのみ読み取ってメモリを推定: [R18]

uvx hf-mem --model-id Qwen/Qwen3-8B --experimental --max-model-len 8192

5. モデル選択ガイド(ハードウェア別・Q4_K_M基準)

VRAM数値はQ4_K_M GGUF基準であり、4Kコンテキストの KVキャッシュとして+12GBを加算すること。VRAM不足時はOllama/llama.cppがシステムRAMに自動オフロードするが、速度が大幅に低下する(1020倍遅いメモリ帯域幅)。[R13][R18]

ハードウェア 推奨モデル 大まかなVRAM/RAM 備考
旧型ノートPC(RAM 4~8GB) qwen3.5:4b / qwen2.5:3b 3~4GB(ファイル) CPU-only可能、低速
一般デスクトップ(RAM 16GB) qwen3:8b / qwen3.5:9b 約5~6.6GB CPU-only可能 [R13][R14]
GPU VRAM 8GB qwen3.5:9b(Q4) / qwen3:7~8b 約5.5~6.6GB RTX 3060/4060級 [R13][R14]
GPU VRAM 12GB qwen3:14b(Q4) 約9~9.5GB Q6_Kの余裕あり [R13][R14]
GPU VRAM 16~24GB qwen3:32b / qwen3.6:27b(約17GB) 17~20GB 24GBでQ4_K_Mが快適 [R12][R14]
GPU VRAM 24GB qwen3.6:35b-a3b(UD-Q4約22GB) 約22GB contextを過剰に設定しないこと [R12][R14]
マルチGPU/サーバー qwen2.5:72b / 235B-A22B / 397B-A17B 数十~数百GB tensor-parallelが必要 [R16][R19]

MoEの落とし穴: 30B-A3B、35B-A3B、80B-A3Bなどはアクティブパラメータが3Bであっても全体のウェイトをVRAMに読み込む必要がある。「アクティブ3B=メモリ3B」ではない。例: Qwen3-Next-80B-A3Bは非量子化時に約160GBのVRAMが必要。[R14][R19]

6. 注意事項とヒント

6.1 ストレージ容量

  • 7B ≈ 5GB、14B ≈ 9GB、27B ≈ 17GB、32B ≈ 20GB、35B-A3B ≈ 22GB(Q4基準)。[R13][R14]
  • Ollamaのデフォルト保存パス: ~/.ollama/models。空き容量を確保すること。[R8]

6.2 量子化(Quantization) [R13][R16][R18]

  • Q4_K_M: 大部分のデフォルト値。VRAM約75%削減、品質損失は最小限。
  • Q5_K_M: ~60%削減、Q4よりやや高品質。
  • Q8_0: 最高品質の量子化。VRAMに余裕がある場合。
  • NVFP4: Blackwell(RTX 5060 Ti/5090)ネイティブ、Q4より効率的。
  • 明示指定の例: ollama run qwen3:8b-q4_K_M
  • 警告: Q2_Kは日本語/中国語/韓国語などCJK出力品質が目に見えて低下する。 CJK作業ではQ4_K_Mを最低ラインとすること。[R13]

6.3 GPU使用

  • NVIDIA: CUDAドライバーが必要。
  • Apple Silicon(M1~M4): 統合メモリが大型モデルに有利。MLXフォーマット+LM Studioを推奨。(例: M3 Max 64GBでqwen3:32bが約22 tok/s) [R13]
  • VRAM不足時はdevice_map="auto"でCPUオフロードされるが、10~20%を超えると体感速度が急落する - より小型のモデルを推奨。[R18]

6.4 日本語での利用

  • Qwen3系列は119言語、Qwen3.5以降は201言語をサポート。日本語性能は優秀で、日本語プロンプトをそのまま使用可能。[R2][R9]

6.5 Thinking Mode(Qwen3以上)

  • CLI: ollama run qwen3 --think / --no-think [R8]
  • API: {"model":"qwen3","think":false,...}または{"thinking":{"budget_tokens":1024}}で推論予算の上限を設定 [R8]
  • プロンプト内での/think、/no_thinkトグルも一部の変種でサポートされている。
  • 推奨: 要約・ドラフトはno-think、コードデバッグ・数学・論理はthink。

6.6 Context/KVキャッシュの注意(原文の不足を補完)

  • Qwen3.5/3.6はネイティブ256K(262,144)コンテキスト、YaRNで~1Mまで拡張可能。[R12][R17]
  • contextを長く設定するほどKVキャッシュがVRAMを大きく消費する。「最小VRAM」表は短・中コンテキスト基準であり、128K~256Kを実際に使う場合は大幅な余裕を確保する必要がある。[R12]

6.7 ネットワーク

  • 初回ダウンロード時はインターネットが必要(数GB~数十GB)。以降は完全オフラインで使用可能。[R8]

6.8 ライセンス

  • Qwen3/3.5/3.6のオープンウェイトはApache-2.0であり、商用利用が可能。(ただし*-Max APIモデルは別途規約がある) [R7]

7. トラブルシューティング

問題 解決方法
「CUDA out of memory」 より小さいモデル、より低い量子化(Q4→Q3)、またはcontextの縮小 [R12][R14]
Ollamaがモデルを見つけられない ollama pull qwen3:8bで明示的にダウンロード [R8]
応答が遅すぎる CPU-onlyなら小型モデル(0.64B)、またはオフロード率を確認(>1020%はGPU不足) [R18]
LM Studioでモデルが表示されない lms import <モデルパス>で手動インポート [R9]
マルチモーダルGGUFがOllamaで壊れる mmproj分離の問題 - llama.cpp/LM Studioを使用 [R9]
ダウンロード前のVRAM適合性確認 uvx hf-mem --model-id <repo> --experimental [R18]

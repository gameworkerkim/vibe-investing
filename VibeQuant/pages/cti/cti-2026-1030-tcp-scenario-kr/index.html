커널 코드로 살펴보는 CVE-2026-98432 익스플로잇 시나리오

발행 2026.10.30 · 주제 Linux-Kernel · CVE-2026-98432 · Use-After-Free · TCP · Detection

수정 전 커널 경로에서 유출과 크기 혼동을 읽고, 탐지 시그널에 연결한다

본 문서는 취약점 메커니즘과 공격 시나리오를 코드 수준에서 분석해 탐지·대응에 연결하는 기술 문서입니다. 익스플로잇 구현 방법(힙 그루밍 레시피, 오프셋, ROP 구성 등)은 의도적으로 다루지 않습니다.

1. 요약

리눅스 IPv4 TCP 핸드셰이크 경로의 UAF(CVE-2026-98432)는 공격자가 원격에서 인증 없이 두 가지 프리미티브를 얻을 수 있게 한다는 점이 핵심이다.

  1. 유출 프리미티브: 해제된 IP 옵션 객체의 내용이 SYNACK 응답에 실려 나감 → 커널 힙 데이터(주소 포함) 노출 → KASLR 무력화 [발표: 48분 소요]
  2. 크기 혼동 프리미티브: optlen 이중 읽기 → 헤더 빌드에서 공격자 통제 크기 사용 → 버퍼 경계 이탈 → 인접 객체 덮어쓰기 → 제어 흐름 탈취 [발표: 추가 5분 후 root 실행]

세부 메커니즘은 아래와 같이 수정 커밋(e3f33b0a1d89)과 수정 전 소스 (부모 커밋 fe4114221364)에서 확인된다. 전체 소유권/수명 분석은 fix-commit-analysis.md 참조.

3. 익스플로잇 단계 개요

[1] 레이스 트리거 준비   옵션 부착 SYN + 핸드셰이크 + 즉시 파괴 + 재전송 반복
[2] 유출 (KASLR 우회)    해제 객체 읽기 → SYNACK 옵션 echo에 커널 주소 노출 (48분)
[3] 손상 (제어 흐름)     동일 UAF 기반 크기 혼동 → 콜백 포인터 덮어쓰기 (5분)
[4] 실행                  커널이 포인터 호출 → root 컨텍스트 셸

4. 시나리오 A — 재전송 SYN vs child 소켓 파괴 (주 시나리오)

4.1 옵션 소유권 이전 (복사 없음) [코드]

tcp_v4_syn_recv_sock() (수정 전 net/ipv4/tcp_ipv4.c:1702):

	inet_opt = rcu_dereference(ireq->ireq_opt);
	RCU_INIT_POINTER(newinet->inet_opt, inet_opt);   /* 참조만 전달 */
	...
	if (inet_opt)
		inet_csk(newsk)->icsk_ext_hdr_len = inet_opt->opt.optlen;
	...
	if (likely(*own_req)) {
		tcp_move_syn(newtp, req);
		ireq->ireq_opt = NULL;                       /* req 쪽 참조만 해제 */
	}

이 시점부터 옵션 객체의 유일한 소유자는 child 소켓이다. IPv6 경로는 여기서 옵션을 복제하므로 이 경로가 없다. [코드/커밋]

4.2 해제 경로 (즉시 kfree) [코드]

/* net/ipv4/af_inet.c:164 (수정 전) — child 소켓 파괴 */
	kfree(rcu_dereference_protected(inet->inet_opt, 1));

/* net/ipv4/tcp_ipv4.c:1213 (수정 전) — request socket 파괴 */
static void tcp_v4_reqsk_destructor(struct request_sock *req)
{
	kfree(rcu_dereference_protected(inet_rsk(req)->ireq_opt, 1));
}

공격자는 핸드셰이크 완료 직후 RST/FIN으로 child를 파괴해 kfree()를 유발할 수 있다. TCP child는 SOCK_RCU_FREE가 아니므로 파괴가 지연되지 않는다. [코드/커밋]

4.3 읽기 경로 (RCU 참조만) [코드]

/* tcp_v4_send_synack() — 재전송 SYN 처리 시 SYNACK 발송 */
	rcu_read_lock();
	err = ip_build_and_send_pkt(skb, sk, ireq->ir_loc_addr,
				    ireq->ir_rmt_addr,
				    rcu_dereference(ireq->ireq_opt),   /* 참조 */
				    tos);
	rcu_read_unlock();

/* ip_build_and_send_pkt() (net/ipv4/ip_output.c:160, 수정 전) */
	skb_push(skb, sizeof(struct iphdr) + (opt ? opt->opt.optlen : 0));  /* 읽기 #1 */
	...
	iph->daddr = (opt && opt->opt.srr ? opt->opt.faddr : daddr);        /* 읽기 #2 */
	...
	if (opt && opt->opt.optlen) {                                       /* 읽기 #3 */
		iph->ihl += opt->opt.optlen >> 2;                              /* 읽기 #4 */
		ip_options_build(skb, &opt->opt, daddr, rt);                   /* 읽기 #5..N */
	}

/* ip_options_build() (net/ipv4/ip_options.c:50, 수정 전) */
	memcpy(&(IPCB(skb)->opt), opt, sizeof(struct ip_options));          /* 구조체 복사 */
	memcpy(iph + sizeof(struct iphdr), opt->__data, opt->optlen);       /* 데이터 복사 */

rcu_read_lock()은 해제 지연을 보장하지 않는다 — 작성자만 지키는 규약이므로 kfree()가 읽기 도중에 실행될 수 있다. [커밋]

4.4 레이스 타이밍

──────────────────────────                ────────────────────────────

      opt->faddr / is_strictroute 읽기                               │

      skb_push(... opt->optlen)                                     │

  • 전제: 079096f103fa 이후 request socket 처리가 리스너 락 없이 수행됨 [커밋]
  • SYNACK 타이머 경로는 안전: timer_delete_sync()가 child 해제 전에 타이머를 정리하므로 공격자는 타이머가 아닌 재전송 SYN 경로를 노린다 [커밋]

4.5 프리미티브 1 — 응답 채널 유출 (KASLR 우회의 기반) [코드+추론]

ip_options_build()는 해제된 opt의 __data[]를 SYNACK의 IP 옵션 영역에 그대로 memcpy한다. 즉 커널 힙 내용이 공격자에게 도착하는 응답 패킷에 실려 나간다. [코드]

  • 해제된 ip_options_rcu 슬랩 객체가 포인터를 포함하는 다른 커널 객체로 재할당되면, 그 포인터 바이트가 SYNACK 옵션 echo에 나타난다. [추론]
  • 공격자는 수신한 SYNACK의 옵션 영역을 자기 SYN에 실어 보낸 옵션과 대조해 "echo되지 않은 추가 바이트"를 골라낸다. [발표: "커널이 추가 바이트를 응답으로 돌려보내게" → 48분 내 주소 확보]
  • 유출은 단일 레이스 승리로 끝나는 것이 아니라 반복 승리마다 일부 바이트씩 축적되는 것으로 보인다. [추론, 발표의 48분 소요와 정합]

4.6 프리미티브 2 — optlen 이중 읽기와 크기 혼동 [코드+추론]

ip_build_and_send_pkt()는 opt->opt.optlen을 두 번 읽는다:

  1. skb_push()의 헤더 공간 크기 계산 (읽기 #1)
  2. iph->ihl += opt->opt.optlen >> 2 + ip_options_build()의 memcpy 크기 (읽기 #4/#5)

해제-재할당 사이에 1과 2의 값이 달라지면(첫 읽기 시 작은 값, 재할당 후 큰 값 등), memcpy가 빌드한 IP 헤더 영역을 벗어나거나 부족하게 복사된다. [추론]

이 크기 혼동이 "버퍼를 넘치게 해 콜백 포인터를 덮어쓴다"는 발표 내용의 코드 수준 근거로 가장 유력하다. 덮어쓰기 대상·그루밍 수열은 미공개이며 본 문서에서 다루지 않는다. [발표+추론]

5. 시나리오 B — request socket migration 경로 [커밋+코드]

net.ipv4.tcp_migrate_req=1 또는 BPF_SK_REUSEPORT_SELECT_OR_MIGRATE 프로그램이 설정된 환경에서는 두 번째 레이스가 가능하다. [커밋]

/* inet_connection_sock.c:913 — 클론 생성: memcpy로 ireq_opt 공유 */
static struct request_sock *inet_reqsk_clone(struct request_sock *req,
					     struct sock *sk) { ... }

/* inet_connection_sock.c:975 — 원본 포인터 정리 */
static void reqsk_migrate_reset(struct request_sock *req)
{
	req->saved_syn = NULL;
#if IS_ENABLED(CONFIG_IPV6)
	inet_rsk(req)->ipv6_opt = NULL;
	inet_rsk(req)->pktopts = NULL;
#else
	inet_rsk(req)->ireq_opt = NULL;
#endif
}
  • 클론과 원본이 같은 ireq_opt를 공유한 상태에서, 원본 req를 참조 중인 다른 CPU가 SYNACK 전송 또는 child 생성을 수행할 때 클론이 파괴되면 UAF가 된다. [커밋]
  • 추가 관찰: CONFIG_IPV6=y 빌드(대부분의 배포판)에서는 reqsk_migrate_reset()이 유니온의 다른 멤버(ipv6_opt, pktopts)만 NULL 처리하므로 ireq_opt가 원본에 남는다. 원본과 클론의 두 destructor가 같은 포인터를 각각 해제하는 double-free 파생 시나리오가 배제되지 않는다. [코드+추론]
  • IPv6 전용 객체(ipv6_opt, CALIPSO)의 동일 마이그레이션 문제는 별도 패치 대상이다. [커밋]

6. KASLR 우회 단계 (개념 수준)

  • 유출 프리미티브(§4.5)로 커널 힙/객체 주소를 확보하면 주소 무작위화가 무력화된다. [발표]
  • 재할당 대상 객체의 선택(어떤 커널 구조체가 ip_options_rcu 슬랩과 크기가 근접한지), 슬랩 상태를 조작하는 그루밍 수열은 공개되지 않았으며, 본 문서는 개념 확인까지가 범위다. [추론/미공개]

7. 제어 흐름 탈취 단계 (개념 수준)

공개 자료는 세 단계만 명시한다. [발표]

  1. 같은 버그(크기 혼동)로 버퍼를 넘치게 한다.
  2. 콜백 포인터를 덮어쓴다 — 포인터는 미리 커널 메모리에 심어 둔 페이로드를 가리킨다. ("페이로드 사전 배치"는 유출 단계에서 확보한 커널 주소 공간 활용을 시사)
  3. 커널이 해당 포인터를 호출하는 순간 공격자가 선택한 셸 명령이 root로 실행된다.

어느 콜백(네트워크 스택·타이머·skb 수명주기 등)인지, 페이로드를 어느 객체에 심는지는 미공개이며, 구현 레벨 기술은 본 문서 범위 밖이다. [미공개]

8. MPTCP 연결고리

  • CVE 레코드와 수정 커밋에는 MPTCP 언급이 없다. [확정]
  • MPTCP와의 연결은 Anthropic 발표문에서만 등장한다. [발표]
  • 즉 "MPTCP 리스너가 없으면 안전하다"는 판정은 현재 근거가 없다. Red Hat도 노출 IPv4 TCP 서비스 전반에서 레이스 트리거가 가능하다는 시각이다. [발표/CTI 리포트]

10. 킬체인 ↔ 탐지 시그널 매핑

단계 관찰 가능 아티팩트 시그널 우리 도구
준비/탐색 옵션 부착 SYN 단발 유입 S1 detector syn_ipopt, Suricata 2026103002~3005, Zeek
레이스 유도 동일 4-tuple 동일 seq 고빈도 재전송 (RTO보다 짧음) S2 detector race_grooming, Suricata 2026103006, Zeek burst
반복 시도 핸드셰이크 완성 직후 RST/폐기 반복, 미수립 다발 S3 Zeek/흐름 로그 (연결 수명 이상치)

탐지의 결정적 창: 유출 단계(48분) 동안의 S1+S2 반복 패턴. 공격자는 레이스를 반복해야 하므로 네트워크 측 시그널이 반드시 남는다. [추론]

11. 패치 효과 (코드 관점)

kfree() → kfree_rcu() 2줄 변경이 두 프리미티브를 구조적으로 제거한다.

  • §4.4 레이스: rcu_read_lock() 구간(§4.3)이 끝날 때까지 해제가 연기되므로 읽기 도중 해제가 불가능해진다. [커밋]
  • §4.5 유출: 해제된 객체를 읽는 경로 자체가 소멸 → echo 채널 폐쇄. [추론]
  • §4.6 크기 혼동: 두 번의 optlen 읽기가 항상 유효한 객체에서 수행됨. [추론]
  • §5 시나리오 B: 두 destructor 모두 RCU 해제로 변경되어 공유 포인터 이중 해제도 같은 grace period 규약에 편입. [커밋]

잔존 리스크: IPv6 CALIPSO(ipv6_opt) 마이그레이션 문제는 별도 패치, EOL 커널 시리즈(4.4~5.4 등)는 업스트림 수정 목록에 없음. [커밋]

12. 공개되지 않은 것 / 분석 한계

  • 익스플로잇 코드, 테스트 커널 버전·구성, 그루밍 수열, 덮어쓰기 대상 콜백 — 모두 미공개. [발표]
  • 비MPTCP 리스너에서의 루트 탈취 가능성 미확정. [CTI 리포트]
  • §4.5/§4.6의 프리미티브 세부 연결은 코드 기반 추론이며, Anthropic의 구현이 다른 경로(예: 시나리오 B)를 사용했을 가능성을 배제하지 않는다.

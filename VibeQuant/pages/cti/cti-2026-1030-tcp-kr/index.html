CVE-2026-98432 리눅스 커널 TCP Use-After-Free 보안 리포트

발행 2026.10.30 · 주제 Linux-Kernel · CVE-2026-98432 · Use-After-Free · TCP · MPTCP · Patch-Gap

인증 없이 원격 루트까지. Ubuntu·RHEL은 아직 수정 커널이 없다

공유 X Facebook LinkedIn

IPv4 핸드셰이크에서 커널은 IP 옵션을 복사하지 않고 참조만 넘긴다. 한 CPU가 새 소켓을 파괴하며 옵션을 해제하는 동안 다른 CPU가 재전송 응답을 만들며 그 옵션을 읽으면, 해제된 메모리를 읽게 된다.

김호광 싸이월드 전 대표 / 2026년 10월 30일

분류: TLP:CLEAR | 문서유형: CTI 리포트 | 작성일: 2026-10-30 심각도: HIGH (실무 기준 CVSS 8.1 이상, MPTCP 노출 서버 9.8) | 신뢰도: A2 | 영향: 리눅스 커널 4.4 이후, IPv4 TCP 리스너

요약

리눅스 커널 IPv4 TCP 핸드셰이크 경로의 Use-After-Free(CVE-2026-98432)는 인증 없이 원격에서 트리거 가능한 결함이며, 2026년 10월 29일 기준 Ubuntu와 RHEL에는 수정 커널이 없다. 종합 위험 등급은 높음(High)으로 판단한다.

  • 원격 루트 실증: Anthropic은 MPTCP 리스너가 있는 서버에서 AI 모델이 작성한 익스플로잇으로 원격 루트 명령 실행에 성공했다고 10월 27일 발표했다.
  • 패치 공백: 업스트림·stable 브랜치는 수정 완료. Debian, Oracle UEK, 일부 SUSE·Amazon Linux만 패키지를 냈고, Ubuntu는 진행 중, Red Hat은 "향후 업데이트로 연기" 상태다. 두 벤더 모두 일정 미공개.
  • 점수 혼선: 커널 CVE 팀 9.8, 벤더 5.9~8.1. 차이는 거의 전부 공격 복잡도(AC) 판단에서 나온다.
  • 실제 악용: 10월 29일 기준 벤더 공지·CVE 레코드·Anthropic 글 어디에도 실제 공격 보고는 없고, CISA KEV에도 없다.
  • 주의: MPTCP 비활성화가 위험을 낮추는지는 어느 공식 문서도 확인하지 않았다. Red Hat은 노출된 TCP 서비스면 레이스 트리거가 가능하다고 본다. MPTCP 비활성화를 확정 완화책으로 간주하면 안 된다.

취약점 개요

결함은 Linux 4.4에서 들어와 약 10년간 존재했고, 수정은 CVE 공개(10월 15일)보다 열흘 앞선 10월 5일에 커널에 반영됐다.

기술 분석

근본 원인은 IP 옵션의 소유권 문제다. 커널이 옵션을 복사하지 않고 참조만 넘기기 때문에, 해제 시점과 사용 시점이 서로 다른 CPU에서 겹칠 수 있다.

  1. 클라이언트가 IPv4 옵션(Record Route 또는 Timestamp)을 담은 SYN을 보낸다. 커널은 이 옵션을 대기 중인 연결 요청(request socket)에 저장한다.
  2. 핸드셰이크가 완료되면 커널은 저장된 IP 옵션을 복사 없이 새 소켓에 넘긴다.
  3. 그 새 소켓이 파괴되면서 옵션 메모리도 해제된다.
  4. 같은 시점에 다른 CPU가 재전송된 연결 요청에 응답하려고 그 옵션을 아직 읽고 있으면, 해제된 메모리를 읽게 된다(Use-After-Free).

IPv6가 안전한 이유: IPv6 경로는 옵션을 복사해서 넘기므로 공유 참조가 생기지 않는다.

수정 방식: 다른 CPU가 옵션 읽기를 마칠 때까지 기다린 뒤에 해제하도록 바꿨다. 즉 해제를 독자(reader)의 종료 이후로 미루는 방식이다.

가능한 결과: 커널 CVE 팀은 인접 커널 메모리의 원격 유출, 커널 메모리 손상, 시스템 충돌을 모두 가능한 결과로 본다.

익스플로잇 분석 (Anthropic 실증)

Anthropic의 공격 체인은 같은 버그 하나로 정보 유출과 코드 실행을 모두 해냈고, 테스트에서 커널 주소 유출까지 48분, 명령 실행까지 추가 5분이 걸렸다.

  1. KASLR 우회: 레이스를 반복 유발해 커널이 추가 바이트를 공격자에게 응답으로 돌려보내게 한다. 응답에 커널 주소가 섞이면 주소 무작위화가 무력화된다.
  2. 제어 흐름 탈취: 같은 버그로 버퍼를 넘치게 해 콜백 포인터를 덮어쓴다. 포인터는 미리 커널 메모리에 심어 둔 페이로드를 가리킨다.
  3. 루트 실행: 커널이 해당 포인터를 호출하는 순간 공격자가 고른 셸 명령이 root로 실행된다.

운영상 핵심 함의: 레이스에서 지면 해당 연결 시도만 실패하고 시스템은 죽지 않는다. 공격자는 탐지되지 않는 한 무제한 재시도가 가능하다. "레이스가 어렵다"는 벤더 논리를 약화시키는 지점이다.

공개되지 않은 것: 익스플로잇 코드, 테스트한 커널 버전, 구성 정보. Claude는 "초기 프롬프팅" 이후 익스플로잇을 작성했다고만 밝혔다. MPTCP 리스너가 없는 서버도 같은 방식으로 장악 가능한지는 발표문에 없다.

CVSS 점수 논란

여파 분석

이번 건의 실질적 위험은 버그 자체보다 "공개된 원격 루트 실증 + 최대 배포판의 무기한 패치 공백"의 조합에서 나온다.

1. 패치 공백(Patch Gap)이 공격 창을 연다. 업스트림 수정 커밋은 10월 5일부터 공개돼 있다. 공격자는 커밋 diff로 버그 위치를 특정할 수 있고, Anthropic이 공격 체인 구조까지 공개했다. 반면 Ubuntu·RHEL 사용자는 받을 패키지가 없다. 이른바 n-day 익스플로잇이 가장 활발해지는 구간이다.

2. AI가 익스플로잇 개발 비용을 낮췄다. 레이스 컨디션 기반 커널 원격 익스플로잇은 전통적으로 숙련자 몇 주 단위의 작업이었다. AI 모델이 이를 만들었다는 사실은 "이론상 가능, 실전은 어려움"이라는 평가 관행 자체를 흔든다. 공격자 측도 유사 도구를 쓸 수 있다고 가정해야 한다.

3. 점수 혼선이 대응 우선순위를 흐린다. 같은 CVE가 스캐너·벤더 포털에 따라 5.9~9.8로 표시된다. 점수 임계값으로 패치 SLA를 돌리는 조직은 이 건을 "Moderate, 다음 정기 패치"로 분류할 위험이 있다.

4. 노출 범위 판정이 불확실하다. 루트 실증은 MPTCP 리스너 대상이지만, 레이스 트리거 자체는 노출된 IPv4 TCP 서비스 전반에서 가능하다는 것이 Red Hat의 시각이다. MPTCP가 없다는 이유로 안전하다고 단정할 근거는 현재 없다.

5. 클라우드·IDC 운영자에 파급이 크다. 인터넷에 직접 노출된 IPv4 리스너가 많은 GPU·호스팅 인프라, 컨테이너 호스트(커널 공유)에서 한 번의 침해가 다수 테넌트로 번질 수 있다.

대응 권고

수정 패키지가 있는 곳은 즉시 설치·재부팅하고, Ubuntu·RHEL은 노출 축소와 탐지로 공백을 버티는 것이 현실적 전략이다.

즉시 (24~72시간)

  • 자산 인벤토리: 인터넷 노출 IPv4 TCP 리스너가 있는 리눅스 호스트와 커널 버전(uname -r) 목록화
  • Debian, Oracle UEK, SUSE Micro 6.2/Leap 16.0, Amazon Linux 2023(kernel6.18·6.12) → 수정 패키지 설치 후 재부팅
  • 자체 빌드 커널 → 수정이 포함된 최신 stable로 갱신 (커널 팀은 개별 패치 cherry-pick을 지원하지 않음)
  • MPTCP 사용 여부 확인: sysctl net.mptcp.enabled, ss -Mltn으로 MPTCP 리스너 존재 확인 → MPTCP 리스너가 있는 서버를 최우선 그룹으로 분류
  • 내부 위험 점수를 벤더 5.9가 아닌 8.1 이상으로 수동 지정해 패치 SLA에서 누락되지 않게 함

단기 (패치 공백 기간)

  • 불필요한 IPv4 공개 리스너 제거, 관리 포트는 VPN·허용 IP 뒤로 이동
  • 서비스상 필요 없으면 MPTCP 비활성화(net.mptcp.enabled=0) — 공격 표면 축소 목적의 보조 조치이며 공식 검증된 완화책은 아님
  • 경계 장비에서 Record Route·Timestamp 옵션이 붙은 IPv4 SYN 차단 검토 — 커널 팀 시나리오상 공격 전제 조건이지만, 효과는 어느 벤더도 확인하지 않았으므로 스테이징에서 영향 검증 후 적용
  • IPv6 전용 노출이 가능한 서비스는 IPv6로 전환 검토 (IPv6 경로는 비영향)

탐지·모니터링

  • IP 옵션이 붙은 SYN의 반복 유입, 동일 출발지의 비정상적 SYN 재전송 패턴 탐지 룰 추가
  • 커널 oops·panic, KASAN 경고 로그를 SIEM으로 수집 (레이스 실패는 대체로 조용하지만 충돌 흔적이 남을 수 있음)
  • Ubuntu CVE 페이지, Red Hat CVE 페이지, CISA KEV 등재 여부 매일 확인
  • Ubuntu Livepatch·RHEL kpatch 형태의 무재부팅 패치 제공 여부 추적

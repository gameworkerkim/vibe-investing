# Leaf — 기능 명세서 (Feature Specification)

> 프로젝트: Leaf (모바일 웹 기반 화보집 뷰어 서비스)
> 버전: v0.1 (기획 초안)
> 플랫폼: Cloudflare 무료 티어 (Pages + Workers + R2 + D1)
> 관련 문서: [`02-이미지보호-기술검증.md`](./02-이미지보호-기술검증.md)

---

## 1. 개요

모바일 브라우저(Chrome / iOS Safari / Android Chrome)에서 화보집을 열람할 수 있는 웹 서비스.
이미지 무단 복사·캡처를 어렵게 하고, 유출 시 추적이 가능하도록 워터마크를 적용한다.
콘텐츠는 **무료 구간 / 유료 구간**으로 나뉘며, 유료는 **계좌 이체(입금 확인)** 방식으로 해제한다.

### 1.1 핵심 원칙

1. **로그인 없이는 원본 이미지 접근 불가** — 원본은 R2(private)에 두고, 인증된 사용자만 Workers를 통해 접근.
2. **"캡처를 막는 것"이 아니라 "캡처를 무의미·추적 가능하게"** — OS 레벨 캡처는 차단 불가(검증 보고서 참조).
3. **XSS에 안전한 구조** — 사용자 입력을 HTML로 렌더하지 않고, 정책(CSP) 적용.
4. **오직 Cloudflare 무료 티어** — 유료 기능(예: Workers Paid, Cloudflare Images) 사용 금지.

|---|---|

| 관리자 (Admin) | 콘텐츠·사용자·결제·보안을 관리하는 운영자 |

## 4. 화면 구성

### 4.1 메인 — 전체 리스트
- 노출 항목: 썸네일, 화보집 제목, 작가/설명(간략), 가격(무료/유료), 페이지 수
- 필터/탭: **전체 | 무료 | 유료**
- 검색: 제목 검색 (게시판형)
- 썸네일은 저해상도 + 워터마크 버전 사용 (원본 노출 금지)
- 정렬: 최신순 / 인기순(조회수) / 가격순

### 4.2 화보집 상세
- 커버 이미지, 상세 설명, 미리보기(무료 페이지 일부)
- 가격 정보, 구매(입금) 방법 안내
- 유료 잠금 표시 (자물쇠 아이콘, "결제 필요")
- "내 앨범에 담기 / 구매하기" 버튼

### 4.3 뷰어 (웹뷰, 핵심)
- 좌우 스와이프 / 버튼 / 화살표 키로 페이지 이동
- 페이지 인디케이터 (n / N)
- **무료 페이지**: 로그인 없이 열람 가능
- **유료 페이지**: 미해제 시 잠금 화면 (썸네일만 흐림 표시)
- 이미지 보호 동작 (상세: `02-이미지보호-기술검증.md`, 유출 검증: `04-유출검증-가이드.md`)
  - 서버 프리-컴포지트 워터마크 (업로드 시 공통 문구)
  - **신원 시각 WM**: `api/viewer-identity`(email·sessionId·IP) → CSS 오버레이 + canvas 픽셀 베이크
  - **비가시 LSB WM**: `LEAFWM1` 페이로드 (추출: `scripts/extract-invisible-wm.html`)
  - 우클릭·인쇄 단축키 차단, 캡처 징후(visibilitychange 등) → D1 보고
  - 하단 네비: safe-area 고정 바 (이전/다음)
- **뷰어 진입 시**: 신원 API로 세션 쿠키 발급 → 이미지 서빙 (로그인/결제 게이트는 P3+)

### 4.4 로그인 / 회원가입
- 가입 필드: **이메일, 패스워드, 전화번호** (전화번호는 입금 확인 안내용·2차 인증용)
- 검증: 이메일 형식, 패스워드 최소 8자 이상, 전화번호 형식 (국가번호)
- 세션: D1 `sessions` 테이블 (HttpOnly + Secure 쿠키)
- 로그아웃, 회원 탈퇴

### 4.5 내 앨범
- 구매(입금 확인 완료)한 화보집 목록
- 다시 열람하기, 구매 내역(입금 상태), 영수증/확인 번호 조회

### 4.6 관리자 (admin)
- 대시보드: 화보집·사용자·결제·보안 알림 요약
- 콘텐츠 관리: 화보집 등록/수정/삭제, 이미지 업로드, 무료/유료 페이지 지정, 가격 설정
- 사용자 관리: 목록·검색·강제 정지·권한 부여
- 결제 관리: 입금 신청 목록 → **입금 확인 처리** → 열람 권한 부여
- 보안: 관리자 IP 화이트리스트, 2FA(TOTP), 캡처 알림 로그, 접속 로그

## 5. 콘텐츠 & 열람 규칙

### 5.1 화보집 모델

| 필드 | 설명 |
|---|---|
| id | PK |
| title | 제목 |
| description | 소개글 (Markdown 금지, HTML 이스케이프 필수) |
| cover_image | 커버 (저해상도 워터마크 버전) |
| price_krw | 가격 (0 = 무료) |
| status | draft / published / hidden |
| free_page_count | 무료로 공개할 페이지 수 |
| total_page_count | 총 페이지 수 |
| created_at / updated_at | 생성/수정 시각 |
| view_count | 조회수 |

### 5.2 페이지(이미지) 모델
각 페이지는 R2에 두 벌로 저장:

| 저장본 | 용도 | 접근 |
|---|---|---|
| **원본 (high-res, private)** | 보관·관리용. 절대 서빙하지 않음 | 관리자/내부 전용 |
| **웹뷰 (watermarked, private)** | 실제 열람용. 업로드 시 미리 워터마크 합성 | 인증된 사용자만 Workers 경유 서빙 |

> `웹뷰` 이미지는 **업로드 시점에 워터마크를 미리 입혀(프리-컴포지트) R2에 저장**한다.
> Workers 무료 티어의 **요청당 CPU 10ms 제한** 때문에 요청 시점에 sharp로 실시간 합성하면
> CPU 한도 초과로 실패한다 (로컬 측정 ~80~200ms, 검증 보고서 §5.6). 이것이 핵심 아키텍처 결정.

### 5.3 열람 권한 규칙

```
GET /api/albums/:albumId/pages/:pageNo
1. 페이지가 무료 페이지(순번 <= free_page_count)인가?
   └─ 무료: 게스트 포함 열람 허용
2. 유료인 경우 로그인 세션 확인
   └─ 미로그인: 401 (로그인/가입 유도)
   └─ 로그인 상태 + 미결제: 403 (결제 유도)
   └─ 로그인 상태 + 결제 완료: 열람 허용
3. (선택) 계정 정지 여부 확인
```

- 무료 페이지는 "이 화보집의 앞 N장"으로 정의 (운영 단순화, 기본값 2~3장)
- 썸네일·커버는 별도 저해상도 버전으로 열람 권한과 무관하게(제한적으로) 접근 허용하되,
  **원본과 동일 해상도 금지**

## 6. 결제 — 계좌 이체

### 6.1 계좌번호 노출
- 화보집 상세 / 결제 버튼 클릭 시 **계좌번호 + 입금 금액 + 입금자명 기재 안내** 표시
- 계좌 정보는 관리자가 콘텐츠 설정에서 지정 (여러 계좌 등록 가능)
- 입금자명(실명) 확인용으로 회원의 실명/전화번호 필수 요구

### 6.2 입금 확인 버튼
- 사용자: "입금했어요" 버튼 → 신청서 제출
  - 항목: 화보집 id, 입금자명, 입금 금액, 예상 입금일, 계좌 선택
- 관리자: 신청 목록에서 계좌 잔액/입금 내역과 대조 → **확인 처리** (또는 거절)
- 확인 완료 시 해당 사용자에게 **영구 열람 권한 부여** (D1 `purchases` 테이블 INSERT)
- 사용자에게 상태 변경 알림 (입금 확인 완료 / 금액 불일치)

### 6.3 상태 머신
```
신청(대기) → 확인됨 → (열람 권한 부여)
신청(대기) → 거절됨 (사유)
```
- 금액 불일치/입금자명 불일치 시 거절 가능. 재신청 가능.

### 6.4 안티 어뷰즈
- 한 사용자의 신청 횟수 제한 (일일 N회, D1 기반 rate limit)
- 입금 확인은 **수동**(관리자) → 무료 티어에서 자동화 금지 (자동 조회는 유료 부가기능)

## 7. 관리자 기능 상세

### 7.1 콘텐츠 관리
- 화보집 CRUD + 이미지 업로드(다중)
- 업로드 파이프라인:
  1. 원본 업로드 → R2 `origin/{albumId}/{page}.jpg` (private)
  2. Workers/도구로 **웹뷰용 리사이즈(최대 폭 1600px) + 워터마크 합성** → R2 `webview/{albumId}/{page}.jpg`
  3. 썸네일(300px) 생성 → R2 `thumb/...`
  4. D1에 메타데이터 기록
- 무료/유료 페이지 수, 가격 설정
- 게시/비공개/숨김 상태 관리

### 7.2 사용자 관리
- 사용자 목록·검색, 가입일, 구매 이력
- 계정 정지/해제
- 패스워드 초기화 (관리자 대행은 토큰 발급 방식)

### 7.3 결제 관리
- 입금 신청 목록 (상태별 필터)
- **입금 확인 / 거절** 처리
- 확인 시 사용자 열람 권한 자동 부여

### 7.4 보안 설정
- **관리자 IP 화이트리스트**: 지정 IP에서만 admin 도메인/경로 접근 허용
- **2FA(TOTP)**: 관리자 로그인 시 OTP 필수 (가입 시 QR 제공, `otpauth://` URI)
- 세션 만료 정책 (예: 24h, IP 변경 감지 시 재인증)
- 보안 로그: 접속 IP·시간·민감 동작 기록

### 7.5 로그/모니터링
- 캡처 알림 로그 (상세: 검증 보고서 §5.3)
- 조회수/접속 로그
- Slack/Discord 웹훅 알림 (무료 티어에서 허용 범위)

## 9. 플랫폼 & 아키텍처

### 9.1 Cloudflare 무료 티어 구성 (무료 티어 한도 내)

| 구성요소 | 역할 | 무료 티어 한도 |
|---|---|---|
| **Pages (frontend)** | 정적 프론트 서빙 (vanilla TS 단일 번들) | 정적 요청 무제한, 빌드 500회/월 |
| **Pages Functions / Worker (API)** | 인증·결제·콘텐츠 API, 이미지 게이트 | 100,000 req/일, **CPU 10ms/요청** |
| **R2 (이미지)** | 원본·웹뷰·썸네일 저장 (private bucket) | 10GB, Class B(읽기) 1,000만/월 |
| **D1 (DB)** | 사용자·화보집·구매·결제·로그·**세션·Rate limit** | 행 읽기 500만/일, 쓰기 10만/일, 5GB |

> **세션·Rate limit도 D1로 통합** — 외부 의존성(Upstash) 없음.
> D1 쓰기 한도(10만/일)는 요청마다 만료 연장·카운트 증가를 감당할 만큼 넉넉함.
> KV는 쓰기 한도(1,000/일)가 낮아 메인 데이터로 부적합 → 필요 시 캐시 용도 한정.

### 9.2 배포 구조

```
Browser ── Cloudflare CDN ──┬─ Pages: 정적 프론트 (CSS/JS/HTML)
                            ├─ Pages Functions(/api/*): API
                            ├─ Worker(image): 이미지 게이트 (별도 Worker 권장)
                            └─ (원본) R2 private
Sessions/Rate limit ── D1 (동일 오리진)
```

- 프론트 + API 동일 오리진 (Pages Functions) → 쿠키 SameSite 편리
- 이미지 게이트는 별도 Worker로 분리 가능 (CPU 예산 격리, 무료 티어 재사용)

### 9.3 이미지 접근 제어 흐름

```
1. 뷰어에서 GET /api/albums/{id}/pages/{no}
2. Workers: 세션 쿠키 → D1 `sessions` 조회 (유효성·만료 확인)
3. 권한 규칙(§5.3) 평가 → 무료/결제 확인
4. 통과 시 R2에서 웹뷰 이미지 GET (단순 읽기, CPU 가벼움)
5. 응답:
   - Cache-Control: private, max-age=… (권한 변동 시 짧게) 또는 no-store
   - ETag / If-None-Match (캐시 효율)
6. 실패 시 401/403 JSON
```

```sql
users(

purchases(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id),

login_logs(id, user_id, ip, user_agent, result, created_at);

sessions(
  sid TEXT PRIMARY KEY,                -- 랜덤 세션 토큰 (쿠키 값)

CREATE INDEX idx_sessions_user ON sessions(user_id);

rate_limits(
  key TEXT NOT NULL,                   -- e.g. 'login:1.2.3.4' | 'payment:user:5'
```

### 9.6 세션 & Rate limit (D1)

**세션** — D1 `sessions` 테이블로 Redis 역할 대체 (TTL 수동 관리).

```
쿠키: sid (HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=7d)

[요청마다] SELECT user_id, role, expires_at FROM sessions WHERE sid = ?1
           └─ 만료 확인 (expires_at > now)
[활동 시]  UPDATE sessions SET expires_at = datetime('now','+7 days') WHERE sid = ?1
           └─ 조회·갱신은 1읽기+1쓰기 = D1 쓰기 한도(10만/일) 여유
[로그아웃/정지] DELETE FROM sessions WHERE sid = ?1 | user_id = ?1
[만료 청소]  크론(일1회) 또는 읽기 시점 지연 DELETE (expires_at < now)
```

**Rate limit** — D1 `rate_limits` 테이블 (Redis INCR 대체).

```
[1] SELECT count FROM rate_limits WHERE key=?1 AND window_start=?2
[2] 없으면  INSERT (count=1) / 있으면 UPDATE count = count+1
    ─ 동시 요청 경합 대비 UPSERT(ON CONFLICT) 사용
[3] count > 한도 → 429 응답
```

**주의사항**
- Redis처럼 자동 만료가 없음 → 만료 컬럼 검사 + 주기 청소 필수
- rate limit 증가가 D1 쓰기를 소모 → 로그인/가입/입금 신청 등 **민감 엔드포인트에만** 적용
- 조회수 등 고빈도 읽기는 D1 대신 **Cache API + 엣지 캐시**로 분리 (한도 절약)
- Redis의 원자 INCR보다 경합이 느슨하므로 트랜잭션/UPSERT로 보완

## 10. 보안 요구사항

### 10.1 XSS 방어 (필수)
1. **React·vanilla 모두 사용자 입력을 `textContent`로만 렌더** (HTML 삽입 금지)
2. CSP 헤더: `default-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self' 'unsafe-inline'` (인라인 스크립트 금지)
3. HTTP 헤더: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` 제한
4. 모든 API 응답 `Content-Type: application/json` (HTML 스니핑 방지)
5. 쿠키: `HttpOnly` (JS 접근 차단), `Secure`
6. 파일 업로드: 확장자+매직바이트 검증, R2 키는 서버 생성 (사용자 입력 비사용)
7. DB: Prepared Statement 필수 (SQL Injection 방지)

### 10.2 CSRF 방어
- 세션 쿠키 `SameSite=Lax` + 민감 동작(POST)에 CSRF 토큰 또는 `Origin/Referer` 검증

### 10.3 관리자 보안
- **IP 화이트리스트**: 관리자 경로는 지정 IP만 접근 (Cloudflare Rules/WAF 또는 Worker에서 확인)
- **2FA(TOTP)**: 관리자 로그인 필수 OTP
- 관리자 API에 별도 세션 강도 (짧은 TTL, IP 바인딩)

### 10.4 인증/세션
- 패스워드 해시: **argon2id 또는 bcrypt** (salt 자동)
- Rate limit: 로그인/가입/입금 신청 시 D1 `rate_limits` 기반 (예: 분당 5회)
- 계정 정지 시 세션 즉시 무효화

## 11. 무료 티어 한도 & 운영 방안

| 리소스 | 예상 사용량 | 대응 |
|---|---|---|
| Workers CPU 10ms | 이미지 게이트는 R2 읽기만 → 수 ms 이내 | 리사이즈·워터마크는 업로드 시 사전 처리 |
| D1 읽기 500만/일 | 페이지별 쿼리는 인덱스화로 최소화 | 무료 페이지 목록·메타는 CDN 캐시 |
| D1 쓰기 10만/일 | 세션 갱신·rate limit 증가 | 민감 엔드포인트에만 rate limit, 세션 만료 연장은 짧은 주기 |
| R2 Class B 1,000만/월 | 열람 1회 = 1 GET | 이미지에 짧은 max-age 캐시로 반복 요청 절감 |
| Workers 요청 100,000/일 | 이미지 1장 = 1요청 | 대역폭 초과 시 Workers Paid(월 $5)로 단계 확장 |

**수익 발생 시**: Workers Paid(월 $5) 업그레이드로 CPU 30만 ms/월, 요청 1,000만/월 확보.
이 시점에 "온더플라이 유저별 워터마크"를 도입해 검증 보고서 §8의 권장 방식을 전환 가능.

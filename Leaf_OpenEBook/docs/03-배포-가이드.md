# Leaf — 배포 가이드 (vibequant.cc/Leaf)

> 현재 상태: **MVP 배포 완료** — https://vibequant.cc/Leaf/
> (기존 vibequant-web Pages 사이트는 무영향. `/Leaf*` 경로만 Worker가 처리)

## 구성

```
vibequant.cc/Leaf* → Worker "leaf" (무료 티어)
├─ GET  /Leaf/                    → 뷰어 (ASSETS: public/index.html)
├─ GET  /Leaf/api/viewer-identity → 세션·IP·email (시각/비가시 WM용)
├─ GET  /Leaf/api/albums/:id/meta → 페이지 수 (R2 list 집계)
├─ GET  /Leaf/api/albums/:id/pages/:n → 워터마크 이미지 (R2, 인증 게이트 없음=MVP)
├─ POST /Leaf/api/capture-alert   → 캡처 징후 D1 기록
└─ GET  /Leaf/api/capture-log     → 로그 조회 (MVP: 인증 없음)
```

유출 이미지 LSB 추출·시각 WM 판독: [`04-유출검증-가이드.md`](./04-유출검증-가이드.md)  
추출기: `scripts/extract-invisible-wm.html` (로컬에서 파일 열기)
| 리소스 | 이름 | 용도 |
|---|---|---|
| Worker | `leaf` | 라우트 `vibequant.cc/Leaf*` |
| R2 | `leaf-images` | `images/{albumId}/{pageNo}.jpg` (업로드 시 워터마크 사전 합성) |
| D1 | `leaf-db` | `capture_alerts` 테이블 |

## 새 화보집 이미지 올리기

```bash
# 1) 원본 이미지 폴더 준비 (jpg/png/webp, 페이지 순서대로 파일명 정렬)
#    예: ./photobook/01.jpg, 02.jpg ...

# 2) 리사이즈(≤1600px) + 워터마크 합성 + R2 업로드 (album id 지정)
cd Leaf_OpenEBook/scripts
node prepare-and-upload.js --album 1 --source ./photobook --watermark "Leaf | (원하는 문구)"

#   --album 2 로 새 화보집을 만들면 /api/albums/2/meta 가 자동 인식
#   (뷰어의 ALBUM_ID = worker/public/index.html 최상단 상수, 화보집 전환 UI는 P4 예정)
```

업로드만 하면 페이지 수는 **R2에서 자동 집계**되므로 Worker 재배포가 필요 없습니다.

## 코드 변경 배포

```bash
cd Leaf_OpenEBook/worker
npm install
npx wrangler deploy        # 빌드+업로드+라우트 적용 (~5초)
```

## 참고 (의도한 설계 제약)

- **워터마크는 업로드 시 사전 합성** — Workers 무료 티어 CPU 10ms 제한 때문에
  요청 시점 sharp 합성은 불가능 (검증: `docs/02-이미지보호-기술검증.md` §4.5)
- **MVP: 인증·결제 게이트 없음** — `/api/albums/:id/pages/:n`은 로그인 없이 열림.
  로그인/유료 해제는 기능명세 P3~P6 단계에서 `pageHandler`에 게이트 추가
- **캡처 알림은 "징후 추정"** — 오탐 가능. 로그 축적용 (기능명세 §8)
- **wrangler R2 명령은 `--remote` 필수** — wrangler 4.x는 R2 명령이 기본 로컬 모드

## 로컬 개발

```bash
cd Leaf_OpenEBook/worker
npx wrangler dev            # http://localhost:8787/Leaf/ (로컬 R2/D1 시뮬레이션)
npx wrangler d1 migrations apply leaf-db --local
```

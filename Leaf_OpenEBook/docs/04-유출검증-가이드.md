## 1. 보호 계층 (현재 배포)

| 계층 | 무엇이 남는가 | OS 스크린샷에 유효? | 추출 방법 |
|---|---|---|---|
| **A. 서버 프리-컴포지트 (변형)** | 페이지당 변형 16종, 격자 오프셋이 서로 다름 + 우하단 `v{n}` 태그 | ✅ (주력) | 육안(태그·오프셋) → 서버 조회 |
| **B. 시각적 신원 WM** | `email \| sessionId(8)` — CSS 오버레이 + **canvas 픽셀 베이크** (행별 시프트) | ✅ (보조) | 육안 / 확대 |
| **C. 비가시 LSB (`LEAFWM1`)** | JSON: sessionId, email, album, page, ts | ❌ JPEG 재압축·리사이즈·크롭 시 **100% 소실** | 추출기 HTML |
| **D. 캡처 징후 로그** | D1 `capture_alerts` (IP, UA, sid) | n/a (서버 로그) | `GET /Leaf/api/capture-log` (토큰) |
| **E. 세션 추적** | D1 `sessions` (sessionId→IP) · `watermark_assignments` (session→변형) | n/a (서버 로그) | D1 조회 |

> OS 스크린샷은 **막을 수 없다**. 추적의 1차 수단은 **A(서버 변형 → 세션 조회)** 와
> **B(시각적 신원 문자열)** 이다. IP는 시각 WM에서 제거되어 서버(D1)에만 보관한다.
> **C(LSB)는 PNG 무손실 저장에만 유효** — JPEG q=100, 리사이즈, 크롭에서 전부 소실(실측).
> **보조 수단으로만 취급.**

## 2. 신원 데이터 출처

뷰어 로드 시 `GET /Leaf/api/viewer-identity` 호출:

```json
{
  "sessionId": "f7a1556f918aa94c1c08f4e5308dae67",
  "ip": "61.74.87.185",
  "email": "guest@leaf.local",
  "label": "Leaf | guest@leaf.local | f7a1556f | 무단전재 금지",
  "auth": false
}
```

| 필드 | 의미 | 비고 |
|---|---|---|
| `sessionId` | `leaf_sid` 쿠키 (32 hex, 30일) | 동일 브라우저 재방문 시 유지 |
| `ip` | `CF-Connecting-IP` | **표시 WM에는 미표기**, D1 `sessions`에만 보관 |
| `email` | 로그인 전 `guest@leaf.local` | P3 이후 실제 계정 이메일 |
| `auth` | 로그인 여부 | MVP는 항상 `false` |

화면 상단 칩·대각선 워터마크·canvas에 `email \| sid(8)`이 반복 표시된다. IP는 화면에 노출하지 않는다.

## 3. 절차 A — 시각적 워터마크로 유출자 확인 (권장)

1. 유출된 이미지(스크린샷·재업로드본)를 확보한다.
2. 사진을 **확대**해 대각선 반투명 텍스트를 읽는다.
3. 형식 예:
   ```
   Leaf | guest@leaf.local | f7a1556f | 무단전재 금지
   ```
4. `sessionId` 앞 8자리(`f7a1556f`)로 열람자를 좁힌다.
5. (선택) 캡처 로그와 교차 확인(관리자 토큰 필요):
   ```bash
   curl -sS -H "Authorization: Bearer <LEAF_ADMIN_TOKEN>" "https://vibequant.cc/Leaf/api/capture-log"
   ```
   `detail`에 `sid=…`가 포함된다.

**한계**: 고의로 워터마크 영역을 크롭·블러하면 식별이 어려워질 수 있다. 텍스트는 이미지 전체에 타일링되어 있다.

## 4. 절차 B — 비가시 LSB 워터마크 추출

페이로드 매직: ASCII `LEAFWM1` + 4바이트 big-endian 길이 + UTF-8 JSON.
삽입 위치: 픽셀 **Blue 채널 LSB** (좌상단부터 순차).

### 4.1 추출기 사용

```bash
# 로컬에서 추출기 열기 (서버 불필요)
open Leaf_OpenEBook/scripts/extract-invisible-wm.html
# 또는 브라우저에서 해당 파일을 연다
```

1. 유출 이미지 파일을 선택한다 (PNG 권장; JPEG는 압축으로 실패할 수 있음).
2. 성공 시 JSON 예:
   ```json
   {
     "v": 1,
     "sid": "f7a1556f918aa94c1c08f4e5308dae67",
     "email": "guest@leaf.local",
     "album": 1,
     "page": 7,
     "ts": "2026-08-01T13:29:00.000Z"
   }
   ```
3. 실패 메시지 `LEAFWM1 페이로드를 찾지 못했습니다` → 재압축/크롭으로 LSB 손상. **절차 A**로 전환.

### 4.2 자체 검증 (개발자)

뷰어에서 canvas가 표시된 상태라면 DevTools에서:

```js
// 현재 표시 canvas의 LSB 추출 (뷰어에 노출된 헬퍼)
const c = document.getElementById('photo-canvas');
const ctx = c.getContext('2d');
const id = ctx.getImageData(0, 0, c.width, c.height);
console.log(window.__LEAF_EXTRACT_WM(id));
```

또는 canvas를 PNG로 저장한 뒤 추출기에 넣으면 거의 항상 성공한다.

### 4.3 LSB가 깨지는 경우

| 원인 | 결과 |
|---|---|
| iOS/Android OS 스크린샷 → JPEG | **항상 실패** (실측: JPEG q=100조차 소실) |
| SNS 재업로드 (추가 압축) | 실패 |
| 리사이즈·크롭 | 실패 또는 부분 손상 |
| **canvas → PNG 무손실 저장** | **유일하게 성공** |

## 5. 절차 C — 캡처 징후 로그

우클릭·인쇄 시도 등이 `POST /Leaf/api/capture-alert`로 기록된다 (서버 신뢰소스: sid는 쿠키에서, detail은 allowlist).

```bash
curl -sS -H "Authorization: Bearer <LEAF_ADMIN_TOKEN>" "https://vibequant.cc/Leaf/api/capture-log"
```

| 컬럼 | 용도 |
|---|---|
| `ip` | CF IP (서버 기록) |
| `detail` | 이벤트 + `sid=` (서버 유래) |
| `page_no` / `album_id` | 열람 위치 |
| `user_agent` | 기기 |
| `created_at` | 시각 |

> 오탐 가능. **확정 증거**가 아니라 시각 WM·서버 변형과 교차 확인할 보조 자료.

## 5-2. 절차 D — 서버 변형·세션 역추적 (운영자, 권장)

> 로드맵 2단계: 페이지당 **16종 변형**을 세션에 결정적으로 배정. OS 스크린샷 재압축에도 변형은 유지되므로 최상위 추적 수단.

1. 유출 이미지의 **우하단 변형 태그** `v{n}`(0~15)를 확인한다.
2. D1에서 해당 페이지·변형을 받은 세션 조회:
   ```sql
   SELECT session_id, album_id, page_no, variant FROM watermark_assignments
   WHERE album_id = 1 AND page_no = 7 AND variant = 3;
   -- → 후보 세션 (한 페이지로는 1/16 해상도, 여러 페이지 교차 시 급격히 좁혀짐)
   ```
3. 세션→IP 연결 (IP는 화면에 없음, 서버 전용):
   ```sql
   SELECT session_id, ip, user_agent, first_seen, last_seen FROM sessions WHERE session_id = '<후보>';
   ```
4. 캡처 로그·시각 WM과 교차 확인 후 제재.

**장점**: JPEG 재압축·리사이즈·OS 스크린샷에서도 유지 (LSB와 달리). 로그인(P3) 후엔 변형 수를 늘려 정확도를 높일 수 있음.

## 6. 체크리스트 (운영)

- [ ] 유출본에서 대각선 텍스트(email / sid 8자) 판독
- [ ] 유출본의 서버 변형 태그 `v{n}` 확인 → `watermark_assignments` 조회
- [ ] (가능하면) LSB 추출기로 전체 sessionId·page·ts 확인 (PNG 무손실 한정)
- [ ] `capture-log`·`sessions`에서 동일 sid·IP 시간대 교차 조회
- [ ] 로그인 도입(P3) 후: email이 `guest@…`가 아니면 계정 제재 후보

## 7. 로컬에서 보호 기능 스모크 테스트

```bash
cd Leaf_OpenEBook/worker
npx wrangler dev --remote
# http://localhost:8787/Leaf/
```

1. 페이지 로드 → 상단 칩에 `Leaf | guest@… | <sid>` 표시
2. 화보에 동일 문자열 대각선 워터마크 확인
3. DevTools → `#photo-canvas` 표시 여부 (img 대신 canvas)
4. `__LEAF_EXTRACT_WM`로 LSB JSON 확인
5. `이전`/`다음`이 화면 하단 safe-area 위에 정렬되는지 확인

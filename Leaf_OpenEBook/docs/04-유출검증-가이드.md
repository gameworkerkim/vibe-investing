# Leaf — 유출 검증 가이드

> 목적: 화보가 유출됐을 때 **누가 열람했는지** 확인하는 절차.
> 관련: [`02-이미지보호-기술검증.md`](./02-이미지보호-기술검증.md) §11 · 추출기 `scripts/extract-invisible-wm.html`
> 라이브: https://vibequant.cc/Leaf/

---

## 1. 보호 계층 (현재 배포)

| 계층 | 무엇이 남는가 | OS 스크린샷에 유효? | 추출 방법 |
|---|---|---|---|
| **A. 서버 프리-컴포지트** | 업로드 시 공통 문구 (`Leaf \| 개인 열람용 …`) | ✅ | 육안 |
| **B. 시각적 신원 WM** | `email \| sessionId(8) \| IP` — CSS 오버레이 + **canvas 픽셀 베이크** | ✅ (주력) | 육안 / 확대 |
| **C. 비가시 LSB (`LEAFWM1`)** | JSON: sessionId, ip, email, album, page, ts | ⚠️ JPEG 재압축 시 손상 가능 | 추출기 HTML |
| **D. 캡처 징후 로그** | D1 `capture_alerts` (IP, UA, sid, email) | n/a (서버 로그) | `GET /Leaf/api/capture-log` |

> OS 스크린샷은 **막을 수 없다**. 추적의 1차 수단은 **B(시각적 신원 문자열)** 이다.
> C는 DevTools·canvas 원본에 가깝게 저장된 파일, 또는 경미한 재인코딩에 유효하다.

## 2. 신원 데이터 출처

뷰어 로드 시 `GET /Leaf/api/viewer-identity` 호출:

```json
{
  "sessionId": "f7a1556f918aa94c1c08f4e5308dae67",
  "ip": "61.74.87.185",
  "email": "guest@leaf.local",
  "label": "Leaf | guest@leaf.local | f7a1556f | 61.74.87.185",
  "auth": false
}
```

| 필드 | 의미 | 비고 |
|---|---|---|
| `sessionId` | `leaf_sid` 쿠키 (32 hex, 30일) | 동일 브라우저 재방문 시 유지 |
| `ip` | `CF-Connecting-IP` | Cloudflare 엣지 기준 |
| `email` | 로그인 전 `guest@leaf.local` | P3 이후 실제 계정 이메일 |
| `auth` | 로그인 여부 | MVP는 항상 `false` |

화면 상단 칩·대각선 워터마크·canvas에 동일 정보가 반복 표시된다.

---

## 3. 절차 A — 시각적 워터마크로 유출자 확인 (권장)

1. 유출된 이미지(스크린샷·재업로드본)를 확보한다.
2. 사진을 **확대**해 대각선 반투명 텍스트를 읽는다.
3. 형식 예:
   ```
   Leaf | guest@leaf.local | f7a1556f | 61.74.87.185 | 무단전재 금지
   ```
4. `sessionId` 앞 8자리(`f7a1556f`)와 IP로 열람자를 좁힌다.
5. (선택) 캡처 로그와 교차 확인:
   ```bash
   curl -sS "https://vibequant.cc/Leaf/api/capture-log" | jq .
   ```
   `detail`에 `sid=…|email=…`가 포함된다.

**한계**: 고의로 워터마크 영역을 크롭·블러하면 식별이 어려워질 수 있다. 텍스트는 이미지 전체에 타일링되어 있다.

---

## 4. 절차 B — 비가시 LSB 워터마크 추출

페이로드 매직: ASCII `LEAFWM1` + 4바이트 big-endian 길이 + UTF-8 JSON.
삽입 위치: 픽셀 **Blue 채널 LSB** (좌상단부터 순차).

### 4.1 추출기 사용

```bash
# 로컬에서 추출기 열기 (서버 불필요)
open Leaf_OpenEBook/scripts/extract-invisible-wm.html
# 또는 브라우저에서 해당 파일을 연다
```

1. 유출 이미지 파일을 선택한다 (PNG 권장; JPEG는 압축으로 실패할 수 있음).
2. 성공 시 JSON 예:
   ```json
   {
     "v": 1,
     "sid": "f7a1556f918aa94c1c08f4e5308dae67",
     "ip": "61.74.87.185",
     "email": "guest@leaf.local",
     "album": 1,
     "page": 7,
     "ts": "2026-08-01T13:29:00.000Z"
   }
   ```
3. 실패 메시지 `LEAFWM1 페이로드를 찾지 못했습니다` → 재압축/크롭으로 LSB 손상. **절차 A**로 전환.

### 4.2 자체 검증 (개발자)

뷰어에서 canvas가 표시된 상태라면 DevTools에서:

```js
// 현재 표시 canvas의 LSB 추출 (뷰어에 노출된 헬퍼)
const c = document.getElementById('photo-canvas');
const ctx = c.getContext('2d');
const id = ctx.getImageData(0, 0, c.width, c.height);
console.log(window.__LEAF_EXTRACT_WM(id));
```

또는 canvas를 PNG로 저장한 뒤 추출기에 넣으면 거의 항상 성공한다.

### 4.3 LSB가 깨지는 경우

| 원인 | 결과 |
|---|---|
| iOS/Android OS 스크린샷 → JPEG | 높은 확률로 실패 |
| SNS 재업로드 (추가 압축) | 실패 |
| 리사이즈·크롭 | 실패 또는 부분 손상 |
| canvas → PNG 무손실 저장 | 성공 |

## 5. 절차 C — 캡처 징후 로그

우클릭·인쇄 시도·짧은 visibility 스파이크 등이 `POST /Leaf/api/capture-alert`로 기록된다.

```bash
curl -sS "https://vibequant.cc/Leaf/api/capture-log"
```

| 컬럼 | 용도 |
|---|---|
| `ip` | CF IP |
| `detail` | 이벤트 + `sid=` + `email=` |
| `page_no` / `album_id` | 열람 위치 |
| `user_agent` | 기기 |
| `created_at` | 시각 |

> 오탐 가능. **확정 증거**가 아니라 시각 WM·LSB와 교차 확인할 보조 자료.

## 7. 로컬에서 보호 기능 스모크 테스트

```bash
cd Leaf_OpenEBook/worker
npx wrangler dev
# http://localhost:8787/Leaf/
```

1. 페이지 로드 → 상단 칩에 `Leaf | guest@… | <sid> | <ip>` 표시
2. 화보에 동일 문자열 대각선 워터마크 확인
3. DevTools → `#photo-canvas` 표시 여부 (img 대신 canvas)
4. `__LEAF_EXTRACT_WM`로 LSB JSON 확인
5. `이전`/`다음`이 화면 하단 safe-area 위에 정렬되는지 확인

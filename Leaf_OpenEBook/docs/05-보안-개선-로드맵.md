## 2. 위협 시나리오

### S1. URL 직접 수집 (현재 완전 무방비) — 심각도 **치명적**

```
1. 뷰어를 열어 DevTools Network에서 이미지 URL 패턴 파악
   → /Leaf/api/albums/1/pages/{n}
2. 반복문으로 1..N 순회 (쿠키·Referer 불필요)
3. 원본 해상도 1600px 이미지 확보
```

- 현재 방어: **없음**
- 남는 흔적: **없음** (capture_alerts 미기록, 신원 WM·LSB 부재)
- 결론: **추적 불가**. 유출본에는 공통 문구뿐이라 열람자를 특정할 수 없다.

### S2. JS 비활성화 열람 — 심각도 **치명적**

canvas 베이크·LSB·CSS 오버레이가 전부 클라이언트 JS다. JS를 끄면
`<img>`가 서버 원본을 그대로 표시하며, 우클릭 차단·캡처 알림도 함께 죽는다.

### S3. OS 스크린샷 (설계상 상정한 주 시나리오) — 심각도 **낮음 (방어 유효)**

- 신원 시각 WM은 픽셀에 구워져 있어 **남는다** → 추적의 유일한 실효 수단.
- LSB는 재압축으로 소실 → 보조 수단으로도 기대 불가.
- 잔여 약점: 워터마크 격자의 x 오프셋이 모든 행에서 동일하므로
  **세로 띠 크롭 한 번으로 모든 행에서 같은 구간(예: IP)이 통째로 제거**된다.

### S4. 로그 위조로 무고한 사용자 프레이밍 — 심각도 **높음**

```bash
curl -X POST .../Leaf/api/capture-alert -d '{"sessionId":"...","email":"victim@..."}'
```

임의 sid·email을 서버가 그대로 저장한다. 캡처 로그는 **증거 능력이 없고**,
반대로 타인을 유출자로 몰기 위한 도구가 될 수 있다. 무제한 쓰기이므로 D1 비용 공격도 가능.

### S5. 열람자 개인정보 역유출 — 심각도 **높음**

`GET /Leaf/api/capture-log`이 공개되어 모든 열람자의 IP·email·sessionId가 노출된다.
또한 IP를 워터마크에 각인하므로, 유출본이 SNS에 퍼지면 **열람자 IP가 함께 공개**된다.

## 4. 수정 로드맵

### 단계 1 — 접근 통제 (P0, 최우선) ✅ 완료

> 이 단계 없이는 아래 워터마크 작업이 모두 장식에 불과하다. → **2026-08-02 완료·배포.**

1. **이미지 게이트에 세션 필수화** — `leaf_sid` 쿠키 없는 요청은 403. ✅
2. **서명 URL 도입** — `/api/albums/{id}/pages/{n}?exp=&sig=`
   HMAC(sessionId + key + page + exp), TTL 120초. 메타 응답에서 발급. ✅
3. **레이트리밋** — D1 `rate_limits`, 세션·IP당 분당 N장 초과 시 429 + 알림 기록. ✅
4. **`capture-log` 관리자 인증** — `Authorization: Bearer` 토큰(secret). ✅
5. **`capture-alert` 서버 신뢰 소스 사용** — 클라이언트 sid/email 폐기,
   쿠키·`CF-Connecting-IP`에서 서버가 직접 채우고, detail allowlist·세션당 쓰기 상한 적용. ✅

**수용 기준 실측 (라이브 `scripts/security-check.sh` 17/17)**:
쿠키 없는 `curl`로 페이지 1장도 받을 수 없다(403) · 25장 순회 시 429 발생 · 로그 무인증 401 ·
위조 알림의 email이 저장되지 않음.

### 단계 2 — 서버 측 신원 워터마크 (P0-2 / P1) ✅ 완료

Workers 무료 티어 CPU 10ms로는 요청마다 합성이 불가능하다. → **방식 A(변형 배정)** 채택:

| 방식 | 개요 | 채택 |
|---|---|---|
| **A. 변형 배정** | 워터마크 위치·오프셋이 다른 변형 N개(16)를 업로드 시 사전 생성, 사용자↔변형을 결정적으로 매핑 | ✅ |
| B. 최초 열람 시 1회 합성 후 R2 캐시 | 로그인 사용자별 합성본 | ⏳ P3(로그인) 도입 시 |

**구현 내용**
- `prepare-and-upload.js`: 페이지당 **변형 16개** 생성(`images/{album}/{page}/{v}.jpg`), 격자 행별 오프셋이 v에 따라 상이 + 우하단 `v{n}` 태그. 원본은 `origin/{album}/{page}.jpg`(서빙 금지)
- Worker `pageHandler`: `variant = FNV-1a(sessionId, album, page) % 16` → **세션 결정적 매핑**, `watermark_assignments`에 기록
- 유출본 역추적: 변형 인덱스(코너 태그) → `watermark_assignments` 조회 → 세션 특정 → `sessions`로 IP 연결

**실측**: 같은 페이지를 두 세션이 요청 → 서로 다른 변형(v8, v12) 할당 확인. 동일 세션 재요청 시 동일 변형.

### 단계 3 — 워터마크 견고성 (P1) ✅ 완료

1. **격자 오프셋 행마다 의사난수 시프트** — 클라이언트(오버레이·canvas 베이크)와 서버 변형 모두 행별 시프트 적용 → 세로 크롭 내성 확보. ✅
2. **식별자에서 IP 제거** — 시각 WM·LSB 페이로드 모두 IP 제거. `viewerIdentity`가 `sessions` 테이블에 세션→IP 기록(서버 보관), 유출 시 사후 조회로 연결. ✅
3. **LSB 정책 결정** — 주파수 영역(DCT) 교체는 무료 티어·복잡도 대비 실익 낮아 **보류**, LSB는 "PNG 무손실에만 유효"로 문서 정정(`04`)하고 **보조 수단으로 격하**. 주력은 시각 WM + 서버 변형. ✅

### 단계 4 — 결함·비용 (P2) ✅ 완료

1. **캔버스 크기 버그 수정** — computed style 복사 제거, CSS(`#photo-canvas` max-width/height)가 크기 제약 담당. `resize`·`orientationchange` 재계산 추가. ✅
2. **캐시버스터 제거** — 서명 URL 도입으로 `?t=` 제거(ETag·`Cache-Control: private, max-age=60`). ✅
3. **서빙 해상도 축소** — 서빙 변형 장변 **900px**로 재생성, 원본(고해상도)은 R2 `origin/`에만 보관(서빙 금지). ✅
4. **`visibility spike` 오탐 제거** — 단독 `mobile_visibility_spike` 알림 **폐기**. ✅

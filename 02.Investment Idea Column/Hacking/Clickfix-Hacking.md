# ClickFix 공격, 왜 방어하기 힘든가

## — 보안 솔루션이 아니라 '사용자의 손'을 해킹하는 공격

"로봇이 아님을 확인하려면 Win+R을 누르고 Ctrl+V, Enter를 누르세요."

오늘날 가장 효과적인 해킹 도구 중 하나가 이 한 문장이다. 취약점도, 제로데이도, 정교한 익스플로잇도 필요 없다. 공격자는 가짜 문제를 보여주고 해결책이라며 명령어 한 줄을 건넨다. 실행하는 것은 공격자가 아니라 사용자 자신이다. 이것이 ClickFix다.

ClickFix는 "기술적 문제를 해결하세요", "회의 참여를 위해 업데이트가 필요합니다", "보안 인증을 완료하세요" 같은 메시지로 사용자가 직접 PowerShell 명령을 붙여넣거나 설치 파일을 실행하게 만드는 사회공학 기법이다. 2024년 말부터 북한 APT 그룹들이 빠르게 도입했고, 러시아·이란·중국 연계 그룹도 거의 동시에 채택했다. 국가 배후 조직부터 일반 사이버범죄 조직까지, ClickFix는 이제 공격자 공통의 초기 침투 수단이다.

이 단순한 공격을 왜 막기 어려운가. 최근 공개된 ChainScript RAT 사례를 중심으로 구조적 이유를 짚어본다.

---

### 첫째, 보안 모델의 전제를 뒤집는다

전통적 엔드포인트 보안은 "외부에서 들어온 악성 행위"를 막도록 설계됐다. 첨부파일 매크로, 브라우저 취약점, 드라이브-바이 다운로드를 감시한다. 그러나 ClickFix에서 명령을 입력하는 주체는 정상 로그인한 사용자이고, 실행 경로는 Windows 실행 창, PowerShell, msiexec.exe 같은 운영체제의 정상 도구다.

보안 솔루션 입장에서 "사용자가 PowerShell을 열어 명령을 실행했다"는 사건은 관리자의 일상 업무와 구별하기 어렵다. 파일 다운로드도 첨부파일 실행도 없이 클립보드에서 시작된 공격은 이메일 게이트웨이와 샌드박스를 통째로 우회한다. 공격자는 방어벽을 뚫는 대신, 그 안에 있는 사람에게 문을 열어달라고 부탁한다.

### 둘째, 미끼는 바뀌고 알맹이는 그대로다

ChainScript는 Blackpoint Cyber의 Adversary Pursuit Group(APG)이 ClickFix 활동을 추적하다 발견한 Node.js 기반 RAT다. ComponentTask33, UpdateDigital, HostShared, OrchidViolet66 등 여러 빌드 이름으로 등장했고, Spotify, Zoom Workplace, Microsoft Teams로 위장했다. 이름은 제각각이지만 핵심 에이전트 구조는 같다.

감염 흐름은 이렇다. ClickFix 미끼가 명령 실행을 유도하면 msiexec.exe가 원격에서 악성 MSI를 받아 설치한다. MSI는 자체 Node.js 런타임을 깔고, 숨겨진 PowerShell·VBScript 단계를 거쳐 JavaScript 에이전트를 실행한다. 지속성은 예약 작업과 Run 레지스트리 키로 확보한다.

```
ClickFix 미끼 → msiexec.exe로 악성 MSI 설치 → 자체 Node.js 런타임 배포
→ 숨겨진 PowerShell/VBScript 단계 → ChainScript 에이전트 실행
→ 예약 작업·Run 키로 지속성 확보
```

기능은 사실상 완전한 원격 제어다. 대화형 CMD·PowerShell, 파일 조작, 화면 캡처, 추가 페이로드 배포, 데스크톱 앱과 브라우저 확장을 아우르는 암호화폐 지갑 탐색, 원격 JavaScript 실행을 지원하고, 자기 업데이트와 흔적 정리 기능까지 갖췄다.

해시나 파일명, 위장 브랜드로 탐지 규칙을 만드는 순간 공격자는 다음 빌드로 넘어간다. 정적 IOC는 늘 한 발 늦다.

### 셋째, 탐지 인프라의 눈을 가린다

ClickFix 페이지도 진화한다. Microsoft는 방문자를 지문 식별(fingerprinting)해 적합한 표적에게만 악성 지시를 보여주는 캠페인을 문서화했다. 크롤러와 자동 분석을 피하기 위해서다. 보안 업체의 수집 봇에는 평범한 페이지가, 실제 표적에게만 가짜 인증 창이 뜬다. 위협 인텔리전스 피드에 오르기 전까지 공격 페이지는 사실상 보이지 않는다.

유포 경로도 넓어졌다. 최근 HBO Max 공식 Reddit 계정이 탈취돼 ClickFix로 이어지는 악성 광고 유포에 악용됐다. 신뢰받는 브랜드의 공식 채널이 미끼가 되면 "출처를 확인하라"는 기존 보안 교육은 힘을 잃는다.

### 넷째, 블록체인에 숨긴 C2는 끌 수 없다

ChainScript의 가장 까다로운 특징은 C2 인프라다. EtherHiding 방식으로 Polygon 스마트 컨트랙트를 활성 WebSocket 패널의 '주소록'으로 쓴다. 컨트랙트가 돌려준 문자열이 `ws://` 또는 `wss://`로 시작하는지 검증한 뒤 5분간 캐시하고, 설정 파일의 주소 대신 사용한다.

연구진은 이 구조가 작동하는 장면을 실시간으로 목격했다. 컨트랙트가 처음 가리킨 서버는 약 18분간 하트비트를 주고받았다. 연결이 끊긴 지 12분 뒤, 같은 컨트랙트는 전혀 다른 주소를 돌려줬다. 악성코드 재배포 없이 30분 만에 백엔드가 교체됐다.

C2 도메인 차단과 서버 테이크다운은 여기서 무력화된다. 서버를 내려도 공격자는 컨트랙트에 새 주소 하나만 기록하면 된다. 퍼블릭 블록체인 위의 컨트랙트는 누구도 삭제할 수 없다. Blackpoint는 백엔드 탐색을 악성코드 본체와 분리한 덕분에 운영자가 같은 임플란트로 감염 호스트를 새 인프라에 연결할 수 있다고 지적했다.

디테일 하나가 더 있다. ChainScript와 연결된 Polygon 컨트랙트는 대응하는 MSI(ComponentTask33)가 만들어지기 불과 23초 전에 배포됐다. 자동화된 빌드 파이프라인의 흔적이다. 공격자는 공장처럼 악성코드와 인프라를 찍어낸다.

북한 연계 그룹은 이미 이런 기법을 폭넓게 운용해 왔다. 이더리움 기반 EtherHiding, TRON·Aptos를 포인터로 쓰고 BSC에 데이터를 저장하는 교차 체인 방식, 빈 이더리움 전송에 제어 주소를 숨기는 방식 등이다. 블록체인은 "탈중앙화된 방탄 호스팅"이 됐다.

단, 현재 공개된 분석에서 ChainScript 자체를 북한 등 특정 국가 행위자로 귀속한 내용은 확인되지 않는다. 기법의 계보가 겹친다는 것과 같은 조직의 소행이라는 것은 다른 문제다.

### 다섯째, 신뢰는 코드보다 먼저 공략된다

북한 APT의 ClickFix가 특히 위험한 이유는 명령어 한 줄 이전에 긴 신뢰 구축 과정이 있기 때문이다.

Kimsuky는 2025년 1월, 3월, 6월 국내 외교·안보·국제정치 전문가를 겨냥해 ClickFix를 결합한 다단계 스피어 피싱을 벌였다. 언론인, 정부 보좌관, 경찰 수사관을 사칭해 인터뷰 요청이나 회의 초청으로 관계를 맺은 뒤에야 악성 링크를 보냈다. BlueNoroff는 Web3·암호화폐 기업을 노려 Zoom·Teams 회의 페이지를 정교하게 모방했고, 탈취한 텔레그램 계정으로 지인을 가장했다. Lazarus 계열의 Contagious Interview 작전은 가짜 채용 담당자와 코딩 테스트로 개발자를 노린다.

| APT 그룹 | 표적 | 주요 미끼 |
|---|---|---|
| Kimsuky | 외교·안보 전문가, 국방 연구기관 | 가짜 인터뷰·회의 초청, HWP 문서 |
| BlueNoroff | Web3·암호화폐 기업 | Zoom/Teams 회의 사칭, 탈취된 텔레그램 계정 |
| Lazarus (Contagious Interview) | 암호화폐 개발자 | 가짜 채용 담당자, 코딩 평가·기술 면접 |

몇 주간 대화한 "기자"가 보낸 회의 링크에서 "오디오 드라이버를 업데이트하라"는 안내가 뜨면, 의심할 사람은 많지 않다. 기술적 방어는 이 신뢰 관계 안으로 들어갈 수 없다.

### 왜 하필 Spotify, Zoom, Teams인가

공개 보고서는 위장 대상 선택 이유를 밝히지 않는다. 다만 추론은 가능하다.

첫째, 신뢰도와 맥락이다. 수억 명이 매일 쓰는 소프트웨어이고, 특히 Zoom과 Teams는 "회의 참여를 위해 설치가 필요하다"는 시나리오에 딱 맞는다. 가짜 인터뷰·회의 초청 수법과 자연스럽게 이어진다.

둘째, 표적 환경이다. Web3 개발자 PC에는 Node.js와 npm이 이미 깔려 있는 경우가 많고, 새 도구 설치가 일상이다. Node.js 런타임이 하나 더 설치되거나 node.exe가 새로 떠도 이상해 보이지 않는다.

셋째는 가설이다. Spotify는 CEF, Zoom과 Teams는 Electron 계열 기술을 쓰는 웹 기반 데스크톱 앱이라, JavaScript 런타임이 따라오는 설치 과정이 덜 어색해 보일 수 있다. 직접적 근거는 없는 추정이며 추가 검증이 필요하다.

### 그렇다면 어떻게 막을 것인가

방어가 어려운 이유를 뒤집으면 대응 방향이 보인다. 공격이 사용자의 손, 정상 도구, 끌 수 없는 인프라를 이용한다면 방어도 그 세 지점을 겨냥해야 한다.

**사용자의 손이 닿는 경로를 좁혀라.** 일반 직원 대부분에게 Win+R 실행 창과 PowerShell은 업무상 필요 없다. 그룹 정책으로 실행 창을 비활성화하고, PowerShell을 제한 언어 모드(Constrained Language Mode)로 묶고, AppLocker나 WDAC로 사용자 경로의 msiexec 원격 설치를 막는 것만으로 공격 표면이 크게 준다. 실행 창 입력 기록(RunMRU 레지스트리) 모니터링도 효과적인 탐지 지점이다.

**파일이 아니라 행위를 봐라.** 빌드 이름과 위장 브랜드는 바뀌어도 행위의 연쇄는 쉽게 바뀌지 않는다. 브라우저 사용 직후의 msiexec 원격 실행, 사용자 프로필에 새로 설치된 Node.js 런타임, 숨김 창으로 실행되는 PowerShell·VBScript, 새로 등록된 예약 작업과 Run 키. 이 고리를 하나의 시나리오로 잡는 행위 기반 룰이 정적 IOC보다 오래 살아남는다.

**블록체인 RPC를 관제 대상에 넣어라.** 일반 업무 PC에서 node.exe 같은 비브라우저 프로세스가 Polygon이나 이더리움 RPC로 `eth_call`을 보내는 일은 극히 드물다. 그 트래픽 자체가 강력한 이상 신호다. 확인된 악성 컨트랙트 주소를 IOC로 공유하면, 방어자는 컨트랙트가 갱신될 때마다 공격자의 새 C2 주소를 오히려 먼저 읽어낼 수 있다. 블록체인의 투명성은 양날의 검이다.

**교육 메시지는 하나로 줄여라.** 공식 계정이 탈취되는 시대에 "출처를 확인하라"로는 부족하다. 대신 이 한 문장을 반복해야 한다. **정상적인 웹사이트, 회의 도구, 채용 담당자는 절대 명령어를 복사해 붙여넣으라고 요구하지 않는다.** 예외가 없는 규칙이라 기억하기 쉽다. 외교·안보 전문가, 암호화폐 기업 임직원, Web3 개발자처럼 이미 표적이 된 집단에는 가짜 인터뷰·회의 초청·코딩 테스트를 시나리오로 한 맞춤형 훈련이 필요하다.

### 전망: 북한의 '표준 해킹 기법'이 된 ClickFix

ClickFix는 일시적 유행이 아니다. 북한은 불과 몇 달 만에 Kimsuky, BlueNoroff, Lazarus 계열 등 성격이 다른 여러 조직에 이 기법을 동시에 녹여 넣었다. 첩보 목적이든 암호화폐 탈취 목적이든, 표적이 외교관이든 개발자든 가리지 않는다. 비용은 낮고 성공률은 높으며, 탐지는 어렵다. 공격자 입장에서 이보다 효율적인 초기 침투 수단은 드물다. ClickFix는 이미 북한이 가장 자주 꺼내 드는 표준 해킹 기법이 됐고, 앞으로 그 빈도는 더 늘어날 것이다.

여기에 블록체인 기반 C2, 자동화된 빌드 파이프라인, AI를 활용한 사칭과 딥페이크가 결합되면 공격 규모와 정교함은 한 단계 더 올라간다. 미끼의 언어는 더 자연스러워지고, 사칭 인물은 더 그럴듯해지며, 인프라는 더 빨리 바뀔 것이다.

가장 먼저, 가장 집요하게 노려질 곳은 정부, 군, 정보기관이다. Kimsuky가 이미 외교·안보 전문가와 국방 연구기관을 반복적으로 겨냥했다는 사실이 그 방향을 보여준다. 이들 조직의 구성원은 기자의 인터뷰 요청, 학회 초청, 유관기관 회의 참석 요청을 일상적으로 받는다. 공격자가 흉내 내기 가장 쉬운 업무 환경이다.

따라서 정부, 군, 정보기관은 ClickFix를 별도의 위협 범주로 다루고 각별히 주의해야 한다. 기술적 통제만으로는 부족하다. 실행 창과 PowerShell 사용 제한, 행위 기반 탐지, 블록체인 RPC 관제를 기본으로 깔되, 실제 북한 공격 시나리오를 재현한 모의 훈련과 정기 교육을 병행해야 한다. 특히 대외 접촉이 잦은 고위직, 연구 인력, 대외협력 담당자는 우선 교육 대상이다. 명령어 한 줄을 붙여넣기 전에 멈추는 습관은 어떤 보안 장비보다 확실한 방어선이다.

### 맺으며

ClickFix는 기술적으로 새로운 공격이 아니다. 오히려 너무 단순해서 위험하다. 수십 년간 쌓아 올린 보안 체계는 "악성코드가 스스로 들어오는 것"을 막는 데 최적화됐고, 공격자는 그 전제를 비켜 "사용자가 스스로 들이게" 만드는 길을 택했다. 그 뒤에서는 끌 수 없는 블록체인 인프라와 자동화된 빌드 파이프라인이 조용히 돌아가고 있다.

방어의 무게중심도 옮겨가야 한다. 무엇이 들어오는지 감시하던 시대에서, 시스템 안에서 무엇이 어떤 순서로 실행되는지 보는 시대로. 그리고 무엇보다, 명령어 한 줄을 붙여넣기 전에 한 번 멈출 수 있는 사람을 만드는 일로.

> 측정 시각: **2026-08-27 11:21~12:05 KST** · 6회 연속 스캔 (실데이터, `wrangler dev` 로컬 실행)
> 환산율 출처: 빗썸 `KRW-USDT` = **1,384 KRW/USDT** · 기준: `FX_MODE=usdt` (실행 가능 스프레드)

## 1. 결론 먼저

**현재 빗썸-바이낸스 사이에 실행 가능한 차익거래 기회는 없다.**
관측된 프리미엄은 최대 ±0.08% 인데, 왕복 비용만 코인별로 **0.17~0.36%** 다.
즉 기회가 성립하려면 지금보다 **2~5배 큰 갭**이 벌어져야 한다.

봇이 4종목 모두 `대기`를 유지하는 것은 정상 동작이다.

## 3. 왜 프리미엄이 이렇게 작은가 — 두 가지 "김치 프리미엄"

같은 "김프"라는 말이 서로 다른 두 값을 가리킨다. 이걸 섞으면 신호가 통째로 틀어진다.

| 기준 (`FX_MODE`) | 환산율 | 재는 값 | 이 프로젝트에서 |
|---|---|---|---|
| `usdt` **(기본)** | 빗썸 `KRW-USDT` | **실행 가능 스프레드.** 바이낸스 USDT 가격을 같은 거래소의 USDT 시세로 되돌리므로 스테이블코인 프리미엄이 양쪽에서 상쇄된다. USDT 를 실제로 옮겼을 때 손에 남는 폭 | 순이익 ≥ 0.2% 로 판정 |
| `fx` | 두나무 `FRX.KRWUSD` | **헤드라인 김프.** 뉴스에 나오는 "김프 3%"가 이것. USDT 프리미엄이 그대로 포함된다 | 프리미엄 절댓값 ≥ 1.5% 로 판정 |

핵심은 **헤드라인 김프가 3% 라도 그게 3% 수익을 뜻하지 않는다**는 점이다.
원화로 USDT 를 살 때 이미 그 프리미엄을 지불하기 때문이다. 실제로 먹을 수 있는 건
`usdt` 기준으로 남는 부분뿐이고, 그게 지금 ±0.08% 다.

그래서 두 기준은 판정 방식도 분리했다. `fx` 기준에 순이익 판정을 걸면
"USDT 를 3% 비싸게 사야 얻는 3%"를 실현 가능한 이익으로 착각한 **거짓 신호**가 나온다.

## 4. 임계값을 왜 0.2% 로 잡았나

초기 설정은 `±1.5% 프리미엄`이었는데, `usdt` 기준 프리미엄은 ±0.1% 수준이라
**이 조합으로는 알림이 영원히 발생하지 않았다.** 실측으로 확인한 뒤 다음과 같이 바꿨다.

- 판정 대상을 **프리미엄 → 순이익**으로 변경. 순이익은 비용을 이미 뺀 값이라 **0 이 손익분기**다.
- 임계값 `0.2%` = 500만원 기준 약 **1만원** 수익. 코인별 출금비 차이도 자동 반영된다.
- 히스테리시스 해제값 `0.05%`.

`FX_MODE=fx` 로 바꾸면 임계값도 자동으로 `1.5%/0.5%`(프리미엄 기준)로 따라간다.
환산율 폴백이 일어나면 **실제 받아온 출처 기준**으로 다시 맞춘다 —
`fx` 를 요청했는데 두나무가 죽어 빗썸 USDT 로 폴백되면, 1.5% 를 그대로 들고 가지 않고 0.2% 로 되돌린다.

## 5. 이 추정치가 담지 못하는 비용

`netPct` 는 **낙관적 상한**이다. 아래는 반영되어 있지 않다.

1. **슬리피지·호가 깊이** — 500만원을 시장가로 밀면 표시 가격에 다 체결되지 않는다
2. **전송 지연** — 코인 전송 중(수 분~수십 분) 가격이 움직인다. 차익거래에서 가장 큰 실질 리스크
3. **원화 입출금 비용·한도**, 트래블룰 대응
4. **바이낸스 실제 수수료율** — BNB 할인·VIP 등급에 따라 다름
5. **과세** — 국내 가상자산 과세·규제 대상이 될 수 있음

이 중 2번(전송 지연)만으로도 0.2% 짜리 기회는 쉽게 사라진다.
**본 시그널은 "볼 만한 갭이 생겼다"는 알림이지, 수익 보장이 아니다.**

## 6. 운영상 확인된 사항

- **두나무 환율 API 가 이 실행 환경에서는 도달하지 않았다** (`internal error`).
  `fx` 모드를 쓰려면 배포 환경에서 도달 가능한지 먼저 확인해야 한다.
  폴백은 정상 동작하며, 폴백 시 로그(`[fx] dunamu 실패 …`)를 남기고 판정 기준도 함께 되돌린다.
- 빗썸·바이낸스 공개 API 는 모두 정상 응답했다.
- 6회 연속 스캔에서 시그널 발생 0건, 알림 0건.

# 개발 계획 (Development Plan)

> 대상: `BTC-Arbitrage-for-Bithumb` — 빗썸 × 바이낸스 차익거래 시그널 봇
> 스택: TypeScript · Cloudflare Workers · Cloudflare KV · 정적 대시보드 · 텔레그램

## 0. 목표

빗썸(KRW)과 바이낸스(USDT)의 가격 차이(김치 프리미엄)를 상시 비교해 차익거래 기회를 신호로 알려주는 **시그널 봇**을 만든다.
실제 자동 매매는 하지 않는다(연구·신호 탐지). 과세·규제 리스크를 사용자에게 명시한다.

## 1.5 기술 검토 및 수정 (2026-08-27)

전체 코드를 검토하고 아래를 수정했다. 테스트 31 → **51개**, typecheck 통과.

### 수정한 버그

| # | 위치 | 문제 | 수정 |
|---|---|---|---|
| 1 | `scan.ts` · `signals.ts` | **30분 쿨다운이 전혀 동작하지 않음.** `updateAlertState` 가 `lastAlertAt` 을 항상 이전 값(=`0`)으로 되돌려서 KV 에 발송 시각이 한 번도 기록되지 않았다. 스팸을 막고 있던 건 히스테리시스뿐 | 발송 성공 시 `markAlertSent(state, now)` 로 시각 기록. 알림 전송을 KV 저장보다 앞으로 옮김 |
| 2 | `signals.ts` | **역방향 순이익이 손실로 표시됨.** 프리미엄 −3%(빗썸 매수 기회)의 순이익이 `−3.14%` 로 계산됐다 | `\|프리미엄\|` 을 총이익으로 보고 비용 차감 |
| 3 | `static/app.js` | **시그널 배지가 항상 "대기".** `/api/status` 에 없는 `status.thresholdPct` 를 읽어 비교가 전부 `undefined` 였다 | `/api/status` 가 임계값을 함께 반환하도록 하고, 프론트는 `/api/signals` 판정을 우선 사용 |
| 4 | `providers/binance.ts` | 폴백이 **HTTP 오류에만** 동작. DNS 실패·타임아웃 같은 네트워크 예외는 잡지 않아 `data-api.binance.vision` 로 넘어가지 못했다 | `try/catch` 로 예외까지 흡수 |
| 5 | `api.ts` | `Cache-Control` 에 `max-age` 가 없어 브라우저가 휴리스틱 캐시 → 새 스냅샷이 나와도 옛 데이터와 **잘못된 "stale N분 전" 경고**가 표시됐다 (로컬 재현) | `max-age=0, s-maxage=240` + 프론트 `cache: "no-store"` |
| 6 | `api.ts` | 401·502 응답까지 `s-maxage=240` 으로 캐시 가능했다 | 오류·관리 응답은 `no-store` |
| 7 | `static/app.js` | 히스토리 포인트가 1개일 때 스파크라인 좌표가 `0/0 = NaN` → SVG 깨짐 | 단일 포인트는 수평선으로 렌더 |
| 8 | `.gitignore` | `.dev.vars.*` 규칙이 **커밋해야 할 `.dev.vars.example` 까지 무시**해 실제로 추적되지 않고 있었다 | `!.dev.vars.example` 예외 추가 |
| 9 | `types.ts` · `scan.ts` | 값 없음을 `NaN` 으로 표현했는데 KV 는 JSON 이라 저장 시 `null` 로 바뀐다(타입 거짓말) | `MaybeNumber = number \| null` 도입, 처음부터 `null` |
| 10 | `signals.ts` | 반대 방향으로 뒤집혀도 NEUTRAL 을 한 번 거쳐야 해서 실제 기회를 한 주기(5분) 놓쳤다 | 반대 임계값 돌파 시 즉시 반전 |
| 11 | `static/index.html` | 7열 표가 `body` 를 밀어내 좁은 화면에서 **페이지 전체가 가로 스크롤**됐다 | 표만 `overflow-x` 컨테이너로 감쌈 |

### 보안·운영

- 관리 API 에 `Authorization: Bearer` 경로 추가(쿼리스트링 토큰은 로그·히스토리에 남음), 토큰 비교를 상수 시간으로
- 모든 업스트림 호출에 **8초 타임아웃**과 User-Agent 부여 (`providers/http.ts`)
- 한 거래소에서 코인 하나가 빠져도 나머지 코인 스캔은 계속되도록 부분 실패 처리
- **KV 쓰기 예산**: 5분 크론 = 288 스캔/일 × 3 write = 864/일로 무료 한도(1,000)에 근접했다. 알림 상태를 변경 시에만 쓰도록 바꿔 스캔당 2 write 로 축소
- `nodejs_compat` 제거(미사용) · **Smart Placement 제거** — 크론 핸들러에는 적용되지 않고, `/api/*` 는 KV 만 읽으므로 사용자에게서 멀어지기만 한다

### 설계상 확인된 사항 (`FX_MODE`)

환산율로 빗썸 `KRW-USDT` 를 쓰면 바이낸스 USDT 가격을 같은 스테이블코인으로 되돌리는 셈이라
**USDT 프리미엄이 상쇄**된다. 로컬 실측 결과 4종목 프리미엄이 모두 ±0.1% 안에 들어와,
기본 임계값 `±1.5%` 로는 알림이 사실상 발생하지 않는다.

이는 버그가 아니라 "무엇을 재느냐"의 문제이므로 `FX_MODE` 로 선택하게 했다.

| `FX_MODE` | 의미 | 임계값 가이드 |
|---|---|---|
| `usdt` (기본) | 실행 가능 스프레드 (USDT 를 실제로 옮겼을 때 남는 폭) | `0.3%` 수준으로 낮춰야 발동 |
| `fx` | 헤드라인 김치 프리미엄 (두나무 실환율 기준) | `±1.5%` 유지 가능 |

5. **알림 과다 방지**: 히스테리시스 + 코인별 쿨다운 + 임계값 튜닝

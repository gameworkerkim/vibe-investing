# 개발 계획 (Development Plan)

> 대상: `BTC-Arbitrage-for-Bithumb` — 빗썸 × 바이낸스 차익거래 시그널 봇
> 스택: TypeScript · Cloudflare Workers · Cloudflare KV · 정적 대시보드 · 텔레그램

## 0. 목표

빗썸(KRW)과 바이낸스(USDT)의 가격 차이(김치 프리미엄)를 상시 비교해 차익거래 기회를 신호로 알려주는 **시그널 봇**을 만든다.
실제 자동 매매는 하지 않는다(연구·신호 탐지). 과세·규제 리스크를 사용자에게 명시한다.

### 보안·운영

- 관리 API 에 `Authorization: Bearer` 경로 추가(쿼리스트링 토큰은 로그·히스토리에 남음), 토큰 비교를 상수 시간으로
- 모든 업스트림 호출에 **8초 타임아웃**과 User-Agent 부여 (`providers/http.ts`)
- 한 거래소에서 코인 하나가 빠져도 나머지 코인 스캔은 계속되도록 부분 실패 처리
- **KV 쓰기 예산**: 5분 크론 = 288 스캔/일 × 3 write = 864/일로 무료 한도(1,000)에 근접했다. 알림 상태를 변경 시에만 쓰도록 바꿔 스캔당 2 write 로 축소
- `nodejs_compat` 제거(미사용) · **Smart Placement 제거** — 크론 핸들러에는 적용되지 않고, `/api/*` 는 KV 만 읽으므로 사용자에게서 멀어지기만 한다

### 설계상 확인된 사항 (`FX_MODE`)

환산율로 빗썸 `KRW-USDT` 를 쓰면 바이낸스 USDT 가격을 같은 스테이블코인으로 되돌리는 셈이라
**USDT 프리미엄이 상쇄**된다. 로컬 실측 결과 4종목 프리미엄이 모두 ±0.1% 안에 들어와,
기본 임계값 `±1.5%` 로는 알림이 사실상 발생하지 않는다.

이는 버그가 아니라 "무엇을 재느냐"의 문제이므로 `FX_MODE` 로 선택하게 했다.

| `FX_MODE` | 의미 | 임계값 가이드 |
|---|---|---|
| `usdt` (기본) | 실행 가능 스프레드 (USDT 를 실제로 옮겼을 때 남는 폭) | `0.3%` 수준으로 낮춰야 발동 |
| `fx` | 헤드라인 김치 프리미엄 (두나무 실환율 기준) | `±1.5%` 유지 가능 |

## 1.6 시그널 기준 전환 — "동작하는 설정"으로 (2026-08-27)

1.5 절에서 확인한 대로, `FX_MODE=usdt` 기준 프리미엄은 실측 ±0.1% 인데 임계값이 `±1.5%` 라
**알림이 구조적으로 발생할 수 없는 상태**였다. 판정 방식을 바꿔 해결했다.

### 무엇을 바꿨나

| 항목 | 이전 | 이후 |
|---|---|---|
| 판정 대상 | 프리미엄 절댓값 | **순이익률**(`net`, 비용 차감 후) — `fx` 모드에서는 프리미엄 유지 |
| 방향 결정 | 프리미엄 부호 + 크기 (한 값으로 겸용) | **방향 = 프리미엄 부호 / 발동 = basis 값 크기** 로 분리 |
| 기본 임계값 | `1.5% / 0.5%` 고정 | basis 별 자동 (`net`: 0.2/0.05 · `premium`: 1.5/0.5) |
| 폴백 시 기준 | 요청한 `FX_MODE` 고정 | **실제 받아온 환산율 출처**를 따라 재조정 |

### 왜 순이익 기준인가

- 순이익은 비용을 이미 뺀 값이라 **0 이 손익분기**다. 임계값이 곧 "이만큼 남으면 알려줘"가 된다.
- 코인별 출금비 차이(BTC 0.278% vs SOL 0.168%)가 자동으로 반영된다.
  프리미엄 기준으로는 SOL 과 ETH 에 같은 잣대를 들이대게 된다.
- 비용도 못 넘기는 갭이 신호가 되는 **거짓 양성**과, 1.5% 미만이지만 실제로 남는 기회를 놓치는
  **거짓 음성**을 동시에 없앤다.

`fx` 모드에 순이익 판정을 걸지 않은 이유는 그 프리미엄에 USDT 프리미엄이 포함돼 있어서다.
"USDT 를 3% 비싸게 사야 얻는 3%"를 실현 가능한 이익으로 계산하면 안 된다.

### 환산율 폴백 시 기준 재조정 (`configForFxSource`)

검증 중 두나무 환율 API 가 도달하지 않아 `fx` 요청이 빗썸 USDT 로 폴백되는 상황이 실제로 발생했다.
이때 프리미엄은 ±0.1% 짜리가 되는데 임계값은 1.5% 로 남아 **조용히 무력화**된다.
그래서 basis 를 요청 모드가 아니라 **결과(`fx.source`)** 에서 파생하도록 바꿨다.
사용자가 임계값을 명시했다면 그 값은 존중한다.

### 부수 수정

- 환산율 폴백이 조용히 일어나던 것을 로그로 남김 (`[fx] dunamu 실패 …`)
- 반올림하면 0 이 되는 음수가 `-0.00%` 로 표시되던 것 수정
- 대시보드 상태 패널에 판정 기준 표시 (`시그널 기준: 순이익 ≥ 0.20%`)

### 현재 상황

실측 결과 **여전히 시그널은 발생하지 않는다** — 이번에는 설정 오류가 아니라
실제로 기회가 없기 때문이다. 상세: [`ARBITRAGE-SITUATION.md`](./ARBITRAGE-SITUATION.md)

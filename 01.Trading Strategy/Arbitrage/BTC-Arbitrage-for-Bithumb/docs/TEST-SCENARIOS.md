## 1. 설정 — `config.test.ts`

### 1.1 `configFromVars` (기본 파싱)

| 시나리오 | 확인하는 것 |
|---|---|
| 기본값 | 코인 4종, 쿨다운 30분, `FX_MODE=usdt`, 기준 `net` |
| 커스텀 변수 파싱 | 대소문자·공백 정규화, 알 수 없는 코인(`doge`) 제외 |
| 잘못된 숫자는 fallback | `"abc"` 같은 값이 들어와도 기본값 유지 |
| `FX_MODE` 파싱 | `fx` 만 인정, `USDT`·`nonsense` 는 기본값 |

### 1.2 `configForFxSource` (환산율 폴백 시 기준 재조정)

환산율이 폴백되면 **재는 값 자체가 달라지므로** 판정 기준도 따라가야 한다.

| 시나리오 | 확인하는 것 |
|---|---|
| 🛡 `fx` 요청 → `bithumb-usdt` 폴백 | 기준이 `premium`→`net`, 임계값 1.5%→0.2% 로 되돌아감. **되돌리지 않으면 ±0.1% 짜리 스프레드에 1.5% 임계값이 걸려 영원히 발동하지 않는다** |
| `usdt` 요청 → `dunamu` 폴백 | 반대 방향도 대칭 동작 (`net`→`premium`, 0.2%→1.5%) |
| 출처가 요청과 일치 | 불필요한 객체 생성 없이 그대로 반환 |
| 사용자 명시 임계값 | 폴백이 일어나도 사용자가 적은 값은 덮어쓰지 않음 |

## 2. 시그널 엔진 — `signals.test.ts`

순수 함수라 외부 의존성 없이 전 분기를 검증한다.

### 2.1 계산

| 시나리오 | 확인하는 것 |
|---|---|
| `computePremium` | `(빗썸/바이낸스KRW − 1) × 100`, 양·음 both |
| 바이낸스 가격이 0 | 0으로 나누지 않고 0 반환 |
| `computeSpreadKrw` | 원화 절대 차이 |
| `estimateNetPct` | 테이커 + 출금비 차감. 진입금액이 커지면 출금비 비중 감소 |
| 🛡 역방향 순이익 | **프리미엄 −3% 와 +3% 의 순이익이 같고 양수**. 예전에는 −3.14% 라는 손실처럼 보이는 값이 나왔다 |

### 2.2 판정 기준 (`signalMetric` / `directionFor`)

| 시나리오 | 확인하는 것 |
|---|---|
| basis 별 metric | `net` → 순이익률, `premium` → 프리미엄 절댓값 |
| 방향 결정 | **방향은 프리미엄 부호**, 크기는 metric — 둘을 분리했다 |

### 2.3 `evaluateSignal` — basis=net (기본)

| 시나리오 | 확인하는 것 |
|---|---|
| 임계값 돌파 | 순이익 0.3% ≥ 0.2% → 프리미엄 부호 방향으로 트리거 (양쪽 다) |
| 🛡 거짓 신호 차단 | **프리미엄 2% 라도 순이익이 −0.05% 면 NEUTRAL.** 예전 프리미엄 기준이면 발동했을 케이스 |
| 히스테리시스 해제 | 0.1% 는 유지, 0.04% ≤ 해제값에서 NEUTRAL 복귀 |
| 🛡 즉시 반전 | 방향이 뒤집히고 임계값을 다시 넘기면 NEUTRAL 을 안 거치고 반전. **거치면 5분 주기를 통째로 놓친다** |
| 반전했지만 약함 | 방향만 뒤집히고 임계값 미달이면 이전 상태 유지 (플래핑 방지) |

### 2.4 `evaluateSignal` — basis=premium (`FX_MODE=fx`)

| 시나리오 | 확인하는 것 |
|---|---|
| 순이익 무시 | 순이익이 −99% 여도 프리미엄 1.5% 면 발동. 헤드라인 김프 모니터링용이므로 의도된 동작 |
| 해제 임계값 0.5% | 0.8% 유지 / 0.4% 복귀 |
| BUY 방향 대칭 | 음수 쪽도 동일 |

### 2.5 쿨다운 상태 (`updateAlertState` / `markAlertSent` / `shouldSendAlert`)

| 시나리오 | 확인하는 것 |
|---|---|
| `since` 갱신 | 상태가 바뀔 때만 진입 시각 갱신, 같은 상태면 유지 |
| 🛡 `lastAlertAt` 책임 분리 | **`updateAlertState` 는 절대 건드리지 않고 `markAlertSent` 만 갱신.** 이 구분이 없어서 쿨다운이 통째로 죽어 있었다 |
| 쿨다운 경과 판정 | 60초 뒤 억제 / 30분 경과 후 허용 |
| 트리거 아니면 미발송 | NEUTRAL 평가는 알림 없음 |

| 정상 파이프라인 | 프리미엄 +2% 계산, 환산율 출처, 스냅샷 저장, 시그널 생성 |

| 히스테리시스 재알림 억제 | 2회차 동일 상태에서는 알림 없음 |
| 🛡 `lastAlertAt` KV 기록 | **발송 성공 후 KV 의 `state:alerts.BTC.lastAlertAt` 이 스캔 시각과 일치.** 예전에는 영원히 0 이었다 |
| 🛡 반전 시 쿨다운 적용 | +2% → −2% 반전 시 방향은 즉시 뒤집히되 30분 이내라 **알림은 억제**. 쿨다운이 실제로 작동함을 증명 |

## 6. HTTP API — `api.test.ts`

이전에는 **API 레이어에 테스트가 하나도 없었다.**

| 시나리오 | 확인하는 것 |
|---|---|
| 🛡 `/api/status` 임계값 포함 | `thresholdPct`·`signalBasis` 반환. **없어서 대시보드 배지가 항상 "대기"였다** |
| 🛡 캐시 헤더 | `max-age=0, s-maxage=240` — 엣지만 캐시, 브라우저는 매번 재검증. **`max-age` 가 없어 브라우저가 옛 데이터와 가짜 stale 경고를 보여줬다** |
| 결측 코인 제외 | 시세 없는 코인은 시그널 목록에서 빠짐 |
| 🛡 폴백 스냅샷 기준 보고 | `FX_MODE=fx` 라도 스냅샷이 `bithumb-usdt` 면 `net`/0.2% 로 보고 |
| 실환율 스냅샷 기준 | 스냅샷이 `dunamu` 면 `premium`/1.5% 로 보고 |
| `ADMIN_TOKEN` 미설정 | 어떤 토큰이 와도 401 (기본 잠금) |
| 틀린 토큰 | 쿼리·Bearer 양쪽 모두 401 |
| 🛡 오류 응답 무캐시 | 401 은 `no-store`. **공유 캐시에 401 이 박히면 토큰을 고쳐도 몇 분간 실패** |
| 텔레그램 미설정 | 인증 통과 후 503 + `no-store` |
| 알 수 없는 경로 | 404 JSON |

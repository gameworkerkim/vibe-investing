# 금융·퀀트·크립토 투자용 오픈소스 프롬프트 라이브러리 가이드 - Awesome LLM Prompts

> 작성일: 2026-07-15 

---

## 1. 개요

LLM을 금융 분석에 활용할 때 프롬프트 품질이 결과물 품질을 좌우한다. 아래는 공개 프롬프트 라이브러리 중 금융·퀀트 분야에서 참조 가치가 있는 저장소를 범용/특화로 구분해 Awesome LLM Prompts로 정리한 것이다.

| 구분 | 저장소 | 성격 | 라이선스 |
|---|---|---|---|
| 범용 | [f/prompts.chat](https://github.com/f/prompts.chat) | 세계 최대 규모 오픈소스 프롬프트 라이브러리 (구 Awesome ChatGPT Prompts, 143K+ 스타) | CC0 |
| 금융 특화 | [ternary-ai/prompts](https://github.com/ternary-ai/prompts) | 인지적 금융 에이전트(Cognitive Financial Agents)용 프롬프트 | 오픈소스 |
| 보조 | [drshahizan/Generative-AI-Playground](https://github.com/drshahizan/Generative-AI-Playground) | 150개 이상 금융 프롬프트 모음 | 오픈소스 |
| 보조 | [AgentDock/AgentDock](https://github.com/AgentDock/AgentDock) | 재무비율 분석 템플릿 (유동성·수익성·효율성·건전성·밸류에이션) | 오픈소스 |
| 보조 | [abilzerian/LLM-Prompt-Library](https://github.com/abilzerian/LLM-Prompt-Library) | Finance 카테고리 포함 50개 이상 프롬프트 | 오픈소스 |

## 2. prompts.chat — 범용 라이브러리

- 저장소: [github.com/f/prompts.chat](https://github.com/f/prompts.chat)
- 프롬프트 탐색: [prompts.chat/prompts](https://prompts.chat/prompts)
- 원본 데이터: [prompts.csv](https://github.com/f/prompts.chat/blob/main/prompts.csv) / [PROMPTS.md](https://raw.githubusercontent.com/f/prompts.chat/main/PROMPTS.md)

하버드, 컬럼비아 등에서 인용된 대표적 프롬프트 저장소이나, 금융 전용이 아닌 **범용 저장소**다. 금융 프롬프트는 전체의 일부이며 "finance", "investor", "accountant", "financial" 키워드로 검색해 찾는다.

### 금융 관련 페르소나 프롬프트

| 프롬프트 | 설명 |
|---|---|
| Accountant | 예산 편성, 투자 전략, 위험 관리를 고려한 재무 계획 수립 |
| Financial Analyst | 재무제표 분석, 기업 가치 평가, 투자 의사 결정 지원 |
| Investment Advisor | 투자 성향에 맞춘 포트폴리오 추천 및 시장 분석 |

### 평가

페르소나(역할극) 기반 프롬프트가 중심이라 **탐색적 아이디에이션에는 유용하나, 정량 분석 파이프라인에 직접 투입하기에는 구조화 수준이 낮다.** "당신은 재무 분석가다" 류의 프롬프트는 모델의 어조를 바꿀 뿐, 데이터 검증이나 계산 정확도를 보장하지 않는다.

## 3. ternary-ai/prompts — 금융·퀀트 특화 라이브러리

- 저장소: [github.com/ternary-ai/prompts](https://github.com/ternary-ai/prompts)

자율적 금융 에이전트 워크플로우를 전제로 설계된 특화 라이브러리로, 카테고리 구조 자체가 실무 금융 분석 프로세스를 반영한다.

| 카테고리 | 설명 | 퀀트 실무 관점 활용도 |
|---|---|---|
| Agent | 자율적 금융 워크플로우를 위한 작업 위임 프롬프트 | 멀티 에이전트 파이프라인 오케스트레이션 골격 |
| Analysis | 10-K 보고서, 실적 발표, 공시 문서 분석 | 펀더멘털 데이터 추출 자동화 |
| Portfolio | 포지션 관리, 집중도 분석, 리밸런싱 가이드 | 일일 포트폴리오 점검 루틴 템플릿 |
| Research | 주식·거시경제 심층 리서치 | 딥리서치형 종목 스크리닝 |
| Risk Management | 시나리오 분석, 하방 리스크 매핑, 자본 보존 프로토콜 | 스트레스 테스트 시나리오 생성 |
| Knowledge Graph | 엔티티 추출 및 관계 기반 구조적 추론 | 지배구조·공급망 관계 매핑 |
| Summarisation | 장문 금융 문서의 실행 가능 인사이트 요약 | 공시·리포트 대량 처리 |
| Trading | 자율 트레이딩 추론 실험용 (실거래용 아님) | 시그널 로직 프로토타이핑 한정 |

### 대표 프롬프트 패턴

- 투자자 페르소나: *"Pretend you are an investing agent modeled with all the knowledge of {investor}."* — 특정 투자자의 철학을 모방한 추론 실험
- 개념 설명: *"Explain {concept} to a novice investor..."* — 금융 개념의 교육·검증용

### 평가

카테고리 설계가 실제 바이사이드 리서치 프로세스(리서치 → 분석 → 포트폴리오 → 리스크)를 따라가므로, **에이전트 기반 자동화 파이프라인의 골격 설계에 참고 가치가 높다.** 다만 저장소 스스로 Trading 카테고리를 "실거래용 아님"으로 명시하는 점에 주목해야 한다. 라이브러리 제작자조차 LLM 트레이딩 추론을 실험 단계로 규정한다.

## 4. 크립토 투자 관점에서의 적용과 한계

위 라이브러리들은 대부분 **전통 금융(TradFi) 중심**으로 설계되었다. 크립토 투자에 적용할 때는 다음 변환이 필요하다.

| TradFi 프롬프트 요소 | 크립토 대응 요소 | 변환 시 유의점 |
|---|---|---|
| 10-K / 실적 공시 분석 | 백서, 토크노믹스 문서, 거버넌스 포럼 | 감사·규제 검증이 없는 자체 발행 문서로, 공시 대비 신뢰도가 구조적으로 낮음 |
| 재무비율 (PER, ROE 등) | TVL, FDV/MC 비율, 토큰 언락 스케줄, 온체인 활성 지표 | 지표 표준화가 안 되어 있어 데이터 소스별 정의 차이가 큼 |
| 리밸런싱 가이드 | 크로스체인 포지션, DEX/CEX 유동성 분산 | 슬리피지·가스비·브리지 리스크가 프롬프트에 반영되지 않음 |
| 시나리오 리스크 분석 | 스마트컨트랙트 익스플로잇, 디페깅, 규제 이벤트 | TradFi 시나리오 템플릿에는 이런 이벤트 유형 자체가 없음 |

**핵심 한계:** 기존 라이브러리에 크립토 특화 프롬프트(토큰 언락 충격 분석, 김치 프리미엄, 브리지 리스크, MEV 등)는 사실상 부재하다. 크립토 퀀트 파이프라인에 쓰려면 위 라이브러리를 구조 참고용으로만 삼고, 도메인 프롬프트는 자체 구축하는 것이 현실적이다.

## 5. 리스크 명세

프롬프트 라이브러리를 투자 분석에 활용할 때의 리스크를 계층별로 정리한다.

### 5.1 LLM 고유 리스크

| 리스크 | 내용 | 완화 방안 |
|---|---|---|
| 환각(Hallucination) | 존재하지 않는 재무 수치, 날짜, 공시 내용을 그럴듯하게 생성 | 모든 수치를 원천 데이터(공시, API)와 대조 검증. LLM 출력은 계산·정리 도구로만 취급 |
| 지식 시점 단절 | 학습 컷오프 이후의 가격·규제·상장폐지 정보 부재 | 실시간 데이터는 반드시 외부 API/검색 도구로 주입 |
| 계산 신뢰성 | 복잡한 수치 연산에서 산술 오류 발생 가능 | 계산은 코드 실행(Python 등)으로 위임하고 LLM은 해석만 담당 |
| 프롬프트 인젝션 | 공개 라이브러리 프롬프트나 분석 대상 문서에 악성 지시가 포함될 수 있음 | 외부 프롬프트는 실행 전 전문 검토, 에이전트 권한 최소화 |
| 아첨 편향(Sycophancy) | 사용자의 기존 포지션을 정당화하는 방향으로 응답이 편향 | 반대 논거를 강제 생성시키는 프롬프트 구조 병행 (멀티 LLM 교차 검증 등) |

### 5.2 투자 실무 리스크

| 리스크 | 내용 |
|---|---|
| 페르소나 프롬프트의 착시 | "워런 버핏처럼 분석하라"는 프롬프트는 해당 투자자의 실제 판단이 아니라 공개 텍스트 기반 문체 모사에 불과. 권위 착시로 인한 과신 위험 |
| 백테스트 부재 | 라이브러리 프롬프트는 어떤 것도 수익률 검증을 거치지 않음. Trading 카테고리조차 제작자가 실거래 부적합을 명시 |
| 과최적화 유도 | LLM에게 전략 개선을 반복 요청하면 과거 데이터에 오버피팅된 규칙을 생성하는 경향 |
| 군집 리스크 | 143K 스타 규모의 공개 프롬프트를 다수가 동일하게 사용할 경우, 유사한 분석 결론·매매 판단으로 수렴하는 crowding 가능성 |
| 규제·컴플라이언스 | LLM 출력 기반 투자 조언을 제3자에게 제공하면 국가에 따라 투자자문업 규제 대상이 될 수 있음. 한국의 경우 자본시장법상 유사투자자문 이슈 검토 필요 |

### 5.3 크립토 특유 리스크

| 리스크 | 내용 |
|---|---|
| 데이터 신뢰도 | 온체인 데이터는 위장 거래(wash trading), 시빌 지갑으로 오염 가능. TradFi 공시 수준의 검증 체계 부재 |
| 24/7 시장 vs 배치 분석 | 크립토는 무휴장. 일 1회 리뷰형 프롬프트 워크플로우는 급변 구간에서 구조적 지연 발생 |
| 유동성 구조 | 소형 토큰은 프롬프트가 산출한 "적정 리밸런싱"이 실제 체결 가능 물량을 초과할 수 있음 |
| 이벤트 유형 부재 | 익스플로잇, 디페깅, 언락 충격 등 크립토 고유 이벤트가 TradFi 기반 리스크 템플릿에 반영되지 않음 |

### 5.4 종합 판단

이들 라이브러리의 실질 가치는 "투자 판단 생성기"가 아니라 **분석 워크플로우의 구조 설계 참고자료**에 있다. LLM은 데이터를 정리·요약·구조화하는 도구이지 시장을 예측하는 신탁이 아니며, 프롬프트 라이브러리는 그 도구의 사용 설명서 모음에 가깝다. 최종 투자 판단의 책임과 검증 부담은 전적으로 사용자에게 남는다.

## 6. 활용 권고

1. **prompts.chat**: 프롬프트를 검색·복사 후 자기 업무 키워드로 수정해 사용. 탐색·교육 용도에 적합
2. **ternary-ai/prompts**: 에이전트 기반 금융 분석 파이프라인의 카테고리 구조 설계 시 골격으로 참고
3. **크립토 적용 시**: 라이브러리는 구조 참고용으로 한정하고, 토크노믹스·온체인 지표·언락 스케줄 등 도메인 프롬프트는 자체 구축
4. **공통**: 모든 수치 출력은 원천 데이터 검증 필수. 계산은 코드 실행으로 위임. 프롬프트 출력만으로 매매 판단 금지
5. **라이선스**: prompts.chat은 CC0, 나머지는 각 저장소 오픈소스 라이선스 확인 후 상업적 활용 가능
